## 요청 A — ColorModel vibrance 슬라이더 범위 (필수)

`ColorModel.applyVibrance` 가 `CIVibrance` 를 `params.vibrance * 0.8` 로 부릅니다. 슬라이더가
−1…1 이면 amount 가 **−0.8 … +0.8** 입니다. 4차까지 잰 구간은 0.05…0.50 뿐이라 **음수와
0.5 초과를 재지 않았습니다.**

그래서 muted-scene 단계에만 표를 넣고 **ColorModel 슬라이더는 예전 수식 그대로 두었습니다.**
재지 않은 곳에 표를 뻗으면 잰 사상이 아니라 지어낸 값이 되기 때문입니다.

4차와 **같은 33³ 규약**으로, amount 만 아래로:

| amount | 파일 이름 |
| --- | --- |
| −0.80 | `civibrance33-am0.800-256x141.f32` |
| −0.60 | `civibrance33-am0.600-256x141.f32` |
| −0.40 | `civibrance33-am0.400-256x141.f32` |
| −0.20 | `civibrance33-am0.200-256x141.f32` |
| −0.05 | `civibrance33-am0.050-256x141.f32` |
| +0.60 | `civibrance33-a0.600-256x141.f32` |
| +0.80 | `civibrance33-a0.800-256x141.f32` |

(0.05…0.50 은 4차에 이미 있습니다. 위는 그 바깥만입니다.)

음수 쪽에서 이 필터가 어떻게 도는지가 특히 궁금합니다 — 4차 자료에서 `f ≥ 1` 이 항상
유지된다고 하셨는데, 그건 양수 구간 이야기입니다. 음수에서 `f < 1` 이 되는지, 아니면
다른 방식으로 도는지가 구현을 가릅니다.

일곱 판 합쳐 약 4 MB 입니다.

## 요청 B — 채도 낮은 스캔 한 장 더 (권장)

vibrance 표를 **실사진**으로 검증한 것이 `GT-X900_frame_4` 하나뿐입니다. 사다리로 amount 는
여섯 가지를 봤지만, 사진은 여전히 한 장입니다.

가지신 스캔에서 vibrance 가 도는 것이 그 한 장뿐이라고 하셨으니, 새 스캔이 있으면
알려 주십시오. 없으면 이 항목은 **필름을 새로 스캔해야 닫힙니다** — 사용자 쪽 일입니다.

## 요청 C — CIUnsharpMask 사상 (필수)

출력 선명도가 `CIUnsharpMask` 를 씁니다. `CIVibrance` 와 같은 이유로 커널 소스가 없습니다.

이건 이웃 화소를 보는 필터라 격자로는 안 됩니다. **알려진 시험 무늬**를 통과시켜 주십시오:

- 256 × 256, `RGBAf`, linear sRGB
- 무늬: (1) 계단 엣지 수직·수평, (2) 점 임펄스 격자, (3) 정현파 주파수 스윕,
  (4) 균일 회색 0.18 / 0.5 / 0.9
- 파이프라인이 쓰는 `radius` · `intensity` 조합으로 각각

Windows 는 이 무늬로 커널 반경·가중을 맞추고, 실사진으로 검증하겠습니다.
어떤 `radius`/`intensity` 를 쓰는지는 `OutputSharpening` 쪽 값을 그대로 알려 주시면 됩니다.

## 요청 E — 흑백·슬라이드 골든 (권장)

지금 골든은 **컬러 네거티브 두 장뿐**입니다. `bwResponse`(baseToe 0.0005 / white 0.85 /
ceiling 0.98)와 E-6 경로는 실측 대조가 하나도 없습니다.

1차와 같은 형식(같은 여덟 조건, `pixel-stats.json` + `manifest.json`)으로:

- 흑백 네거티브 스캔 한 장 (D-76 또는 B&W Reversal)
- 슬라이드 스캔 한 장 (E-6)

`[nega]` · `[vib]` 로그도 함께 주시면 어긋났을 때 자리를 바로 찾습니다.

## 요청 F — DigitalFilmLook 픽셀 골든 (권장)

디지털 소스 전용 룩입니다. 필름 42종 중 어느 것이든 두세 개, 강도 0.5 / 1.0 으로 같은 형식.

## 우리 쪽에서 맥 없이 하는 것

혼선을 막기 위해 적습니다. 아래는 **요청하지 않습니다** — 저희가 가진 골든으로 됩니다.

- `c-target-hs` / `c-target-sp` 의 명부 불일치 (G max 가 7692 어긋납니다). F135·HR 은 같은
  경로에서 맞으므로 HS·SP 타깃 데이터 문제로 좁혀져 있습니다.
- `b-main-scannerprofile-portra400` 의 median 밀림.
- alpha(`preserveAlpha`) 전 계층 구현.
- 메타데이터 정책의 태그 단위 대조 — task6 골든이 이미 있습니다.

## 정리해도 되는 것

`vibrance/` 가 37 MB 입니다. 표가 확정됐으므로 **다음은 지워도 됩니다**:

- `civibrance-*-128x39.f32` 여섯 개 (17³ — 33³ 이 대체)
- `civibrance65-*` 두 개 (검증 끝, 결과는 문서에 남음)

`civibrance33-*` 열한 개와 실사진 사다리는 남겨 주십시오 — 표를 다시 만들 때 씁니다.

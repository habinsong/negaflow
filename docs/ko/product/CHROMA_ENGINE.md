# Chroma Engine

[문서 홈](../README.md)

Chroma Engine은 필름을 반전하고 현상합니다. 코드는 `Chromabase` 모듈에 들어 있습니다. 앱과 CLI가 공통 모듈을 공유하므로 입력이 일치하면 똑같은 단계 순서를 거칩니다.

| 한눈에 | 내용 |
|---|---|
| 기본 현상 | `MAIN`, 자동 밸런스 ON |
| 필름 베이스 | 자동 측정, 스포이드, RGB 직접 입력 |
| 내부 색 | 부동소수점 선형 색 공간(macOS 16비트 half-float, Windows 32비트 float) |
| 자동 기능 | 자동 밸런스 ON |
| 출력 색 공간 | sRGB, Display P3, Adobe RGB, 내보내기용 RGB 프린터 ICC(`prtr`), 소프트 프루프용 `prtr`/`mntr`/`spac` |

> [!IMPORTANT]
> 기본 설정은 `MAIN`과 자동 밸런스 ON이며, 컬러와 흑백 네거티브의 MAIN(PRINT 포함), CS에서는 타깃 제목 오른쪽에 작은 알약 모양 스위치가 보입니다. 이 스위치는 현재 사진을 기준으로 색과 밝기를 맞추며 꺼짐 상태에서는 그 단계를 건너뜁니다. 반면 자동 톤, 자동 화이트 밸런스, 자동 레벨, 자동 색상은 별도 기능이라 기본 상태가 꺼짐입니다.

## 먼저 지키는 것

1. 필름 베이스를 실측할 수 있으면 이름으로 고른 기본값보다 실측 결과가 앞섭니다.
2. 필름의 성질, 스캔 광원, 스캐너 스타일, 장면 자동 보정은 서로 분리해 처리합니다.
3. 자동 톤이나 자동 화이트 밸런스처럼 별도로 마련된 기능은 직접 실행할 때만 켜집니다.
4. 똑같은 원본과 편집 설정, 프로파일 조합은 언제나 정해진 단계 순서를 거칩니다.
5. 합성 시험과 실기 검증은 단계를 엄격히 나누어 기록합니다.

## 단계 순서

작업 이미지는 부동소수점 선형 색 공간에서 계산하며 macOS는 Core Image의 16비트 half-float, Windows 엔진은 32비트 float를 사용하여 양쪽 경로 모두 0 미만과 1 초과의 수치를 그대로 지킵니다.

컬러 믹서, 컬러 그레이딩, 캘리브레이션, 포인트 커브는 `[0, 1]` 범위의 지각적 sRGB 인코딩에서 동작하되 범위 밖(`< 0` 또는 `> 1`) 수치를 자르는 대신 보존하며, 마지막 화면 표시나 파일 인코딩 직전에 `DisplayGamutMap`이 색역 밖의 색을 색상 왜곡 없이 출력 색 공간의 선형 원색 안으로 넣습니다.

1. 파일을 읽고 방향을 정렬합니다.
2. 선형 입력(RAW는 카메라 RGB)으로 바꿉니다.
3. 필름 종류에 따라 포지티브는 전용 경로로 넘기고 네거티브는 베이스를 측정합니다.
4. 광학 농도와 반전을 계산한 뒤 자동 밸런스 ON/OFF와 RAW 카메라 행렬을 거칩니다.
5. `EXPIRED` 복구 보정(선택 시) 뒤에 화이트 밸런스와 노출, 기본 톤, 파라메트릭 커브를 반영합니다.
6. 스캐너 타깃(`HS`, `SP`, `F135`, `HR`)과 번들 스캐너 프로파일을 거칩니다.
7. 포인트 커브, 컬러 믹서, 컬러 그레이딩, 캘리브레이션을 실행합니다.
8. `CS` 커스텀 타깃과 디지털 원본 전용 디지털 필름 룩을 입힙니다.
9. 소프트웨어 결함 제거와 노이즈 감소를 수행합니다.
10. 부분 닷지와 번, 디테일과 질감, 기하 변환을 거칩니다.
11. `DisplayGamutMap`을 통과시켜 표시와 출력 색 공간으로 인코딩합니다.

`CIContext`는 매번 새로 생성하는 대신 표시, 분석, 내보내기 목적별로 풀에서 재사용합니다. 미리보기는 필요한 크기와 최신 편집 버전만 계산하고 내보내기는 원본 해상도에서 새로 만듭니다.

Apple의 Core Image 문서:

- [CIImage](https://developer.apple.com/documentation/coreimage/ciimage)
- [CIContext](https://developer.apple.com/documentation/coreimage/cicontext)
- [workingColorSpace](https://developer.apple.com/documentation/coreimage/cicontext/workingcolorspace)
- [Core Image performance guide](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/CoreImaging/ci_performance/ci_performance.html)

## 필름 베이스

### 측정하는 이유

네거티브에서 노출되지 않은 영역은 필름 유제와 현상 공정, 스캔 광원이 합쳐진 출발점이며 컬러 네거티브의 오렌지 마스크도 여기에 포함됩니다. 따라서 베이스를 잘못 잡으면 그 뒤의 모든 광학 농도와 채널 비율이 틀어지는데, Kodak의 Portra 400 데이터시트 역시 최소 농도와 특성곡선, 염료 분광 농도를 구분해 싣고 있습니다.

- [Kodak Professional Portra 400 technical data](https://www.kodakprofessional.com/sites/default/files/wysiwyg/pro/resources/e4050_portra_400.pdf)

### 자동 측정

`FilmBaseEstimator`는 프레임 전체에서 밝은 픽셀의 공간 분포를 평가해 노출되지 않은 베이스를 찾아냅니다.

- 필름 픽셀은 노출되지 않은 베이스보다 밝아지지 못합니다.
- 훨씬 밝은 화소는 백라이트나 퍼포레이션, 필름 바깥 영역일 가능성이 높습니다.
- 진짜 베이스는 프레임 가장자리를 따라 넓은 띠 모양을 이룹니다.
- 한 시트에 필름 스트립이 여럿이면 떨어진 영역을 함께 읽어 들입니다.
- 홀더와 필름이 섞이는 경계는 안쪽보다 가중치를 낮춥니다.

축소한 분석 이미지에서 밝기 분포를 구하고 인접한 영역을 모은 뒤 필름 밖에 있는 후보를 걸러냅니다. 조건을 통과한 스트립이 여럿이면 함께 합산해 구합니다. 결과에는 선택한 방법과 신뢰도도 들어갑니다.

### 방법 고르기

| 모드 | 동작 |
|---|---|
| `Manual` | 입력한 RGB를 Dmin으로 삼으며 스포이드로 추출한 색상도 이 모드로 들어옵니다. |
| `Film` | 실측이 가능하면 측정된 `Dmin`을 우선 적용하고 실패할 때만 필름의 `Dmin` 기본값을 따릅니다. 필름의 상대 농도 범위 계수(`relativeRangeFactor`)를 공급하며 컬러 네거티브에서는 색 치우침이 있는 광원 게인을 확정된 `Dmin`에 함께 반영합니다. |
| `Auto` | 공간 분석을 먼저 수행하고 실패하면 가장자리 기반 방법으로 전환됩니다. |

수동 입력이 없거나 필름 ID가 어긋나면 다음 안전 경로로 넘어가므로 장면 속 밝은 피사체를 필름 베이스로 오인하는 오류를 막습니다.

## 광학 농도와 반전

광학 농도는 선형 투과율 `T`와 채널별 베이스 `Dmin`에서 계산합니다.

```math
D = \log_{10}\left(\frac{D_{\min}}{T}\right)
```

`D = 0`은 입력이 노출되지 않은 베이스와 일치하는 상태를 나타내며, 퍼포레이션이나 백라이트 영역에서는 농도가 음수로 내려갈 수 있는데 이 수치도 중간에 자르는 대신 유한한 부동소수점으로 끝까지 지킵니다.

### 필름 종류 자료

현재 표에는 필름 이름 27개(C-41 컬러 네거티브 23종과 ECN-2 영화용 네거티브 4종)가 들어 있으며 아래 용도에 활용합니다.

- 베이스를 측정하지 못할 때의 Dmin 기본값
- 필름 종류에 상대적인 고정 농도 계수

일부 수치는 공개된 자료의 곡선을 읽어 근사하고 나머지는 보수적인 수치로 정했으며, 베이스 측정에 성공하면 언제나 실측치가 이 기본 표보다 앞섭니다.

### MAIN/PRINT와 CS

자동 밸런스 ON에서는 채널마다 장면에서 가장 짙은 0.2% 백분위를 구해 농도 범위를 1.8D로 제한한 뒤 `shoulder-print-response-v4` 곡선과 약한 장면용 비브런스를 반영합니다. 반면 OFF는 똑같은 곡선에 고정 명목 범위(컬러 1.55D, 흑백 2.17D)를 적용하며, 컬러 네거티브에서는 한 롤의 프레임 세 장 이상에서 구한 스캐너와 필름 채널 범위 보정치도 함께 곱해 줍니다.

ON 모드는 장면 구성에 따라 밝기와 색 밸런스가 함께 달라지며 구체적인 수식, 1.8D 상한, RAW 처리 순서는 아래 문서에 정리했습니다.

[네거티브 반전 응답](../reference/PRINT_RESPONSE.md)

## 프로파일 세 종류

| 종류 | 답하는 질문 | 포함 파라미터 |
|---|---|---|
| 필름 종류 | 필름의 베이스와 농도 범위는 얼마인가 | Dmin/Dmax, 필름 종류 |
| 광원 | 스캔 광원이 채널마다 어떤 영향을 줬는가 | 채널 게인, 베이스에 따른 보정 |
| 스캐너 타깃 | 결과의 톤과 색 스타일은 어떠한가 | 이 프로젝트용으로 촬영한 스캔의 상대 통계 |

이 세 요소를 분리하면 한 필름 이름에 유제 특성과 광원 색상, 랩의 출력 스타일이 한꺼번에 뒤섞이는 문제를 피하게 됩니다. 실제 베이스를 구하면 그 결과가 필름의 `Dmin` 기본값보다 우선하며, 컬러 네거티브에서는 색 치우침이 있는 광원 게인을 확정된 `Dmin` 뒤에 반영하고 스캐너 통계는 상대 톤 보정에만 활용합니다.

자료는 [필름 프로파일](FILM_PROFILES.md)에 설명했습니다.

## 현상 타깃

### `MAIN`

자동 밸런스가 켜진 기본 타깃입니다. 스위치는 이 문서의 맨 위에 설명했습니다.

### `PRINT`

작업 이미지는 `MAIN`과 일치하며 유효한 RGB 프린터 ICC는 내보내기의 마지막 단계에 한 번만 반영합니다. 이때 프로파일이 없거나 규격에 맞지 않으면 sRGB나 임의의 용지 설정으로 대체하는 대신 즉시 오류를 내고 멈춥니다.

### `HS`, `SP`

고정 렌더링 경로로 화이트 밸런스, 노출, 기본 톤, 파라메트릭 커브 바로 뒤에 오고 포인트 커브, 컬러 믹서, 컬러 그레이딩, 캘리브레이션 앞에 자리합니다. 실제 현상소에서도 오퍼레이터의 농도와 색 보정을 스캔에 먼저 걸고 인화 곡선은 고정해 운영하는데, 이와 마찬가지로 이 경로는 장면 통계를 새로 읽지 않으므로 입력 화소가 같으면 어느 사진에서나 일치하는 출력을 냅니다.

프레임별 노출과 색 조정은 반전과 오른쪽 패널의 자동 보정 버튼들이 담당하며 화이트 밸런스 스포이드는 이 고정 렌더링 이전의 색상을 샘플링하므로 `HS` 특유의 회색축 기울기는 스포이드를 찍은 뒤에도 그대로 남습니다.

렌더링은 휘도 톤 커브, 밝기별 채도 게인, `HS` 전용 회색축 기울기로 구성되며 모든 곡선은 매듭에서 매끄럽게 연결되는 단조 3차 스플라인으로 계산합니다.

- `SP`는 한 롤의 프레임 네 장을 실제 SP-3000과 본 프로젝트의 스캐너로 각각 스캔해 화소 단위로 정렬한 비교 자료에서 도출했으며 톤 곡선은 SP-3000 프레임 185장의 백분위 분포를 4분의 1 비중으로 섞어 완성했습니다. 이 네 프레임에서 SP-3000 스캔 대비 CIEDE2000 중앙값은 `MAIN`의 약 7.4에서 3.9로 낮아지는데, 현상소에서 프레임별로 붉은 암부 캐스트를 수동 제거한 어두운 프레임 한 장만은 고정 렌더링만으로 따라잡기 어려워 원래 차이가 대부분 남습니다.
- `HS`에는 화소 쌍이 없습니다. `SP`에서 출발해 필름과 롤 이름이 맞는 세 롤에서 두 기계의 중앙값 차이를 반영합니다. 중간톤은 약간 어둡게, 흰색은 조금 높게, 채색 픽셀은 채도 0.88배, 밝은 쪽 회색은 초록 쪽으로 기웁니다(a* 약 −1~−4).
- `HS`는 밝기 채널에 선명화 패스를 적용하는데 반지름은 스캐너의 35mm 출력(긴 변 3089px)에서 0.9px이고 이미지 해상도에 비례해 스케일링되므로 미리보기와 내보내기의 선명도가 그대로 맞습니다.

번들 프로파일을 고르면 두 기계에서 이름과 이미지 수가 맞는 롤의 상대 차이인 `scannerSignature`가 결합됩니다. 지금은 모든 프로파일이 `realOnly`입니다.

- 상대 차이는 롤 이름과 이미지 수가 충분히 가까울 때만 계산합니다.
- 보정 방향이 반전되는 구간은 걸러냅니다.
- 흑백에서는 색 성분을 버립니다.
- 어느 파일이나 매니페스트의 SHA-256이 어긋나면 번들 전체를 거부합니다.

### `F135`, `HR`

본 프로젝트에는 Pakon F-135나 Kodak HR-500에서 직접 뽑은 참조 스캔이 없으므로 두 타깃은 `SP`의 수치에서 파생하는 대신 현상소와 사용자들의 기술 자료를 바탕으로 독립된 응답 표를 구성했습니다.

두 타깃 모두 회색축에는 별도 색조 없이 무채색을 유지하는데, Pakon 사용기에서 보고되는 노란빛, 초록빛, 파란빛 틴트는 기계 고유의 고정 축 대신 프레임마다 다르게 작동한 장면 밸런스에서 비롯된 결과이기 때문입니다.

- `F135`(Kodak Pakon F-135, 소비자용 TLX/PSI 스캐너): Noritsu보다 채도가 차분하고 화이트 밸런스가 안정적이며 명부와 암부의 계조가 살아 있으면서 일부 스캔은 평탄하고 흑백은 밝게 뽑힌다는 보고를 반영했습니다. 18% 회색은 소비자 인화처럼 0.3스톱 밝게 잡고 중간톤의 부분 대비는 0.8~1.0으로 `SP`의 1.2~1.35보다 낮게 설정합니다. 또한 토를 들어 올려 −6스톱이 0.101(`SP` 0.073)이 되게 하고 명부를 완만하게 접어서, 반전 단계가 장면 흰색으로 매핑한 선형 0.70이 sRGB 231에 도달하며 채도 게인은 모든 밝기 구간에서 `HS`보다 낮은 0.68~0.74 범위를 지킵니다.
- `HR`(Kodak Professional HR 500): 후반 보정을 전제로 한 평탄한 raw 성격의 스캔이라는 현상소의 설명과 정교한 색 분리, 깨끗한 암부 계조를 근거로 설계했습니다. 18% 회색은 0.1스톱 짙게 잡고 중간톤의 부분 대비는 1.15~1.2로 유지합니다. 암부는 기울기 1.2~1.3으로 `MAIN`의 선형 암부보다 짙고 깨끗하게 떨어지며(−6스톱 0.018) 스톱당 계조 간격이 `SP`보다 1.6배 넓습니다. 명부는 `SP`처럼 일찍 누르는 대신 기울기 1.2~1.35로 곧게 뻗어 장면 흰색이 sRGB 242에 이르며, 채도 게인은 중간까지 1.0으로 고정되다가 명부에서 0.88로 차분하게 내려갑니다.

네 타깃의 응답은 타깃 직전 단계까지 현상한 실제 네거티브 7장(진단 전용 두 롤)에 각각 씌워 비교했습니다. 사진마다 평균을 내면 `MAIN`과 네 타깃의 모든 쌍이 CIEDE2000 2.9 이상 벌어지며 측정으로 만든 `SP`–`HS`는 4.3입니다.

사진 한 장 안에서는 하이키와 중간톤 위주 장면에서 `MAIN`–`HR`, `F135`–`HR`이 2.0~2.6까지 내려옵니다. 어느 쪽이든 기계와 대조하려면 `SP`에 있던 것처럼 실제 기계에서 스캔한 똑같은 네거티브가 필요합니다.

### `EXPIRED`

유효기간이 지난 필름을 위한 복구 타깃으로, 일괄 탈채도나 무리한 범위 확장 대신 현재의 측정 근거가 뒷받침하는 보수적인 범위 안에서만 색을 보정해 줍니다.

### `CS`

`CS`(Custom)는 색 스타일 18종을 세 갈래로 나누어 제공합니다.

소재와 공정 갈래 11종은 Emulsion과 Reversal, Dye Transfer와 Skip Bleach, Plate Glass와 Amber Glass, Ultramarine과 Terracotta, Celadon과 Nacre와 Dichroic이고 광학과 스튜디오 갈래 4종은 Wetzlar와 Classic, Studio와 Rochester이며 상영과 스냅 갈래 3종은 Slide Show와 Cinema, Point & Shoot입니다.

Custom 타깃은 자동 밸런스가 켜진 `MAIN` 반전 뒤에 스캐너 프로파일 없이 custom-3 톤과 농도, 채도 응답을 바로 씌우며 CLI에서도 `--target classic`처럼 똑같은 타깃 ID를 그대로 받습니다.

## 디지털 원본의 필름 룩

필름 탭에는 다섯 갈래에 걸쳐 42종이 들어갑니다. 슬라이드 7종과 컬러 네거티브 16종, ECN-2 영화용 4종과 흑백 네거티브 13종, 흑백 리버설 2종으로 구성됩니다.

이 단계는 `Digital Color`와 `Digital B&W` 원본에만 작동하며 이미 실제 유제 응답을 품고 있는 필름 스캔에서는 실행하지 않습니다.

`Digital Color`는 네 단계를 순서대로 거칩니다.

1. 선형 산란과 붉은 쪽으로 기운 할레이션(`DigitalHalation`)
2. 채널 커브, 분광 행렬, 암부와 명부 틴트, 채도, 데이터시트 MTF 아큐턴스를 한 테이블로 합친 포지티브 영역 33³ 3D LUT(`FilmEmulationStage`)
3. 절반 강도로 거는 보조 필름 색 프리셋(`DigitalFilmColorPresetStage`)
4. 농도에 따라 달라지는 필름 그레인(`DigitalFilmGrain`)

`Digital B&W`는 무채색 할레이션, 분광 RGB-흑백 변환, 유제 톤 커브(`digitalBWFilm`), MTF 아큐턴스, 무채색 농도 연동 그레인 순으로 진행됩니다.

## 현상 컨트롤

| 그룹 | 항목 |
|---|---|
| 톤 | 노출과 대비, 농도와 하이라이트/섀도, 화이트와 블랙, 파라메트릭 커브와 채널별 포인트 커브 |
| 색 | 색온도와 색조, 비브런스와 채도/색 깊이, 8색 HSL과 3영역 컬러 그레이딩, 채널 보정과 흑백 토닝 |
| 디테일과 효과 | 선명도와 클래리티, 필름 그레인과 비네트, 할레이션과 노이즈 감소 |
| 부분 보정 | 방사형/선형/다각형/브러시 마스크를 이용한 닷지와 번 |
| 변환 / 기하 보정 | 원근 보정과 수평 보정 |

기본 톤 컨트롤과 파라메트릭 커브는 어떤 조합에서도 계조 역전이 없는 단조 응답을 지킵니다. 기본 톤은 대비와 농도, 하이라이트와 섀도, 화이트와 블랙을 이 순서대로 앞 단계 결과에 차례로 거는데 연산마다 단조 증가 함수를 따릅니다.

뒤따르는 파라메트릭 커브의 네 구간은 사진 휘도의 10%와 35%, 65%와 90% 지점에 배치한 제어 마디를 각각 움직여 단조 3차 곡선으로 연결하며 마디마다 인접 지점과 양 끝점에서 sRGB 0.10 이상 간격을 지키므로 컨트롤을 끝까지 밀면 어느 사진에서나 최소 sRGB 0.045 이상의 변화 폭을 얻을 수 있습니다.

컬러 믹서와 컬러 그레이딩, 캘리브레이션과 포인트 커브는 `[0, 1]` 범위의 지각적 sRGB 인코딩에서 동작하면서 0 미만이나 1 초과의 수치를 그대로 보존하며, 출력 인코딩 직전에 `DisplayGamutMap`이 색역 밖의 색을 색상 이동 없이 출력 색 공간의 선형 원색 안으로 변환해 넣습니다.

조정 내역은 단계별 편집 기록으로 저장되며 GrainMend 결함 복원과 일반 부분 보정은 목적과 저장 구조가 서로 분리되어 있습니다.

### 자동 보정

| 컨트롤 | 동작 |
|---|---|
| 자동 톤 | 노출과 대비, 농도와 하이라이트/섀도, 화이트와 블랙을 설정합니다. 노출은 장면의 로그 평균 휘도를 장면 키에 일치시켜 밝은 사진은 낮추고 어두운 사진은 올리며, 장면이 밝을수록 목표 키도 높아집니다. 나머지 항목은 기본 톤 연산 순서에 따라 앞 단계를 거친 결과에서 차례로 계산합니다. 이때 확산 화이트보다 어두운 영역에서 가장 밝은 채널이 상한에 새로 도달하는 화소는 0.5% 이내로 억제하되 확산 화이트보다 밝은 반사광이나 광원은 클리핑을 열어 놓습니다. 채도 높은 색이 포화될 위험이 있으면 화이트를 먼저 낮추고 뒤따라 노출과 농도, 대비의 밝기 증가량을 줄이며 노출 상승을 억제한 만큼 어두워진 중간톤은 농도 항목으로 메웁니다. 따라서 계산된 장면 키에서 노출을 양보하는 폭은 최대 1스톱으로 제한되며 사용자의 색 컨트롤과 커브는 그대로 보존됩니다. |
| 자동 화이트 밸런스 | 무채색에 가까운 휘도 대역에서 색온도와 색조를 추정하되 RGB 채널이 잘린 표본은 제외하며 무채색 근거가 부족하거나 톤 범위가 좁으면 보정 강도를 낮춥니다. |
| 자동 레벨 | 공통 휘도 끝점을 구하고 RGB에 똑같은 휘도 게인을 곱해 채널 비율을 지킵니다. 네거티브에서는 양 끝점을 반전 단계의 검정과 확산 화이트 참조치(컬러 선형 0.70, 흑백 0.85)에 정렬하며, 노출 숄더의 니(knee)는 두 필름 모두 선형 0.70에 고정한 채 헤드룸만 각 필름의 화이트 참조치 비율로 조절해 줍니다. |
| 자동 색상 | 남아 있는 색 캐스트를 무채색 후보를 바탕으로 걷어냅니다. 피팅 결과가 기존에 반영하지 않은 별도 휘도 대역을 설명할 때만 채널 기울기를 적용하고 그 밖에는 균일한 게인을 곱하며, 대체 근거가 약할수록 보정 폭을 줄입니다. 채널 기울기는 가장 어두운 유효 대역부터 흰색까지만 반영하고 그보다 어두운 암부에는 유효 대역 하단의 보정량을 일정하게 유지합니다. |

자동 톤은 1차 제안치를 미리보기에 반영해 결과를 먼저 살핍니다. 노출이나 화이트 포인트를 추가로 조정하자는 제안이 생성되면 그 설정도 함께 계산해 중간톤과 끝점, 톤 범위와 클리핑 지표가 개선될 때만 채택합니다.

이때 밝기를 더 올리는 경우에도 똑같은 채널 상한을 적용하여 보정 전 이미지와 화소 단위로 대조했을 때 새로 포화되는 화소가 스캐너 타깃과 커브를 포함해 0.5%를 넘으면 화이트와 노출을 차례로 낮춥니다. 상한 안에서 가장 밝은 설정을 찾기 위해 미리보기 확인을 최대 세 번까지 반복하며 두 결과를 비교할 때는 포화 화소가 적은 쪽을 항상 우선합니다.

이 과정은 상한이 정해진 수치 보정이므로 명령을 여러 번 실행해도 값이 누적되지 않고 똑같이 재계산되며, 초기화하더라도 사용자의 색 컨트롤은 그대로 남습니다.

분석 단계는 긴 변의 크기를 제한한 선형 RGB 이미지에서 면적 가중 평균을 구하며 톤과 화이트 밸런스 분석은 sRGB 미리보기에서 계산하므로 여기서 말하는 클리핑은 센서 포화 대신 미리보기 채널의 포화를 말합니다.

통계 추정은 피사체 고유의 색과 조명 캐스트를 언제나 구분하거나 절대적인 필름 색 정확도를 보장하기보다 실용적인 초기 출발점을 제공하는 역할을 하며, MAIN과 CS의 자동 밸런스와 약한 장면용 비브런스는 반전 단계에 속합니다.

## 색 관리

입력에 유효한 ICC가 있으면 그 색 공간을 읽습니다. Windows에서는 내장된 광색역 ICC 입력을 내부 Rec.2020 중간 프로파일로 변환해 처리하고 Gray ICC 흑백 스캔도 지원합니다. 내부 계산은 고정된 선형 작업 공간에서 하고 출력 공간 전환은 표시와 소프트 프루프, 내보내기 단계에서 일어납니다.

주로 지원하는 출력:

- sRGB
- Display P3
- Adobe RGB
- 사용자가 고른 RGB ICC: 프린터 출력 내보내기는 ICC 프린터 클래스인 `prtr` RGB 프로파일만 허용하며 소프트 프루프는 출력 가능한 RGB 프로파일인 `prtr`, `mntr`, `spac`을 모두 받습니다

프린터 프로파일의 이름, 바이트 수, SHA-256은 내보내기를 시작할 때 고정합니다. 렌더링 중에 파일이 바뀌면 실행이 멈춥니다. Windows에서 기존 ICM이 LUT 프린터 ICC의 Relative Colorimetric을 거부하면 Perceptual이나 WCS v4 경로로 전환됩니다.

현재의 Core Image와 ColorSync 경로는 운영체제 버전마다 렌더링 인텐트나 블랙 포인트 보정에서 미세한 수치 차이가 생길 수 있는데, 비트 단위의 완전한 일치를 보장하려면 별도의 ColorSync 버퍼 경로와 대용량 16비트 이미지용 메모리 관리가 선행되어야 합니다.

## 출력 인코딩

형식 설정은 색 파이프라인 밖에 자리하지만 전달되는 파일의 기록 방식을 정해 줍니다.

JPEG는 인코더의 서브샘플링 임계값 미만에서 색을 휘도보다 낮은 해상도로 저장합니다. 그 구간에서는 채도 성분이 가로와 세로 모두 절반이 되어 휘도 디테일은 그대로인 채 채도가 높은 가장자리가 흐려집니다. 그래서 품질 95% 이상은 색 서브샘플링 없이 인코딩하고 더 낮은 설정은 더 작은 파일을 요청한 것이므로 고른 수치를 그대로 따릅니다.

PNG와 TIFF는 서브샘플링 없는 무손실 형식이므로 품질 설정이 채널당 8비트 또는 16비트 심도로만 결정되며 양자화 줄무늬를 완화하는 디더링은 8비트 출력에서만 적용됩니다.

## 성능과 안전

- `CIContext`는 목적별로 재사용합니다.
- 조정은 낮은 해상도의 미리보기를 활용하고 내보내기는 원본에서 다시 만듭니다.
- 오래 걸리는 작업은 결과를 반영하기 직전에 프레임 ID와 편집 버전, 세션을 다시 확인합니다.
- 메모리가 부족하면 썸네일이나 미리보기처럼 재생성 가능한 캐시를 버립니다.
- 원본과 편집 기록은 캐시와 분리해 보관합니다.

## 검증 단계

1. 공식 시험: 곡선의 단조성과 고정점, 역함수
2. 합성 이미지: 알려진 입력과 출력, 클리핑, 방향과 색 공간
3. 합성 IT8: 패치 264개에 대한 수학적 왕복
4. 실제 촬영 통계: `realOnly` 프로파일
5. REAL/TARGET 쌍: 별도 검증 자료를 분리해 보관한 장치 품질 검사
6. 실기: 실제 스캐너와 필름, 디스플레이와 인화

합성 IT8 결과는 수식과 파이프라인의 왕복 일관성을 보여 주며 실제 네거티브에 대한 스캐너 프로파일 품질 판정은 `PROFILE_QUALITY_GATE.md`([스캐너 프로파일 품질 검사](../reference/PROFILE_QUALITY_GATE.md))와 `IT8_COLOR_VALIDATION.md`([IT8 색 검사](../reference/IT8_COLOR_VALIDATION.md))의 기준을 따릅니다.

# 라이브러리에서 인화까지

[문서 홈](../README.md)

여기서는 파일 가져오기와 폴더 단위 현상부터 설정 복사와 스캐너 썸네일, 출력 흐름까지 설명하며 라이브러리의 폴더 구조는 각 원본 파일의 실제 상위 디렉터리를 그대로 따릅니다.

> [!IMPORTANT]
> 사진을 다른 폴더로 직접 옮기지 않는 한 원본 파일은 바뀌지 않습니다. 폴더를 라이브러리에서 제거하는 것과 Finder에서 파일을 지우는 것은 별개의 동작입니다.

## 가져오기

가져오기 컨트롤 아래에는 진행 막대와 백분율/완료 건수가 표시됩니다. 메타데이터를 메인 스레드 밖에서 읽고 새 프레임을 한꺼번에 등록하므로 큰 폴더를 불러올 때도 라이브러리 색인을 한 번에 갱신해 줍니다.

입력 형식은 TIFF/PNG/JPEG/HEIC/HEIF/BMP/DNG와 카메라 RAW를 지원하며 내장된 Gray와 RGB ICC 프로파일을 읽고, 프레임 크기가 일치하는 `_ir` / `-ir` / `.ir` 적외선 동반 파일은 자동으로 연결합니다.

가져온 사진의 자동 현상은 **기본 상태가 꺼짐**이므로 아래의 세 단계를 따릅니다.

1. 원본을 등록합니다.
2. 원본 썸네일과 폴더가 먼저 나타납니다.
3. 폴더에 프로세스와 타깃을 실행하거나 현상 화면에 들어가면 그때 현상이 시작됩니다.

가져온 사진을 모두 자동으로 현상하려면 **설정 > 워크플로우 > 새로 가져온 사진 자동 현상**을 켜며 이 선택은 앱을 다시 열어도 그대로 남습니다. 이 옵션은 새로 가져온 프레임에만 작동하고 이미 현상된 프레임은 그대로 보존하므로 현상이 끝난 사진은 폴더에서 **적용**을 직접 누르거나 설정을 붙여넣을 때만 다시 렌더링합니다.

반면 스캐너 캡처는 스캔 중에 필름 종류와 프로세스/타깃을 미리 지정하므로 스캔 결과가 게시되자마자 현상이 바로 열립니다. 현상과 인화 화면의 필름스트립은 컬러 네거티브와 슬라이드, 흑백 네거티브와 흑백 포지티브 원본에 현상된 썸네일을 표시하는 반면 라이브러리 화면은 원본 상태를 확인하기 위해 원본 썸네일을 그대로 보여 줍니다.

## 폴더 목록

- 접힘과 펼침 상태는 그대로 유지되어 새 폴더를 만들거나 앱을 다시 열더라도 기존 폴더의 접힌 상태가 보존됩니다.
- 폴더 행마다 똑같은 `×` 컨트롤이 자리합니다. 이 버튼은 선택한 폴더와 사진을 **라이브러리에서만** 걷어냅니다. 원본 파일은 Finder에 그대로 남습니다.
- 현상 화면에서 폴더 안의 사진 목록은 높이가 제한된 자체 스크롤 영역 안에서 움직이므로 목록이 길거나 화면이 작아도 사이드바의 나머지 영역을 그대로 확보합니다.
- 라이브러리와 필름스트립의 프레임에서는 별점(`1`–`5`)과 채택/제외(Pick/Reject) 플래그, 가상 사본과 스택, 컬렉션과 스냅샷/편집 기록, 카탈로그 백업과 휴대용 `.negaflowarchive` 아카이브를 함께 관리할 수 있습니다.

### 사진을 다른 폴더로 옮기기

사진 한 장이나 선택한 사진을 다른 폴더 행으로 끌어다 놓으면 실제 파일을 옮기고 카탈로그도 함께 갱신하는데 가져온 폴더와 앱이 만든 폴더뿐 아니라 스캐너 캡처가 든 폴더도 똑같은 규칙을 따릅니다.

이때 옮겨 갈 폴더에 이름이 겹치는 파일이 이미 있으면 기존 파일을 보호하기 위해 `frame.tiff` 대신 `frame 2.tiff`나 `frame 3.tiff`처럼 번호를 붙인 새 이름을 차례로 시도하며 스캐너 원본의 IR 동반 파일도 한 번의 트랜잭션으로 함께 옮깁니다.

### Finder에서의 변경

negaflow는 등록된 실제 원본 폴더를 감시합니다. 짧은 디바운스 뒤에 아래를 보면 바뀐 폴더만 다시 훑습니다.

- 원본 파일의 이동이나 이름 변경
- 등록된 폴더의 이동이나 이름 변경
- 등록된 폴더 바로 안에 생긴 새 이미지

macOS에서는 원본의 영구 북마크가 새 위치를 찾아내면 기존 프레임을 다시 연결하고 Windows에서는 `FileSystemWatcher`가 등록된 폴더마다 파일 이동과 이름 변경, 새 이미지를 감시해 카탈로그를 갱신합니다. 옮긴 폴더는 폴더 ID와 추가 날짜를 그대로 유지하며 새로 생긴 파일은 기존 항목과 중복을 피해서 가져옵니다.

이 감시 경로는 주기적 폴링 대신 파일 시스템 이벤트로만 동작하므로 실제 상위 폴더가 일치하는 프레임들은 감시자 한 개를 공유하고 변경 이벤트가 발생한 폴더만 다시 확인합니다.

## 폴더 단위 현상

폴더 제목 옆에서 프로세스와 타깃을 고른 뒤 **적용** 버튼을 누르면 별도 토글 스위치 없이 바로 일괄 렌더링이 열립니다.

이 작업은 이전에 현상한 사진을 포함해 폴더 안의 모든 사진을 새 프로세스와 타깃으로 다시 렌더링하되 노출이나 대비처럼 사용자가 개별 조정한 수치는 그대로 보존하며 이미 렌더링 중인 프레임이 있으면 그 작업이 끝나기를 기다립니다.

버튼 옆에는 진행 막대와 백분율/완료 건수가 표시되며 대량 배치에서는 사진마다 작업을 한꺼번에 띄우는 대신 정해진 렌더링 슬롯 수만큼만 작업자를 유지합니다.

## 수평 보정과 기하 변환

현상 화면 오른쪽에서 편집 > 크롭을 연 뒤 ⌘(Windows는 Ctrl)를 누른 채 수평 기준이 될 가장자리를 따라 드래그하고 놓으면 그 선이 수평이 되도록 사진이 회전하며 세로에 가깝게 그은 선은 수직축에 맞춰집니다. ⌥(Windows는 Alt)를 누르고 있는 동안에는 크롭 영역 위에 촘촘한 보조 그리드가 나타납니다.

이 두 보조 키는 작업 공간과 현상, 별점과 결함 도구 단축키와 함께 설정 > 단축키에서 바꿀 수 있되 서로 다른 키로 지정해야 하며 Mac에서는 ⌃ 클릭이 보조 클릭으로 동작하므로 수평 보정 키에서 ⌃는 빠집니다.

변환 섹션은 캘리브레이션 아래이자 디테일과 효과 위에 놓입니다. 여기서 끔은 원본 기하를 그대로 유지하는 반면 자동과 수준, 수직과 전 방향 옵션은 이미지에서 곧은 선분을 검출해 원근을 바로잡습니다.

구체적으로 수준은 회전만 교정하고 수직은 위로 모이는 세로선까지 곧게 세우며 전 방향은 세로와 가로 원근을 함께 보정하고 자동은 전 방향과 똑같은 계산을 수행하되 과도한 변형을 억제합니다. 마지막으로 도우미는 사용자가 화면 위에 직접 그린 안내선 2~4개를 기준으로 삼습니다.

수직과 수평뿐 아니라 회전과 종횡비, 비율과 X/Y 오프셋 슬라이더도 각 모드가 찾은 결과 위에 추가로 반영되며 슬라이더를 두 번 누르면 기본 수치로 복귀합니다.

자르기 제한을 켜면 빈 모서리가 생기지 않는 가장 큰 내접 사각형으로 잘라 내고 끄면 빈 모서리를 화면과 내보내기 파일 모두에서 흰색으로 채우는데 히스토그램과 클리핑 경고, 자동 톤과 자동 화이트 밸런스 계산에서는 이 여백을 걸러냅니다. 아울러 90° 회전과 뒤집기를 실행해도 기하 보정이 함께 따라가며 모든 보정 리셋을 실행하면 크롭과 각도/변환 설정이 함께 지워집니다.

## 프리셋과 설정 복사

현상 설정은 따로 고를 수 있는 그룹이 일곱 개입니다.

| 그룹 | 포함 항목 |
|---|---|
| 입력 감마 | 원본 전달 곡선 해석 |
| 베이스 스케일 | 필름 베이스 스케일 |
| 베이스 | 필름 종류와 프로세스/타깃, 스캐너 프로파일과 필름 베이스, 채널 범위 보정과 자동 밸런스/자동 레벨/무채색 밸런스 |
| 톤 | 노출과 대비/농도, 하이라이트와 섀도, 화이트와 블랙/톤 커브 |
| 색 | 온도와 색조/색 깊이, 비브런스와 채도, 믹서와 그레이딩/캘리브레이션, 흑백 토닝과 필름 에뮬레이션 |
| 디테일 | 그레인과 선명도/할레이션, 클래리티와 비네트/노이즈 감소, GrainMend 강도와 부분 보정 |
| 지오메트리 | 크롭과 회전, 가로/세로 뒤집기, 수평 보정과 크롭 비율/변환 |

일괄 붙여넣기나 사용자 프리셋은 대상의 현상 상태를 통째로 교체하는 반면 범위를 지정한 붙여넣기는 선택한 그룹의 유효 항목만 바꾸고 나머지는 그대로 보존합니다.

룩의 일부만 붙여넣을 때는 룩의 톤과 색/질감 기여분을 개별 수치에 먼저 합산한 뒤 룩 참조를 비워서 이전 룩이 중복 합산되는 일을 막으며 똑같은 항목을 여러 번 붙여넣어도 결과가 달라지지 않습니다. 메뉴와 단축키/패널은 모두 똑같은 붙여넣기 범위를 공유합니다.

붙여넣기와 사용자 프리셋은 선택한 모든 사진에 한꺼번에 들어갑니다. 실행 취소와 다시 실행 한 번으로 선택한 사진을 모두 되돌릴 수 있으며 Windows에서는 변경을 시작하기 전에 모든 대상을 먼저 검증합니다. 반영 직후에는 썸네일과 현재 미리보기를 새 설정으로 갱신하되 원본 파일과 평점/원본 좌표에 종속된 결함 편집은 복사 대상에서 빠집니다.

사용자 프리셋은 모든 현상 상태와 기하 항목을 함께 기록하며 그 항목이 빠진 구버전 프리셋이나 붙여넣기 범위에는 하위 호환용 기본값을 채워 넣습니다. 이름을 비워 놓으면 사용 가능한 첫 번호가 자동으로 붙고 이름이 겹치더라도 기존 프리셋을 보존한 채 별도 항목으로 등록합니다.

## 스캐너 플러그인 없이

시작할 때 스캐너 플러그인이 설치되어 있지 않으면 공용 라이브러리와 현상 사이드바에서는 플러그인 안내와 다시 검색 컨트롤/시뮬레이터 블록을 숨긴 채 이미지 가져오기 기능만 깔끔하게 보여 줍니다.

스캐너 다시 검색과 시뮬레이터 지원은 그대로 있습니다. 스캐너 진입점과 설정에서 호출할 수 있고 플러그인을 설치하거나 시뮬레이터를 직접 켜면 기존 스캐너 UI가 나타납니다.

## 인화 레이아웃과 출력 수

인화 모듈은 단일 이미지와 콘택트 시트, 사진 패키지와 사용자 패키지, 시아노타입과 유리건판, 젤라틴과 워터마크의 여덟 가지 레이아웃을 제공합니다. 이 가운데 단일 이미지 계열 다섯 가지는 선택한 사진마다 완성된 페이지를 세로 스크롤로 보여 주며 워터마크는 독립된 레이아웃으로 분리하고 나머지는 기존 컨트롤을 그대로 지킵니다.

내보내기와 빠른 내보내기는 완성된 페이지 단위로 출력 수량을 계산합니다. 예를 들어 사진 39장의 6 × 7 콘택트 시트는 합성한 파일 한 개, 4장짜리 사진 패키지는 10페이지, 기본 사용자 패키지는 한 페이지가 되고 단일 이미지 계열 다섯 가지는 제한된 배치로 39개 파일이 됩니다.

패키지 화면은 이미 준비된 썸네일과 현상 이미지/RAW 데이터를 재사용하고 캐시가 전혀 없을 때만 축소본을 새로 만듭니다.

최종 내보내기는 원본 메타데이터로 배치마다 좌표를 계산해 필요한 화소만 현상하며 원본을 2~4개씩 동시에 준비하고 마지막 페이지 렌더링까지 한 Core Image 그래프로 구성해 처리합니다. 덕분에 공유 렌더 컨텍스트와 페이지당 512MiB의 원본 래스터 예산 안에서 고해상도 중간 이미지가 과도하게 불어나는 현상을 막습니다.

## 인화 워터마크

레이아웃 종류 메뉴에서 젤라틴 다음에 있는 워터마크를 고르면 원본 사진을 자르는 대신 하단에 여백 띠를 두르고 필요하면 똑같은 높이의 상단 여백도 함께 넣을 수 있어서 최종 용지 크기가 사진과 여백을 합친 치수를 따릅니다.

하단 영역의 왼쪽에는 카메라와 렌즈 정보가 위아래로 배치되고 오른쪽에는 로고 옆으로 초점 거리와 조리개/셔터 속도/ISO가 나란히 들어간 뒤 그 아래에 촬영 날짜가 놓입니다.

로고 옵션을 켜고 별도 이미지를 지정하지 않으면 기본 negaflow 로고를 그리며 카메라 제조사 로고는 번들에 포함하지 않으므로 사용자가 JPEG나 PNG 이미지를 직접 선택해 경로만 설정과 템플릿에 저장합니다. 렌더링할 때 지정한 경로의 크기와 수정 시각이 이전과 일치하면 캐시된 로고를 재사용하고 원본이 이동됐거나 삭제됐으면 로고만 생략한 채 하단 상태 점과 진단 보고서에 표시해 줍니다.

카메라와 렌즈/노출/날짜 입력란 가운데 비워 놓은 항목은 생략하고 입력된 문구만 그리며 문구가 길거나 세로 사진처럼 가로 폭이 좁으면 내부 요소를 똑같은 비율로 축소해 글자가 영역 밖으로 넘치는 일을 막습니다.

여백 스타일은 흰색과 검정, 사진을 흐리게 편 이미지 중에서 선택합니다. 흰색에서는 상단 문구를 검정으로, 하단 문구를 회색으로 표시하고 검정에서는 모든 글자를 밝게 그리며 흐린 이미지에서는 글자와 분포 그래프의 색상을 검정이나 밝은 색 중에서 직접 고릅니다.

밝기 분포는 점 형태의 막대그래프로 나타내며 항목 이름과 그래프의 배치 규칙은 [인화 레이아웃과 C-print 미리보기](../reference/C_PRINT.md)에 정리했습니다. 흐린 배경과 분포 계산에는 사용 가능한 필름스트립 썸네일을 우선 재사용하고 없을 때만 축소한 사진 이미지를 활용하며 템플릿에는 용지 색상과 문구/로고 경로를 비롯한 모든 워터마크 설정이 함께 저장됩니다.

## 인화 프로파일

인화의 ICC 컨트롤은 각기 다른 역할을 맡습니다.

| 설정 | 화면 미리보기 | 인화 내보내기 | 현상 미리보기 |
|---|---|---|---|
| 프린터 출력 프로파일 | C-print 미리보기가 꺼져 있을 때 인화 결과를 보여 줌 | 완성된 페이지에 반영(비-Raw/비-DNG 형식) | 소프트 프루프가 켜져 있고 프레임 타깃이 `PRINT`일 때 사용 |
| C-print 프루프 프로파일 | 랩과 용지 공정을 소프트 프루프 | 전달 파일에 굽지 않음 | 반영 안 함 |
| 일반 소프트 프루프 | ICC 프로파일은 인화에서 제외되고(macOS의 프루프 사본 제외), 프린터 출력 프로파일을 미리 볼 때 `프로파일` 대 `용지 + 블랙` 시뮬레이션 모드가 작동함 | 표시 보조일 뿐 | 자체 설정을 따름(`PRINT` 타깃에서는 프린터 출력 프로파일로 전환) |

프린터 출력 프로파일은 **설정 > 내보내기 > 색상 관리**에서 고릅니다. 현상과 인화는 모두 소프트 프루프와 색역 경고를 지원하며 Windows에서는 Windows Advanced Color가 꺼져 있을 때 현재 모니터 ICC 프로파일을 미리보기에 반영합니다.

프린터 출력 프로파일은 개별 사진을 복제하기 전에 미리 씌우는 대신 콘택트 시트와 사진 패키지/사용자 패키지의 레이아웃을 먼저 완성한 뒤 완성된 페이지에 한 번만 씌웁니다. 따라서 사진 한 장을 반복해 배치한 페이지와 여러 사진을 섞은 페이지가 똑같은 출력 변환을 거칩니다.

C-print 프루프 프로파일은 현상소가 제공한 공정 미리보기 전용이므로 실제 출력 프로파일과 완전히 분리되어 동작하며 프로파일 요건과 정확도 범위는 [인화 레이아웃과 C-print 미리보기](../reference/C_PRINT.md)에 정리했습니다.

## DNG 내보내기

DNG는 현상한 그림을 sRGB와 Display P3/Adobe RGB 중 고른 출력 색 공간의 비압축 16비트 선형 RGB 파일(`PhotometricInterpretation = LinearRaw`)로 내보냅니다.

톤과 색이 이미 반영되어 있어서 다른 앱은 출력 기준 파일로 읽으며 TIFF와 똑같은 메타데이터 정책에 따라 저작권과 스캐너/소프트웨어/날짜/필름 메모를 기록하되 원본 카메라의 EXIF와 IPTC/GPS는 제외합니다. 화소당 6바이트이므로 24메가픽셀 프레임은 약 144MB가 됩니다.

JPEG와 PNG, 8비트나 16비트 TIFF와 Raw TIFF 외에도 비압축 원본(TIFF와 BMP, 카메라 RAW와 DNG)에서는 선형 DNG를 내보낼 수 있습니다. 선택한 모든 프레임이 이 조건을 만족할 때만 DNG 옵션이 열리며 손실 압축이나 웹 형식(JPEG/PNG/HEIC/HEIF/WebP/AVIF/GIF) 원본은 DNG 출력 대상에서 빠집니다.

현상과 `PRINT` 타깃, 인화 레이아웃이 모두 DNG를 지원하는데 인화 DNG는 합성한 페이지를 ColorMatrix가 붙은 표준 RGB로 기록하고 프린터 ICC 변환은 생략합니다. DNG 내보내기는 사용자가 지정한 폴더에 `.dng` 확장자로 저장하고 최종 파일 게시와 검증을 마쳐야 완료로 표시하며 생성된 파일은 exiftool과 Apple 이미지 디코더에서 정상으로 읽힙니다.

## 원본을 바꾸는 동작

| 동작 | Finder의 원본 | 카탈로그와 편집 |
|---|---|---|
| 폴더 `×` | 유지 | 폴더와 사진이 라이브러리에서 제거됨 |
| 다른 폴더로 끌기 | 이동, 이름이 겹치면 새 이름 선택 | 새 위치로 다시 연결 |
| Finder에서 이동과 이름 변경 | 사용자가 한 변경 유지 | 북마크로 자동 재연결 |
| 폴더 현상 실행 | 유지 | 프로세스와 타깃을 갱신하고 다시 렌더링 |
| 프리셋과 설정 복사 | 유지 | 선택한 현상과 지오메트리 설정 갱신 |
| 인화 내보내기 | 유지 | 별도의 출력 파일과 렌더 기록 생성 |

## 대형 라이브러리 점검

사진이 256장을 넘으면 선택이 바뀔 때마다 필름스트립이 길게 자동 스크롤하는 동작을 멈추고 화면에 들어오는 카드와 폴더 행만 필요한 시점에 생성합니다.

2,000프레임 부하 점검은 24MP/40MP/60MP 해상도와 3200 DPI/4800 DPI 스캔 픽스처를 폴더 50개에 나누어 가져옵니다. 모든 프로세스와 타깃을 섞고 컬러 네거티브를 절반 이상으로 배치한 뒤 크롭과 방향 변경을 거쳐 현상과 썸네일/카탈로그 왕복을 검증하며 `negaflow-mac/`에서 아래 명령으로 실행합니다.

```bash
bash scripts/performance/run-virtual-library-stress.sh
```

이 부하 점검은 수동 실행 전용이라 기본 `swift test`에서는 빠집니다.

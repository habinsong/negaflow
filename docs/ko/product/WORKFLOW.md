# 라이브러리에서 인화까지

[문서 홈](../README.md)

사진을 가져오고, 폴더에서 현상 범위를 정하고, 여러 사진에 같은 편집을 옮긴 뒤 인화하는
과정을 설명합니다. 이 문서의 폴더는 화면에만 보이는 분류가 아니라 각 사진의 실제 원본
위치를 기준으로 합니다.

> [!IMPORTANT]
> 사진 이동처럼 명시적으로 파일 위치를 바꾸는 동작을 제외하면 원본 파일을 수정하지 않습니다.
> 라이브러리에서 제거하는 일과 Finder의 파일을 지우는 일도 서로 다릅니다.

## 가져오기

이미지나 폴더를 고르면 가져오기 캡슐 아래에 진행 막대, 퍼센트, 완료 장수와 전체 장수가
나옵니다. 메타데이터는 백그라운드에서 읽고, 프레임 등록은 한 번에 묶어 큰 폴더에서도
라이브러리 재색인을 반복하지 않습니다.

가져온 사진의 자동 현상 기본값은 **꺼짐**입니다.

1. 원본을 등록합니다.
2. 원본 썸네일과 폴더를 먼저 보여 줍니다.
3. 사용자가 폴더에서 **적용**을 누르거나 현상 화면으로 들어가면 현상을 시작합니다.

항상 자동으로 현상하려면 **설정 → 작업 흐름 → 가져온 이미지 자동 현상**을 켭니다. 이 값은
앱을 다시 열어도 유지됩니다.

가져오기 자동 현상은 이번 가져오기에서 새로 등록한 프레임에만 적용합니다. 기존에 현상된 상태를
덮어쓰지 않습니다. 이미 현상한 사진을 다시 처리하는 때는 사용자가 폴더 **적용**이나 설정
붙여넣기를 직접 실행했을 때뿐입니다.

스캐너로 만든 사진은 예외입니다. 스캔할 때 필름 종류, 현상 프로세스와 타깃이 이미 정해져
있으므로 스캔 공개가 끝난 뒤 바로 현상합니다. 현상과 인화 화면의 필름스트립에는 컬러
네거티브, 슬라이드, 흑백 네거티브, 흑백 포지티브 모두 현상된 썸네일을 사용합니다.
라이브러리는 원본 확인을 위해 원본 썸네일을 유지합니다.

## 폴더 목록

- 폴더를 접거나 펼친 상태는 저장됩니다. 새 폴더를 만들거나 앱을 다시 열어도 다른 폴더가
  저절로 펼쳐지지 않습니다.
- 모든 폴더 행에는 같은 위치에 `×`가 있습니다. 이 버튼은 해당 폴더와 사진을
  **라이브러리에서만 제거**하며 Finder의 원본은 남깁니다.
- 현상 화면의 폴더 안 사진 목록은 높이가 제한된 자체 스크롤을 씁니다. 사진이 많거나 창이
  작아도 폴더 제목과 다른 사이드바 항목은 함께 밀려나지 않습니다.

### 사진을 다른 폴더로 옮기기

사진 한 장 또는 여러 장을 선택해 다른 폴더 행으로 끌면 실제 파일과 카탈로그 위치를 함께
옮깁니다. 앱에서 만든 폴더, 가져온 폴더, 스캔 파일이 들어 있는 폴더에 같은 규칙을 씁니다.

목적지에 같은 이름이 있으면 이동을 거절하거나 기존 파일을 덮어쓰지 않습니다.
`frame.tiff`가 있으면 `frame 2.tiff`, 그 파일도 있으면 `frame 3.tiff`처럼 빈 이름을
찾습니다. 스캔 원본에 IR 동반 파일이 있으면 IR 파일도 같은 이동에 포함합니다.

### Finder에서 위치를 바꿨을 때

negaflow는 등록된 실제 원본 폴더를 감시합니다. Finder에서 다음 동작이 생기면 약간의
디바운스 뒤 변경된 폴더만 다시 읽습니다.

- 사진 이동과 이름 변경
- 등록된 폴더 이동과 이름 변경
- 등록된 폴더 바로 안에 새 이미지 추가

원본의 persistent bookmark가 새 위치를 확인하면 기존 프레임을 다시 연결합니다. 폴더 전체가
옮겨진 경우에도 폴더 ID와 추가 날짜를 유지합니다. 새 사진만 생긴 경우에는 이미 등록한
파일을 중복으로 만들지 않고 새 파일만 가져옵니다.

이 감시는 주기적으로 전체 라이브러리를 훑는 폴링이 아닙니다. 실제 원본 경로가 같은 프레임은
하나의 폴더 감시를 공유하고, 변경 신호가 들어온 폴더만 검사합니다.

## 폴더별 현상

라이브러리의 폴더 제목 오른쪽에서 현상 프로세스와 타깃을 고르고 **적용**을 누릅니다.
별도의 끔·켬 토글은 없습니다.

적용하면 그 폴더의 모든 사진을 다시 렌더링합니다. 이미 현상한 사진도 새 프로세스와 타깃을
반영하며, 노출·대비처럼 사용자가 조절한 다른 값은 그대로 둡니다. 다른 현상 작업이 진행
중이면 끝날 때까지 기다렸다 이어서 처리합니다.

적용 버튼 옆에는 진행 막대, 퍼센트, 완료 장수와 전체 장수가 나옵니다. 대량 작업은 사진
수만큼 작업을 한꺼번에 만들지 않고 렌더 슬롯 수만큼만 처리해 메모리를 제한합니다.

## 프리셋과 복사·붙여넣기

현상 설정은 다음 다섯 묶음으로 옮길 수 있습니다.

| 묶음 | 포함되는 값 |
|---|---|
| 베이스 | 필름 종류와 프로세스, 현상 타깃, 스캐너 프로파일, 필름 베이스, 자동 레벨·중성화 |
| 톤 | 노출, 대비, 농도, 하이라이트·섀도, 화이트·블랙, 톤 커브 |
| 색 | 색온도, 틴트, 컬러 깊이, 채도, 믹서, 그레이딩, 캘리브레이션, 흑백 토닝, 필름 에뮬레이션 |
| 디테일 | 그레인, 선명도, 할레이션, 클라리티, 비네팅, 노이즈 제거, GrainMend, 부분 보정 |
| 편집 | 크롭, 회전, 가로·세로 뒤집기, 기울기 보정, 크롭 비율 |

전체 붙여넣기는 다섯 묶음을 모두 사용합니다. 범위를 고르면 선택한 묶음만 바꾸고 나머지는
대상 사진의 값을 유지합니다. 여러 사진을 선택한 상태에서 붙여넣으면 선택한 사진 모두에
적용하고, 이후 현상도 제한된 작업 수로 이어서 처리합니다.

사용자 프리셋도 같은 전체 현상 상태와 편집 방향을 저장합니다. 예전 프리셋이나 붙여넣기
범위에 편집 항목이 없으면 호환을 위해 편집을 포함한 것으로 읽습니다.

## 스캐너가 없을 때

시작할 때 설치된 스캐너 플러그인이 없으면 라이브러리와 현상 화면의 공통 왼쪽 사이드바에
플러그인 없음 설명, 다시 찾기, 시뮬레이터 묶음을 자동으로 띄우지 않습니다. 사진 가져오기는
그대로 사용할 수 있습니다.

스캐너 다시 찾기와 시뮬레이터 기능을 없앤 것은 아닙니다. 스캐너 진입점이나 설정에서 직접
열 수 있고, 플러그인이 설치되거나 사용자가 시뮬레이터를 켠 경우에는 기존 스캐너 화면을
사용합니다.

## 인화 레이아웃과 출력 장수

인화에는 단일 이미지, 콘택트 시트, 사진 패키지, 사용자 패키지, 시아노타입, 유리건판,
젤라틴의 7가지 레이아웃이 있습니다. 시아노타입, 유리건판, 젤라틴은 단일 이미지와 같은
인스펙터를 사용합니다. 여러 사진을 골랐을 때 한 장씩 인화하는 네 레이아웃은 완성 페이지를
세로로 이어 보여 주며 아래로 스크롤해 다음 사진으로 이동합니다.

내보내기와 빠른 내보내기의 장수는 선택한 원본 수가 아니라 완성 페이지 수입니다. 예를 들어
39장을 6 × 7 콘택트 시트에 넣으면 합성된 한 파일, 4장 사진 패키지는 10페이지, 기본 사용자
패키지는 한 페이지, 한 장씩 인화하는 네 레이아웃은 제한된 배치로 39파일을 만듭니다.

패키지 미리보기는 이미 있는 썸네일·현상 이미지·원본 프리뷰를 재사용하고, 아무것도 없을 때만
작은 빠른 프리뷰를 만듭니다. 최종 출력은 원본 메타데이터로 배치를 먼저 계산하고 각 칸에 필요한
픽셀만 현상합니다. 한 번에 2~4개 원본만 준비하고 Core Image 그래프를 최종 페이지 렌더까지
유지하며, 공유 렌더 컨텍스트와 페이지당 512 MiB 원본 래스터 한도로 풀해상도 중간 이미지가
장수만큼 무한히 늘어나지 않게 합니다.

## 인화 프로파일

인화에서 쓰는 ICC는 역할이 다릅니다.

| 항목 | 화면 미리보기 | 인화 내보내기 | 현상 화면 |
|---|---|---|---|
| 프린터 출력 프로파일 | 인화 결과 확인 | 배치가 끝난 페이지 전체에 적용 | 적용하지 않음 |
| C-print 인화 프로파일 | 인화소·인화지 공정의 소프트 프루프 | 전달 파일에는 굽지 않음 | 적용하지 않음 |
| 일반 소프트 프루프 | 설정한 화면 범위에서 확인 | 화면 보조 기능 | 설정에 따름 |

프린터 출력 프로파일은 단일 사진에 먼저 적용한 뒤 복사하는 방식이 아닙니다. 콘택트 시트,
사진 패키지, 사용자 패키지를 한 페이지로 만든 다음 마지막에 한 번 적용합니다. 한 원본을
여러 칸에 반복하거나 여러 원본을 다른 크기로 섞어도 페이지의 모든 배치 항목에 같은
프로파일이 들어갑니다.

C-print 인화 프로파일은 인화소가 제공한 공정 미리보기용입니다. 출력 프로파일로 몰래
사용하지 않습니다. 두 프로파일의 정확한 차이와 프로파일 조건은
[인화 레이아웃과 C-print 미리보기](../reference/C_PRINT.md)에 있습니다.

## 원본에 영향을 주는 동작

| 동작 | Finder의 원본 | 카탈로그와 편집 |
|---|---|---|
| 폴더의 `×` | 그대로 둠 | 해당 폴더와 사진을 라이브러리에서 제거 |
| 사진을 다른 폴더로 드래그 | 목적지로 이동, 충돌 시 새 이름 | 새 위치로 다시 연결 |
| Finder에서 이동·이름 변경 | 사용자가 바꾼 위치 유지 | bookmark로 자동 다시 연결 |
| 폴더별 현상 적용 | 그대로 둠 | 프로세스·타깃 갱신 후 다시 렌더링 |
| 프리셋·복사 붙여넣기 | 그대로 둠 | 선택한 현상·편집 값 갱신 |
| 인화 내보내기 | 그대로 둠 | 별도 출력 파일과 렌더 기록 생성 |

## 큰 라이브러리 확인

필름스트립은 256장을 넘으면 선택 변화마다 먼 거리로 자동 스크롤하지 않습니다. 화면에는
필요한 카드만 만들고, 폴더 내부 사진 목록도 지연 생성합니다.

2,000프레임 검사는 24 MP, 40 MP, 60 MP, 3200 DPI, 4800 DPI 픽셀 자료를 50개 폴더에
나눠 가져옵니다. 모든 현상 프로세스와 타깃을 섞고 컬러 네거티브 비중을 절반보다 높인 뒤,
크롭과 방향까지 적용해 현상·썸네일·카탈로그 저장을 확인합니다.

```bash
bash scripts/performance/run-virtual-library-stress.sh
```

이 검사는 시간이 오래 걸리므로 일반 `swift test`에서는 건너뜁니다.

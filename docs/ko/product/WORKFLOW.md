# 라이브러리에서 인화까지

[문서 홈](../README.md)

이 안내는 가져오기, 폴더 현상, 설정 옮기기, 스캐너 썸네일, 인화 출력을 다룹니다. 라이브러리의 폴더는 각 원본의 실제 상위 폴더를 따릅니다.

> [!IMPORTANT]
> 사진을 다른 폴더로 직접 옮기지 않는 한 원본 파일은 바뀌지 않습니다. 폴더를 라이브러리에서 제거하는 것과 Finder에서 파일을 지우는 것은 별개의 동작입니다.

## 가져오기

가져오기 컨트롤 아래에 진행 막대, 백분율, 완료한 수, 전체 수가 나옵니다. 메타데이터는 메인 스레드 밖에서 읽고 새 프레임을 한꺼번에 등록하므로 큰 폴더에서도 라이브러리 색인을 계속 다시 만들지 않습니다.

가져온 사진의 자동 현상은 **기본값이 꺼짐**입니다. 가져오기는 이렇게 진행됩니다.

1. 원본을 등록합니다.
2. 원본 썸네일과 폴더가 먼저 나타납니다.
3. 폴더에 프로세스와 타깃을 적용하거나 현상 화면에 들어가면 현상이 시작됩니다.

가져온 사진을 모두 자동으로 현상하려면 **설정 → 워크플로우 → 새로 가져온 사진 자동 현상**을 켭니다. 선택은 실행 사이에 유지됩니다. 이 설정은 그 가져오기로 등록된 프레임에만 적용되고 이미 현상된 상태를 바꾸지 않습니다. 현상된 사진은 폴더에서 **적용**을 직접 누르거나 설정을 붙여넣을 때만 다시 처리합니다.

스캐너 캡처는 다릅니다. 필름 종류, 프로세스, 타깃을 스캔 중에 정하므로 스캔 결과가 게시된 뒤에 현상이 시작됩니다. 현상과 인화의 필름스트립은 컬러 네거티브, 슬라이드, 흑백 네거티브, 흑백 포지티브 원본에 현상된 썸네일을 씁니다. 라이브러리는 원본 확인을 위해 원본 썸네일을 유지합니다.

## 폴더 목록

- 접힘과 펼침 상태는 유지됩니다. 폴더를 만들거나 앱을 다시 열어도 다른 폴더가 펼쳐지지 않습니다.
- 폴더 행마다 같은 `×` 컨트롤이 있습니다. 이 컨트롤은 그 폴더와 사진을 **라이브러리에서만** 제거합니다. 원본 파일은 Finder에 남습니다.
- 현상 화면에서 폴더 안의 사진 목록은 높이가 제한된 자체 스크롤 영역을 가집니다. 목록이 길거나 창이 작아도 사이드바의 나머지가 밀려나지 않습니다.

### 사진을 다른 폴더로 옮기기

사진 한 장이나 선택한 사진을 다른 폴더 행으로 끌어다 놓으면 실제 파일을 옮기고 카탈로그도 함께 갱신합니다. 가져온 폴더, 앱이 만든 폴더, 스캐너 캡처가 든 폴더 모두 같은 규칙입니다.

목적지에 같은 이름이 있어도 덮어쓰지 않습니다. `frame.tiff`가 있으면 negaflow는 `frame 2.tiff`, `frame 3.tiff` 순으로 시도합니다. 스캐너 원본의 IR 동반 파일은 같은 트랜잭션으로 옮깁니다.

### Finder에서의 변경

negaflow는 등록된 실제 원본 폴더를 감시합니다. 짧은 디바운스 뒤에 아래를 보면 바뀐 폴더만 다시 훑습니다.

- 원본 파일의 이동이나 이름 변경
- 등록된 폴더의 이동이나 이름 변경
- 등록된 폴더 바로 안에 생긴 새 이미지

원본의 영구 북마크가 새 위치를 찾아내면 기존 프레임을 다시 연결합니다. 옮긴 폴더는 폴더 ID와 추가 날짜를 유지합니다. 새로 생긴 파일은 이미 아는 파일과 중복되지 않게 가져옵니다.

이것은 이벤트 기반의 폴더 감시이며 주기적으로 라이브러리 전체를 훑는 방식이 아닙니다. 실제 상위 폴더가 같은 프레임은 감시 하나를 함께 쓰고, 변경을 알린 폴더만 확인합니다.

## 폴더 단위 현상

폴더 제목 옆에서 프로세스와 타깃을 고르고 **적용**을 누릅니다. 따로 켜고 끄는 스위치는 없습니다.

적용은 이전에 현상한 사진을 포함해 폴더의 모든 사진을 다시 렌더링합니다. 새 프로세스와 타깃이 쓰이고 노출, 대비 같은 다른 사용자 조정은 그대로 남습니다. 이미 렌더링 중인 프레임이 있으면 폴더 작업은 그 렌더링이 끝나기를 기다립니다.

적용 옆에 진행 막대, 백분율, 완료한 수, 전체 수가 나옵니다. 큰 배치는 사진마다 작업을 시작하지 않고 렌더링 슬롯 수만큼의 작업자만 유지합니다.

## 수평 맞추기와 변환

현상 화면 오른쪽에서 편집 → 크롭을 엽니다. ⌘(Windows는 Ctrl)를 누른 채 수평이어야 할 가장자리를 따라 드래그하고 놓으면 그 선이 수평이 되도록 사진이 돌아갑니다. 세로에 가깝게 그은 선은 수직으로 맞춥니다. ⌥(Windows는 Alt)를 누르고 있는 동안에는 크롭 위에 촘촘한 격자가 나옵니다. 두 키는 설정 → 단축키에서 바꿀 수 있고 같은 키로 둘 수는 없습니다. Mac에서는 ⌃ 클릭이 오른쪽 클릭이라서 기준선 키로 ⌃를 고를 수 없습니다.

변환 섹션은 캘리브레이션과 디테일 및 효과 사이에 있습니다. 끔은 사진을 그대로 둡니다. 자동·수준·수직·전체는 사진에서 곧은 선을 한 번 찾아 보정합니다. 수준은 사진을 돌리기만 하고 수직은 위로 모이는 세로선까지 세웁니다. 전체는 세로와 가로 원근을 모두 바로잡습니다. 자동은 전체와 같은 일을 하되 큰 보정을 억제합니다. 도우미는 사진 위에 직접 그린 안내선 2~4개를 따릅니다.

수직, 수평, 회전, 종횡비, 비율, X 오프셋, Y 오프셋 슬라이더는 모드가 찾은 값 위에 더해집니다. 슬라이더를 두 번 누르면 처음 값으로 돌아갑니다. 자르기 제한을 켜면 빈 모서리가 없는 가장 큰 사각형으로 잘라 냅니다. 끄면 빈 모서리는 화면에서도 내보낸 파일에서도 흰색입니다. 히스토그램, 클리핑 경고, 자동 톤, 자동 화이트 밸런스는 그 자리를 사진으로 세지 않습니다. 90° 회전과 뒤집기를 해도 보정은 그대로 따라가고, 모든 보정 초기화는 크롭·각도와 함께 변환도 지웁니다.

## 프리셋과 복사·붙여넣기

현상 설정은 따로 고를 수 있는 그룹이 일곱 개입니다.

| 그룹 | 값 |
|---|---|
| 입력 감마 | 원본 전달 특성 해석 |
| 베이스 스케일 | 필름 베이스 스케일 |
| 베이스 | 필름 종류와 프로세스, 타깃, 스캐너 프로파일, 필름 베이스, 채널 범위 보정, 자동 밸런스, 자동 레벨, 중립 밸런스 |
| 톤 | 노출, 대비, 농도, 하이라이트, 섀도, 화이트, 블랙, 톤 커브 |
| 색 | 온도, 색조, 색 깊이, 비브런스, 채도, 믹서, 그레이딩, 캘리브레이션, 흑백 토닝, 필름 에뮬레이션 |
| 디테일 | 그레인, 선명도, 할레이션, 클래리티, 비네트, 노이즈 감소, GrainMend 강도, 국소 보정 |
| 지오메트리 | 크롭, 회전, 가로·세로 뒤집기, 수평 맞추기, 크롭 비율, 변환 |

전체 붙여넣기나 사용자 프리셋은 대상의 현상 설정을 통째로 바꿉니다. 범위를 지정한 붙여넣기는 선택한 그룹의 유효 값만 바꾸고 나머지는 둡니다. 룩의 일부만 붙여넣을 때는 룩의 톤, 색, 질감 기여분을 값에 녹이고 룩 참조를 지워서 옛 룩이 다시 더해지지 않게 합니다. 같은 설정을 반복해서 붙여넣어도 상태는 같습니다. 메뉴, 단축키, 패널이 같은 붙여넣기 범위를 씁니다.

붙여넣기와 사용자 프리셋은 선택한 모든 사진에 적용됩니다. 실행 취소와 다시 실행 한 번이 선택 전체를 덮고, Windows는 어느 것이든 바꾸기 전에 모든 대상을 검증합니다. 썸네일과 활성 미리보기는 새 설정으로 새로 고쳐집니다. 원본 파일, 평점, 원본에 묶인 결함 편집은 복사하지 않습니다.

사용자 프리셋은 현상 상태 전체와 지오메트리를 저장합니다. 지오메트리가 없는 옛 프리셋이나 붙여넣기 범위에는 호환을 위해 지오메트리가 들어갑니다. 이름을 비워 두면 비어 있는 첫 번호 이름이 붙고, 저장해도 이름이 같다는 이유로 기존 프리셋을 덮어쓰지 않습니다.

## 스캐너 플러그인 없이

시작할 때 스캐너 플러그인이 설치되어 있지 않아도 공용 라이브러리·현상 사이드바에 플러그인 없음 안내, 다시 검색 컨트롤, 시뮬레이터 블록이 자동으로 나타나지 않습니다. 이미지 가져오기는 그대로 쓸 수 있습니다.

스캐너 다시 검색과 시뮬레이터 지원은 그대로 있습니다. 스캐너 진입점과 설정에서 쓸 수 있고, 플러그인을 설치하거나 시뮬레이터를 직접 켜면 기존 스캐너 UI가 나타납니다.

## 인화 레이아웃과 출력 수

인화에는 레이아웃이 여덟 가지 있습니다. 단일 이미지, 콘택트 시트, 사진 패키지, 사용자 패키지, 시아노타입, 유리 건판, 젤라틴 실버, 워터마크입니다. 단일 이미지 계열 다섯 가지는 선택한 사진마다 완성된 페이지를 세로 스크롤로 보여 줍니다. 워터마크는 독립된 레이아웃이고 나머지는 기존 컨트롤을 유지합니다.

내보내기와 빠른 내보내기는 완성된 페이지를 셉니다. 예를 들어 사진 39장의 6 × 7 콘택트 시트는 합성한 파일 하나, 4장짜리 사진 패키지는 10페이지, 기본 사용자 패키지는 한 페이지가 되고, 단일 이미지 계열 다섯 가지는 제한된 배치로 39개 파일이 됩니다.

패키지 미리보기는 있는 썸네일, 현상 이미지, RAW 미리보기를 재사용하고 아무것도 없을 때만 작은 빠른 미리보기를 만듭니다. 최종 내보내기는 원본 메타데이터로 배치마다 위치를 계산하고, 그 배치에 필요한 픽셀만 현상하며, 원본을 2~4개씩 동시에 준비하고, 마지막 페이지 렌더링까지 Core Image 그래프를 이어 둡니다. 공유 렌더 컨텍스트와 페이지당 512MiB의 원본 래스터 예산이 한 페이지가 끝없는 전체 해상도 중간 이미지로 불어나는 것을 막습니다.

## 인화 워터마크

레이아웃 종류 메뉴에서 젤라틴 실버 다음의 워터마크를 고릅니다. 사진을 자르지 않고 각 사진 아래에 테두리를 더하며, 같은 높이의 위쪽 테두리도 더할 수 있습니다. 사진 용지 크기는 사진과 테두리를 합친 크기를 따릅니다.

아래쪽 테두리 왼쪽에는 카메라와 그 아래 렌즈가 나옵니다. 오른쪽에는 로고, 그 옆에 초점 거리, 조리개, 셔터 속도, ISO가 나오고 그 아래에 날짜가 나옵니다. 로고를 켜면 하나를 더할 수 있고 파일을 고르지 않으면 negaflow 로고를 씁니다. negaflow는 제조사 로고를 싣지 않으므로 JPEG, PNG 같은 이미지 파일을 직접 고르세요. 설정과 템플릿에는 파일 경로만 저장합니다. 그릴 때 파일을 확인하고 크기와 수정 시각이 같으면 캐시된 로고를 재사용합니다. 파일을 옮기거나 지웠으면 로고만 빠지고, 아래의 상태 점과 진단 보고서에 기록됩니다. 비어 있는 카메라, 렌즈, 노출, 날짜 칸은 비어 있는 채로 두며 입력한 텍스트만 그립니다. 텍스트가 길거나 세로 사진처럼 테두리가 좁으면 테두리 안의 모든 항목이 같은 비율로 줄어서 텍스트가 사진 밖으로 나가거나 잘리지 않습니다.

테두리는 흰색, 검정, 사진을 흐리게 한 배경 중에서 고릅니다. 흰색에서는 글자가 검정이고 둘째 줄은 회색입니다. 검정에서는 모든 글자가 흰색입니다. 흐린 배경에서는 글자와 히스토그램의 색을 검정이나 흰색으로 고릅니다. 히스토그램은 점으로 된 막대로 그립니다. 이름과 히스토그램의 위치 규칙은 [인화 레이아웃과 C-print 미리보기](../reference/C_PRINT.md)에 있습니다. 흐린 배경과 히스토그램은 쓸 수 있는 필름스트립 썸네일이 있으면 재사용하고, 없으면 축소한 사진 이미지를 씁니다. 템플릿은 용지 색과 텍스트, 로고 경로를 포함한 모든 워터마크 설정을 저장합니다.

## 인화 프로파일

인화의 ICC 컨트롤은 역할이 서로 다릅니다.

| 설정 | 화면 미리보기 | 인화 내보내기 | 현상 미리보기 |
|---|---|---|---|
| 프린터 출력 프로파일 | 인화 결과를 보여 줌 | 완성된 페이지에 적용 | 적용 안 함 |
| C-print 프루프 프로파일 | 랩과 용지 공정을 소프트 프루프 | 전달 파일에 굽지 않음 | 적용 안 함 |
| 일반 소프트 프루프 | 설정한 표시 범위에서 사용 | 표시 보조일 뿐 | 자체 설정을 따름 |

프린터 출력 프로파일은 원본 하나를 복제하기 전에 그 원본에 적용하지 않습니다. 콘택트 시트, 사진 패키지, 사용자 패키지를 먼저 구성한 뒤 페이지 전체에 프로파일을 한 번 적용합니다. 그래서 한 원본을 반복해 놓은 배치와 여러 원본을 섞은 배치가 같은 출력 변환을 받습니다.

C-print 프루프 프로파일은 랩이 제공한 공정 미리보기입니다. 출력 프로파일로 조용히 대체되는 일은 없습니다. 프로파일 요건과 정확도의 한계는 [인화 레이아웃과 C-print 미리보기](../reference/C_PRINT.md)에 있습니다.

## DNG 내보내기

DNG는 현상한 그림을 sRGB, Display P3, Adobe RGB 중 고른 출력 색 공간의 비압축 16비트 선형 RGB 파일(`PhotometricInterpretation = LinearRaw`)로 씁니다. 톤과 색은 이미 반영되어 있어서 다른 앱은 출력 기준 파일로 읽습니다. 파일에는 TIFF와 같은 메타데이터 정책에 따라 저작권, 스캐너, 소프트웨어, 날짜, 필름 메모가 들어갑니다. 원본 카메라의 EXIF, IPTC, GPS는 복사하지 않습니다. 픽셀당 6바이트라서 24메가픽셀 프레임은 약 144MB입니다.

DNG는 압축하지 않은 원본(TIFF, 카메라 RAW, DNG)에서 쓸 수 있습니다. JPEG, PNG, HEIC 원본은 DNG로 내보낼 수 없습니다. 현상, `PRINT` 타깃, 인화 레이아웃이 모두 DNG를 지원합니다. 인화 DNG는 합성한 페이지를 ColorMatrix가 붙은 표준 RGB로 기록하고 프린터 ICC 변환은 건너뜁니다. DNG 내보내기는 내보내기에서 고른 폴더를 쓰고 `.dng` 확장자를 유지합니다. 최종 파일이 게시되고 검증되어야 완료입니다. exiftool과 Apple의 이미지 디코더가 파일을 읽습니다. 다른 RAW 편집기에서의 렌더링은 측정하지 않았습니다.

## 원본을 바꾸는 동작

| 동작 | Finder의 원본 | 카탈로그와 편집 |
|---|---|---|
| 폴더 `×` | 유지 | 폴더와 사진이 라이브러리에서 제거됨 |
| 다른 폴더로 끌기 | 이동, 이름이 겹치면 새 이름 선택 | 새 위치로 다시 연결 |
| Finder에서 이동·이름 변경 | 사용자가 한 변경 유지 | 북마크로 자동 재연결 |
| 폴더 현상 적용 | 유지 | 프로세스와 타깃을 갱신하고 다시 렌더링 |
| 프리셋, 복사·붙여넣기 | 유지 | 선택한 현상·지오메트리 값 갱신 |
| 인화 내보내기 | 유지 | 별도의 출력 파일과 렌더 기록 생성 |

## 대형 라이브러리 점검

사진이 256장을 넘으면 선택이 바뀔 때마다 필름스트립이 길게 자동 스크롤하지 않습니다. 보이는 카드와 폴더 행은 필요할 때 만듭니다.

2,000프레임 부하 점검은 24MP, 40MP, 60MP, 3200 DPI, 4800 DPI의 픽셀 픽스처를 폴더 50개에 가져옵니다. 모든 프로세스와 타깃을 섞고 컬러 네거티브를 절반 이상으로 두며 크롭과 방향 변경을 적용한 뒤 현상, 썸네일, 카탈로그 왕복을 검증합니다. `negaflow-mac/`에서 실행합니다.

```bash
bash scripts/performance/run-virtual-library-stress.sh
```

부하 점검은 직접 켜는 방식이라서 일반 `swift test` 실행에서는 건너뜁니다.

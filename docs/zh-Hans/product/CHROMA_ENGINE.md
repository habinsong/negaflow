# Chroma Engine

[文档首页](../README.md)

Chroma Engine 负责胶片的反相和显影。代码位于 `Chromabase` 模块。应用和 CLI 使用同一个模块，所以相同的输入会经过相同顺序的步骤。

| 概览 | 内容 |
|---|---|
| 默认显影 | `MAIN`，自动平衡 ON |
| 片基 | 自动测量、吸管、直接输入 RGB |
| 内部色彩 | 32 位浮点线性色彩空间 |
| 自动功能 | 自动平衡 ON |
| 输出色彩空间 | sRGB、Display P3、Adobe RGB、自定义 RGB ICC |

> [!IMPORTANT]
> 默认是 `MAIN`，自动平衡为 ON。开关是目标标题右侧的小胶囊按钮，只在彩色和黑白负片的 MAIN（含 PRINT）和 CS 下显示。它依据当前照片调整颜色和亮度，OFF 时跳过这一步。自动色调、自动白平衡、自动色阶和自动颜色是独立功能，默认 OFF。

## 优先遵守的原则

1. 如果能测量片基，测量值优先于按名称选出的默认值。
2. 胶片特性、扫描光源、扫描仪风格和场景自动校正彼此分开。
3. 自动色调、自动白平衡等功能只在你运行时才启用。
4. 相同的源文件、编辑值和配置文件包，会经过相同顺序的步骤。
5. 合成测试和真实设备验证，不会当作同等的证据。

## 步骤顺序

工作图像在 32 位浮点线性色彩空间中处理。只有需要伽马的运算在固定的步骤转换，面向屏幕或文件格式的编码放在最后。

1. 读取文件并校正方向。
2. 线性输入（RAW 用相机 RGB）。
3. 胶片类型：正片进入正片处理，负片先测量片基。
4. 光学密度与反相，然后是自动平衡 ON/OFF，再是 RAW 的相机矩阵。
5. 显影目标与配置文件。
6. 影调、色彩与局部调整。
7. 细节与效果。
8. 显示或输出色彩空间。

`CIContext` 不会每次渲染都重建，而是按显示、分析、导出这三种用途分别复用。预览只计算所需的尺寸和最新的编辑版本，导出则按源尺寸重新渲染。

- [CIContext](https://developer.apple.com/documentation/coreimage/cicontext)

## 片基

### 为什么要测量

负片未曝光的部分，是片基、显影和扫描光源合在一起的参照点，彩色负片的橙色底也在其中。片基取错，之后所有的密度和通道关系都会出错。Kodak 的 Portra 400 资料也把最小密度、特性曲线和染料光谱密度分开记录。

- [Kodak Professional Portra 400 technical data](https://www.kodakprofessional.com/sites/default/files/wysiwyg/pro/resources/e4050_portra_400.pdf)

### 自动测量

`FilmBaseEstimator` 评估整个画幅中亮像素的空间分布，来识别未曝光的片基。

- 胶片像素不可能比未曝光的片基更亮。
- 亮得多的东西可能是背光、片孔或胶片之外的部分。
- 真正的片基往往沿画幅边缘形成一条宽带。
- 一张片夹上有多条胶片时，分开的区域可以一起读取。
- 片夹与胶片混在一起的边界，其可信度低于内部。

先在缩小的分析图像上求出亮度分布，把相连的区域归为一组，再去掉位于胶片之外的候选。多条胶片都通过条件时，一起计算。结果还会记录选用了哪种方法以及置信度。

### 选择方法

| 模式 | 行为 |
|---|---|
| `Manual` | 把你输入的 RGB 当作 Dmin。用吸管成功取到的值也归入这里。 |
| `Film` | 把测量值当作 Dmin，所选胶片主要提供 `dmaxNorm`。只有测量失败时，才使用胶片和光源的默认值。 |
| `Auto` | 使用空间分析，失败时退回基于边缘的方法。 |

没有手动值或胶片 ID 有误时，会转入下一个安全的方法。场景里最亮的物体绝不会被直接当作片基。

## 光学密度与反相

密度由线性透射率 `T` 和各通道的片基 `Dmin` 得出：

```math
D = \log_{10}\left(\frac{D_{\min}}{T}\right)
```

`D = 0` 表示输入等于未曝光的片基。片孔或背光处可能为负。这些值保持有限，不会当场被截断。

### 胶片类型数据

当前的表里有 27 个胶片名称，涵盖彩色负片、黑白和电影负片。这些数据用于：

- 无法测量片基时的 Dmin 默认值
- 相对于胶片类型的固定密度系数

部分数值是读取公开资料中的曲线近似得到的，部分是保守设定的。27 个名称并不等于 27 个经过验证的色彩配置文件，测量到片基后，以测量为准。

### MAIN/PRINT 与 CS

自动平衡 ON 时，每个通道取场景中最密的 0.2% 百分位，范围限制为 1.8D，随后应用 `shoulder-print-response-v4` 曲线和低饱和场景的自然饱和度。OFF 使用同一条曲线和固定的标称范围（彩色 1.55D，黑白 2.17D）。对于彩色负片，OFF 还会乘上针对扫描仪和胶片的通道范围校准，该值取自同一卷至少三帧的测量。

ON 会随场景内容同时改变亮度和颜色。两种模式都不能证明胶片色彩的实测准确性。公式、1.8D 限制和 RAW 的顺序见：

[负片反转响应](../reference/PRINT_RESPONSE.md)

## 三种配置文件

| 种类 | 回答的问题 | 数值 |
|---|---|---|
| 胶片类型 | 胶片的片基和密度范围是多少 | Dmin/Dmax、胶片类型 |
| 光源 | 扫描光源对每个通道有什么影响 | 通道增益、由片基驱动的校正 |
| 扫描仪目标 | 结果有怎样的影调和色彩风格 | 为本项目拍摄的扫描的相对统计 |

把三者分开，可以避免让一个胶片名称同时代表乳剂特性、光源颜色和冲印店的输出风格。有真实片基时，测量优先于光源默认值。扫描仪的统计不会直接当作场景的绝对色彩矩阵。

数据在[胶片配置文件](FILM_PROFILES.md)中说明。

## 显影目标

### `MAIN`

默认目标，自动平衡为 ON。开关的说明在本页开头。

### `PRINT`

工作图像与 `MAIN` 相同。有效的 RGB 打印机 ICC 在导出的最后应用一次。配置文件缺失或无效时直接失败，不会退回 sRGB 或任意的纸张数值。

### `HS`, `SP`

在反相之后应用的固定渲染。它不从照片里读取任何东西，所以同一个像素在每张照片里都得到相同的结果。逐帧的曝光和色彩由反相以及右侧的自动色调、自动白平衡、自动色阶和自动颜色按钮负责。

渲染由亮度影调曲线、随亮度变化的饱和度增益组成，`HS` 还有灰轴的轻微倾斜。所有曲线都是单调三次曲线，节点处不会出现折弯。

- `SP` 来自同一卷的四帧，分别用真实的 SP-3000 和本项目自己的扫描仪扫描，并逐像素对齐。影调曲线有四分之一的权重来自 185 帧 SP-3000 的百分位。在这四帧上，相对 SP-3000 扫描的 CIEDE2000 中位数从 `MAIN` 的约 7.4 降到 3.9。有一帧较暗的照片几乎没有变化，因为冲印店在那里逐帧去除了红色的阴影偏色，固定渲染做不到。
- `HS` 没有像素配对。它从 `SP` 出发，再加上两台机器在三卷胶片与卷名相符的素材上的中位数差异：中间调略暗，白色略高，有色像素的饱和度为 0.88 倍，亮部的灰色偏绿（a* 约 −1 到 −4）。
- `HS` 会对亮度通道锐化。半径在该机器 35 mm 输出（长边 3089 px）上为 0.9 px，并随分辨率缩放，所以预览和导出一致。强度没有测量过。

选用内置配置文件时，仍会加上 `scannerSignature`，即两台机器上卷名和图像数量相符的卷之间的相对差异。目前所有配置文件都是 `realOnly`。

- 只有卷名和图像数量足够接近时，才计算相对差异。
- 方向翻转的数值不应用。
- 黑白会丢弃色彩分量。
- 任何文件或清单的 SHA-256 不符，整个配置文件包都会被拒绝。

### `F135`, `HR`

本项目没有来自 Pakon F-135 或 Kodak HR-500 的参考扫描，所以这两个目标都没有与对应的机器核对过。两者都从测得的 `SP` 渲染出发，接上按 `SP` 中间调对齐的 Kodak Endura Premier 相纸（E-4070 数据表）曲线。比中灰暗 1 档往上，两者用同一条曲线，区别在暗部。

- `F135` 到 −2 档为止跟随相纸曲线。从 −3 档往下比 `SP` 低 0.9 档，这是相纸趾部比 `SP` 压得最深的量。黑色比 `SP` 更深，但每一档暗部仍能分开，这一段的局部反差不低于 `SP` 的 91%。
- `HR` 在 −4 档以下沿用测得的 `SP` 暗部。−3 档和 −2 档略微压低，让曲线升向相纸中间调时反差不会下陷。暗部比 `F135` 最多亮 5.4 L*，饱和度为 0.92 倍。

要核对它们，需要 `SP` 曾有的东西：在真实机器上扫描的同一批负片。

### `EXPIRED`

面向旧胶片的修复目标。它不做整体去饱和，也不拉伸范围，只停留在当前证据所支持的有限校正内。

### `CS`

`CS`（Custom）收录 18 种色彩风格，分三组：Emulsion、Reversal、Dye Transfer、Skip Bleach、Plate Glass、Amber Glass、Ultramarine、Terracotta、Celadon、Nacre、Dichroic（11 个）；Wetzlar、Classic、Studio、Rochester（4 个）；Slide Show、Cinema、Point & Shoot（3 个）。

Custom 目标使用带自动平衡的 `MAIN` 反相，然后应用 custom-3 的影调、密度和色度响应。它不使用扫描仪配置文件。CLI 接受同样的 ID，例如 `--target classic`。

## 数码来源的胶片风格

左侧的胶片标签页提供正片和彩色负片的胶片。对扫描件来说，这只是一次色彩变换，因为扫描的像素里已经带有胶片自身的宽容度、密度响应、散射和颗粒。

数码照片没有这些。测量显示了仅做色彩变换的结果：在相机渲染过的输入上，高光层次塌缩到 0.0031，约为平坦输入上相同层次的十四分之一，饱和度却上升了。结果看起来像数码滤镜。

所以标记为 `Digital Color` 或 `Digital B&W` 的源文件，会走一条单独的链，依次重做胶片所做的事：

1. 撤销相机的显示渲染，估计胶片会接收到的曝光。溢出的细节找不回来，所以这是合理的重建。
2. 在密度出现之前、图像仍是线性光时，加入散射和光晕。返回的光先照到红色层，形成偏红的光晕，只重新分配光，不增加能量。
3. 虚拟显影。特性曲线生成密度，DIR 耦合剂抑制相邻层，负片随后经过 RA-4 相纸。负片的低伽马和相纸的高伽马是两条独立的曲线，高光因此平缓过渡而不被截断。
4. 胶片的色彩特征，因为对比度已在第 3 步产生。
5. 随密度变化的颗粒，以及来自数据表 MTF 的边缘响应。

扫描来源绝不会进入这条链。切换只取决于来源标记，扫描路径保持不变。

曝光会按每种乳剂的宽容度重新缩放。反转片在中灰上方约一档处就会变白，所以把六档的数码场景原样推进去，高光细节会荡然无存。这种缩放保持每种胶片的对比度排序。

选定胶片后，颗粒和光晕就成了胶片的特性，所以纹理滑块设定的是它们的强度，而不是再叠加第二个独立的效果。

## 显影控件

| 分组 | 项目 |
|---|---|
| 影调 | 曝光、对比度、高光、阴影、白色色阶、黑色色阶、RGB 及各通道的点曲线 |
| 色彩 | 色温、色调、自然饱和度、饱和度、8 色 HSL、三区域颜色分级、通道校正、黑白转换与调色 |
| 细节与效果 | 锐化、清晰度、去朦胧、胶片颗粒、暗角、光晕、降噪 |
| 局部调整 | 径向、线性、多边形、画笔蒙版、减淡与加深 |

这些数值以分步的编辑历史保存。GrainMend 与普通的局部调整，用途和存储方式都不同。

### 自动校正

| 控件 | 行为 |
|---|---|
| 自动色调 | 指定曝光、对比度、密度、高光、阴影、白色色阶和黑色色阶。保留用户的色彩控件和曲线。 |
| 自动白平衡 | 根据接近中性的亮度带估计色温和色调。舍弃 RGB 通道被截断的样本，中性证据稀少或色调范围窄时减弱校正。 |
| 自动色阶 | 测量共同的亮度端点，对 RGB 应用相同的亮度增益。保持通道比例，而不是分别拉伸每个通道。 |
| 自动颜色 | 把残余偏色拟合到中性候选上。仅当拟合预测出独立的、未使用的亮度带时才使用通道斜率，否则使用增益。证据较弱的后备情形，校正更少。 |

自动色调会在渲染出的预览上检查第一个建议。如果它提出进一步改变曝光或白点，也会渲染该候选，只有当中间调、端点、色调范围和截断的得分有所改善时才采纳。这是有边界的校正，不是在寻找唯一理想的渲染。重复执行命令是重新指定设置而不是累加，重置自动色调时会保留用户的色彩控件。

分析使用线性 RGB 中按面积加权的平均值，并限制长边。色调和白平衡使用 sRGB 预览，所以截断指预览通道的截断，不是传感器饱和。这些估计无法把所有被摄体颜色与光源偏色区分开，也不能证明胶片色彩的实测准确性。MAIN/CS 的自动平衡及其低饱和场景的自然饱和度属于反相阶段。

## 色彩管理

输入带有有效 ICC 时，读取该色彩空间。内部运算在固定的线性工作空间中进行，向输出空间的转换发生在显示、软打样和导出时。

主要支持的输出：

- sRGB
- Display P3
- Adobe RGB
- 用户选定的 RGB 打印机或输出 ICC

导出开始时，会固定打印机配置文件的名称、字节数和 SHA-256。如果文件在渲染期间发生变化，运行会停止。

不声称当前的 Core Image 与 ColorSync 路径能在所有 macOS 版本上逐位一致地给出渲染意图和黑场补偿。要提供这种保证，需要先有单独的 ColorSync 缓冲路径，以及针对大型 16 位图像的内存检查。

## 输出编码

格式设置在色彩管线之外，但决定交付的文件里保留什么。

除非编码器超过其子采样阈值，JPEG 会以低于亮度的分辨率存储色彩。低于该阈值时，色度在水平和垂直方向都减半，饱和的边缘会变柔，而亮度细节保持不变。因此质量在 95% 及以上时不做色度子采样，更低的设置保留所选的值，因为选择它们就意味着要求更小的文件。PNG 和 TIFF 是无损的，从不子采样。它们唯一的质量控制是位深，每通道 8 位或 16 位，抖动只在 8 位时应用，用来掩盖量化产生的色带。

## 性能与安全

- `CIContext` 按用途复用。
- 调整使用较低分辨率的预览，导出则从源文件重建。
- 耗时较长的任务在应用结果之前，会立即重新检查画幅 ID、编辑版本和会话。
- 内存不足时，丢弃缩略图和预览之类的缓存。
- 原始文件和编辑历史与缓存分开保存。

## 验证的层级

1. 公式测试：曲线的单调性、锚点、反函数
2. 合成图像：已知的输入与输出、截断、方向、色彩空间
3. 合成 IT8：264 个色块的数学往返
4. 真实拍摄统计：`realOnly` 配置文件
5. REAL/TARGET 配对：带有单独验证资料的设备质量关卡
6. 真实硬件：实际的扫描仪、胶片、显示器和印相

合成 IT8 的结果再好，也不能证明在真实负片上的绝对准确度。评判扫描仪配置文件质量，按[扫描仪配置文件质量判定](../reference/PROFILE_QUALITY_GATE.md)和[IT8 色彩检验](../reference/IT8_COLOR_VALIDATION.md)进行。

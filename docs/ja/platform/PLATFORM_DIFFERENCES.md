# macOS 版と Windows 版の違い

[ドキュメントホーム](../README.md)

negaflow は二つあります。macOS 版は Core Image の上の Swift と SwiftUI、Windows 版は
Direct3D の上の C++ エンジンに C# と WinUI 3 です。二つはソースコードを共有していません。

このページでは、実際に何が同じで、何が違って見えて、片方にしかないものが何かを書きます。

## なぜ二つなのか

一つのコードで両方を作るには、ツールキットを一つ選んで、その結果を両方の環境で受け入れる
ことになります。メニューの位置がずれ、ファイルダイアログの挙動が妙になり、色が変換層を
もう一段通り、ウィンドウがどうしてもそのOSのアプリらしくなりません。

それぞれのプラットフォームの流儀で書くと、手間はおよそ二倍になります。機能を一つ足すたびに
二度作り、二度確かめます。その代わり、どちらの版も使い慣れた環境で期待どおりに動きます。

## 同じところ

出てくる絵です。同じスキャンを渡せば同じ写真になります。

言葉だけの話ではありません。macOS 版が書き出した基準画像がリポジトリの
`docs/verification/macos-golden` に入っています。Windows のエンジンテストがこれを読み戻して
画素値を比べます。Windows 側を直していて macOS の結果から外れると、テストが落ちます。

次も同じです。

- フィルムベースの測定と反転
- すべての現像ターゲット: `MAIN`、`PRINT`、`HS`、`SP`、`F135`、`HR`、`EXPIRED`
- トーン、カーブ、HSL、カラーグレーディング、モノクロトーニング
- GrainMend の検出と修復、赤外線の経路を含む
- プリントのレイアウトとページ配置
- 書き出しのファイル名、EXIF の書き込み、メタデータの扱い
- カタログの形式。片方で作ったライブラリをもう片方で読めます

## 違うところ

### カラーマネジメント

macOS は ColorSync、Windows は ICM を使います。どちらも同じ ICC プロファイルを受け取り、
丸め誤差の範囲で同じ値を出します。静かにずれやすい部分なので、基準画像の比較がここを見ています。

### グラフィックス

macOS は現像の流れを Core Image で回します。Windows は Direct3D のコンピュートシェーダーで
回し、GPU が使えない機械では CPU に切り替えます。

速さはプラットフォームより機械次第です。Apple Silicon の Mac でも独立GPUを積んだ PC でも、
35mm のスキャン一枚なら待つことはありません。

### ファイルの場所

| | macOS | Windows |
|---|---|---|
| アプリ | `/Applications/negaflow.app` | `%LOCALAPPDATA%\Negaflow\App` |
| ライブラリと設定 | `~/Library/Application Support/negaflow` | `%LOCALAPPDATA%\Negaflow` |
| ログ | コンソールとアプリサポートフォルダー | `%LOCALAPPDATA%\Negaflow\Logs` |

### インストールと削除

macOS は PKG でアプリを `/Applications` に入れます。消すときは他の Mac アプリと同じく
ゴミ箱に入れるだけです。

Windows は管理者権限なしでユーザーフォルダーにインストールします。削除はスタートメニューの
`negaflow の削除`か設定から行い、アプリフォルダー、スタートメニューの項目、パッケージ登録を
まとめて消します。

### コマンドライン

macOS には `negaflow` という CLI があります。スキャナーを探し、ファイルを現像し、GrainMend を
かけ、性能を測るところまでできます。実際に使うための道具です。

Windows には `negaflow-cli.exe` があります。ファイル一つをエンジンがどう扱うか見る小さな道具で、
サブコマンドではなくフラグを取ります。日常の作業ではなく診断のためのものです。

### 署名

どちらも有料の開発者証明書で署名していないため、初回起動で警告が出ます。macOS は
プライバシーとセキュリティで「このまま開く」、Windows は SmartScreen で詳細情報を押してから
実行を選びます。

## スキャナー

スキャナープラグインは別の GPL プロジェクト
[`negaflow-scanner-sane`](https://github.com/habinsong/negaflow-scanner-sane) で、こちらも
両方の環境にあります。プラグインは別プロセスで動き JSON でやり取りするので、negaflow 本体には
どちらの環境でも SANE のコードが入りません。

Windows では、プラグインが Windows のもともとのスキャナードライバー経路を使います。何も
置き換えないので、同じ機械で VueScan や SilverFast をそのまま使えます。

## 二つを揃える方法

機能はまず macOS に入り、Windows は文書に書いた仕様ではなく macOS の実際の動きを見て作ります。
出力を測れる部分は、macOS の基準画像が Windows 側の正否を決めます。

食い違ったら macOS が正解で、Windows がバグです。

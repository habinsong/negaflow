# Chroma Engine

[ドキュメントホーム](../README.md)

Chroma Engine は、フィルムを反転して現像します。コードは `Chromabase` モジュールにあります。アプリと CLI は同じモジュールを使うので、同じ入力は同じ順序の段階を通ります。

| ひと目で | 内容 |
|---|---|
| 既定の現像 | `MAIN`、自動バランス ON |
| フィルムベース | 自動測定、スポイト、RGB の直接入力 |
| 内部の色 | 32bit 浮動小数点のリニア色空間 |
| 自動機能 | 自動バランス ON |
| 出力の色空間 | sRGB、Display P3、Adobe RGB、独自の RGB ICC |

> [!IMPORTANT]
> 初期値は `MAIN` と自動バランス ON です。スイッチは、ターゲット見出しの右にある小さなピル型です。カラー・白黒ネガの MAIN(PRINT を含む)と CS でのみ表示されます。現在の写真に合わせて色と明るさを整え、オフにするとこの処理を省きます。自動トーン、自動ホワイトバランス、自動レベル補正、自動カラー補正は別の機能で、初期値はオフです。

## 最初に守ること

1. フィルムベースを測れるときは、名前で選んだ既定値より測定が優先されます。
2. フィルムの性質、スキャン光源、スキャナーのスタイル、シーンの自動補正は分けて扱います。
3. 自動トーンや自動ホワイトバランスなどの機能は、自分で実行したときだけ有効になります。
4. 同じ元ファイル、編集値、プロファイルの組は、同じ順序の段階を通ります。
5. 合成テストと実機での検証を、同じ証拠として並べません。

## 段階の順序

作業用の画像は、32bit 浮動小数点のリニア色空間で処理します。ガンマが必要な演算だけが決まった段階で変換し、画面やファイル形式のためのエンコードは最後に行います。

1. ファイルを読み、向きを直す。
2. リニア入力(RAW ではカメラ RGB)。
3. フィルム種別: ポジはポジの処理へ、ネガはベースを測る。
4. 光学濃度と反転、続いて自動バランス ON/OFF、そのあと RAW のカメラ行列。
5. 現像ターゲットとプロファイル。
6. トーン、色、部分補正。
7. ディテールとエフェクト。
8. 表示用または出力の色空間。

`CIContext` はレンダリングごとに作り直さず、表示、解析、書き出しという目的ごとに再利用します。プレビューは必要なサイズと最新の編集バージョンだけを計算し、書き出しは元のサイズで描画し直します。

Apple の Core Image のドキュメント:

- [CIImage](https://developer.apple.com/documentation/coreimage/ciimage)
- [CIContext](https://developer.apple.com/documentation/coreimage/cicontext)
- [workingColorSpace](https://developer.apple.com/documentation/coreimage/cicontext/workingcolorspace)
- [Core Image performance guide](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/CoreImaging/ci_performance/ci_performance.html)

## フィルムベース

### 測る理由

ネガの未露光の部分は、フィルム、現像、スキャン光源がひとつになった基準点です。カラーネガのオレンジマスクもその中にあります。ベースを誤ると、その後のすべての濃度とチャンネルの関係が狂います。Kodak の Portra 400 の資料も、最小濃度、特性曲線、染料の分光濃度を別々に記しています。

- [Kodak Professional Portra 400 technical data](https://www.kodakprofessional.com/sites/default/files/wysiwyg/pro/resources/e4050_portra_400.pdf)

### 自動測定

`FilmBaseEstimator` は、フレーム全体で明るいピクセルの空間的な分布を評価して、未露光のベースを見つけます。

- フィルムのピクセルが未露光のベースより明るくなることはありません。
- それよりずっと明るいものは、バックライト、パーフォレーション、フィルムの外側かもしれません。
- 本物のベースは、フレームの端に沿って広い帯になりやすい傾向があります。
- 1枚のシートに複数のストリップがあるときは、離れた領域をまとめて読めます。
- ホルダーとフィルムが混ざる境界は、内側よりも信頼しません。

縮小した解析画像で明るさの分布を求め、つながった領域をまとめてから、フィルムの外にある候補を除きます。条件に通ったストリップが複数あれば、まとめて計算します。結果には、どの方法を選んだかと確信度も記録されます。

### 方法の選び方

| モード | 動作 |
|---|---|
| `Manual` | 入力した RGB を Dmin として使います。スポイトで取れた値もここに入ります。 |
| `Film` | 測定値を Dmin として使い、選んだフィルムは主に `dmaxNorm` を与えます。測定に失敗したときだけ、フィルムと光源の既定値が入ります。 |
| `Auto` | 空間解析を使い、失敗するとエッジに基づく方法に戻ります。 |

手動の値がない、またはフィルム ID が間違っているときは、次の安全な方法に移ります。シーンでもっとも明るいものを、そのままフィルムベースとすることはありません。

## 光学濃度と反転

濃度は、リニアな透過率 `T` とチャンネルごとのベース `Dmin` から求めます。

```math
D = \log_{10}\left(\frac{D_{\min}}{T}\right)
```

`D = 0` は、入力が未露光のベースと等しいことを意味します。パーフォレーションやバックライトは負になりえます。その値は有限のまま保ち、その場で切り捨てません。

### フィルム種別のデータ

現在の表には、カラーネガ、白黒、映画用ネガにわたるフィルム名が27個あります。このデータは次のために使います。

- ベースを測れないときの Dmin の既定値
- フィルムに対して相対的な、固定の濃度係数

一部の値は公開資料のカーブを読んで近似し、一部は控えめに決めました。名前27個が検証済みの色プロファイル27個ではなく、ベースを測れたなら測定が優先されます。

### MAIN/PRINT と CS

自動バランス ON では、チャンネルごとにシーンでもっとも濃い0.2%パーセンタイルを使い、範囲を1.8Dに制限したうえで、`shoulder-print-response-v4` カーブと、彩度の低いシーン向けのバイブランスを適用します。OFF は同じカーブに固定の公称範囲(カラー1.55D、白黒2.17D)を使います。OFF はカラーネガで、同じロールの3フレーム以上から決めたスキャナーとフィルムのチャンネル範囲補正も掛けます。

ON は、シーンの内容によって明るさと色の両方が変わることがあります。どちらのモードも、測定したフィルムの色の正確さを保証しません。式、1.8Dの制限、RAW の順序は次にあります。

[ネガ反転応答](../reference/PRINT_RESPONSE.md)

## 3種類のプロファイル

| 種類 | 答える問い | 値 |
|---|---|---|
| フィルム種別 | フィルムのベースと濃度範囲はどうか | Dmin/Dmax、フィルム種別 |
| 光源 | スキャン光源が各チャンネルにどう影響したか | チャンネルゲイン、ベースに基づく補正 |
| スキャナーターゲット | 結果のトーンと色のスタイルはどうか | このプロジェクトのために撮影したスキャンの相対統計 |

3つを分けておくと、フィルム名ひとつが、乳剤の性質、光源の色、ラボの出力スタイルを一度に代表してしまうことを避けられます。実際のベースがあれば、測定が光源の既定値より優先されます。スキャナーの統計は、シーンの絶対的な色行列としては使いません。

データは[フィルムプロファイル](FILM_PROFILES.md)で説明しています。

## 現像ターゲット

### `MAIN`

自動バランスがオンの、既定のターゲットです。スイッチについてはこの文書の冒頭に書きました。

### `PRINT`

作業用の画像は `MAIN` と同じです。有効な RGB プリンター ICC は、書き出しの最後に1回だけ適用します。プロファイルがない、または不正なときは、sRGB や任意の用紙の値で代用せず、失敗します。

### `HS`, `SP`

反転のあとに適用する固定のレンダリングです。写真から何も読み取らないので、同じピクセルはどの写真でも同じ結果になります。フレームごとの露出と色は、反転と、右側の自動トーン、自動ホワイトバランス、自動レベル補正、自動カラー補正のボタンが受け持ちます。

レンダリングは、輝度のトーンカーブ、明るさに応じた彩度ゲイン、そして `HS` ではグレー軸のわずかな傾きでできています。すべてのカーブは単調な3次カーブなので、節で折れ曲がりません。

- `SP` は、同じロールの4フレームを、実際の SP-3000 とこのプロジェクトのスキャナーでスキャンし、画素単位で合わせた資料から作りました。トーンカーブは、SP-3000 の185フレームのパーセンタイルから4分の1の重みを取っています。その4フレームで、SP-3000 のスキャンに対する CIEDE2000 の中央値は、`MAIN` の約7.4から3.9に下がります。暗いフレーム1枚はほとんど動きません。ラボがそこで赤いシャドウの色かぶりをフレームごとに取り除いており、固定のレンダリングにはそれができないからです。
- `HS` には画素ペアがありません。`SP` から出発し、フィルムとロールの名前が合う3ロールでの、2台の機械の中央値の差を足します。中間調がわずかに暗く、白がやや高く、色のついた画素は彩度0.88倍、明るい側のグレーは緑寄りになります(a* で約 −1〜−4)。
- `HS` は明るさチャンネルをシャープにします。半径は、機械の35mm出力(長辺3089px)で0.9pxで、解像度に比例して変わるので、プレビューと書き出しが一致します。強さは測っていません。

同梱のプロファイルを選ぶと、2台の機械で名前と画像数が合うロールの相対差である `scannerSignature` がさらに足されます。現在はすべてのプロファイルが `realOnly` です。

- 相対差は、ロール名と画像数が十分に近いときだけ計算します。
- 向きが逆転する値は適用しません。
- 白黒では色成分を捨てます。
- ファイルまたはマニフェストのどれかの SHA-256 が合わなければ、プロファイルのバンドル全体を拒否します。

### `F135`, `HR`

このプロジェクトには、Pakon F-135 や Kodak HR-500 で得た基準スキャンがないため、どちらのターゲットも、その機械とは照らし合わせていません。どちらも、測定した `SP` のレンダリングに、Kodak Endura Premier 印画紙(E-4070 のデータシート)の曲線を `SP` の中間調に合わせて付けたところから始まります。中間グレーより 1 段暗いところから上は同じ曲線で、違いはシャドウにあります。

- `F135` は −2 段まで印画紙の曲線に従います。−3 段から下は `SP` より 0.9 段低く置きます。印画紙のトウが `SP` より最も深く下げた量です。黒は `SP` より深くなりますが、段ごとの階調は分かれ、その区間の局所コントラストは `SP` の 91% 以上です。
- `HR` は −4 段より下で、測定した `SP` のシャドウをそのまま使います。−3 段と −2 段は少し下げ、印画紙の中間調へ上がる間にコントラストが落ち込まないようにしています。シャドウは `F135` より最大 5.4 L* 明るく、彩度は 0.92 倍です。

検証には、`SP` にあったもの、つまり実機で同じネガをスキャンした資料が必要です。

### `EXPIRED`

古いフィルムのための復元ターゲットです。一律の彩度低下や範囲の引き伸ばしはせず、現在の根拠が裏づける限定的な補正にとどまります。

### `CS`

`CS`(Custom)は、18のカラースタイルを3つのまとまりで持ちます。Emulsion、Reversal、Dye Transfer、Skip Bleach、Plate Glass、Amber Glass、Ultramarine、Terracotta、Celadon、Nacre、Dichroic(11個)、Wetzlar、Classic、Studio、Rochester(4個)、Slide Show、Cinema、Point & Shoot(3個)です。

Custom ターゲットは、自動バランス付きの `MAIN` の反転を使い、そのあとで custom-3 のトーン・濃度・彩度の応答を適用します。スキャナープロファイルは併用しません。CLI も同じ ID を受け取ります。例: `--target classic`。

## デジタル由来の画像のフィルムルック

左のフィルムタブには、ポジとカラーネガのフィルムがあります。スキャンでは、これは色の変換にすぎません。スキャンの画素に、フィルム固有の寛容度、濃度の応答、散乱、粒子がすでに含まれているからです。

デジタル写真には、そのどれもありません。色の変換だけを行うとどうなるかを測りました。カメラが描画した入力では、ハイライトの段差が0.0031まで潰れ、フラットな入力での同じ段差の約14分の1になったのに、彩度は上がりました。結果は、デジタルのフィルターのように見えます。

そこで、`Digital Color` または `Digital B&W` と印を付けた元ファイルは、フィルムがすることを順にやり直す、別のチェーンを通ります。

1. カメラの表示用のレンダリングを元に戻し、フィルムが受けたはずの露出を推定します。飛んだディテールは戻らないので、もっともらしい復元です。
2. 濃度ができる前、画像がまだリニアな光のうちに、散乱とハレーションを加えます。戻ってきた光はまず赤い層に当たり、赤みが強い光のにじみになります。エネルギーを加えず、光を再配分します。
3. 仮想の現像。特性曲線が濃度を作り、DIR カプラーが隣の層を抑え、ネガはそのあと RA-4 の印画紙を通ります。ネガの低いガンマと印画紙の高いガンマは別々の2つのカーブで、そのおかげでハイライトが飛ばずになめらかに肩を作ります。
4. フィルムの色の署名。コントラストはすでに3の段階で出ているからです。
5. 濃度に従う粒子と、データシートの MTF から得たエッジの応答。

スキャンの元ファイルがこのチェーンに入ることはありません。切り替えは元ファイルのフラグだけで、スキャンの経路は変わりません。

露出は、乳剤ごとの寛容度に合わせて取り直します。リバーサルフィルムは、中間のグレーの約1段上で白になるので、6段のデジタルシーンをそのまま押し込むと、ハイライトのディテールがまったく残りません。この取り直しは、フィルムごとのコントラストの順位を保ちます。

フィルムを選ぶと、粒子とハレーションがフィルムの性質になるので、テクスチャのスライダーは、2つ目の別のエフェクトを足すのではなく、その強さを決めます。

## 現像のコントロール

| グループ | 項目 |
|---|---|
| トーン | 露出、コントラスト、ハイライト、シャドウ、白レベル、黒レベル、RGB とチャンネルごとのポイントカーブ |
| 色 | 色温度、色かぶり補正、自然な彩度、彩度、8色の HSL、3領域のカラーグレーディング、チャンネル補正、白黒変換とトーニング |
| ディテールとエフェクト | シャープネス、明瞭度、かすみの除去、フィルム粒子、周辺光量、ハレーション、ノイズ軽減 |
| 部分補正 | 円形、線形、多角形、ブラシのマスク、覆い焼きと焼き込み |

これらの値は、段階ごとの編集履歴として保存されます。GrainMend と通常の部分補正は、目的も保存の方法も異なります。

### 自動補正

| コントロール | 動作 |
|---|---|
| 自動トーン | 露出、コントラスト、濃度、ハイライト、シャドウ、白レベル、黒レベルを割り当てます。ユーザーの色のコントロールとカーブは保ちます。 |
| 自動ホワイトバランス | ニュートラルに近い輝度の帯から色温度と色かぶり補正を推定します。RGB のチャンネルが飛んだサンプルは除き、ニュートラルの根拠が少ない、またはトーンの範囲が狭いときは補正を弱めます。 |
| 自動レベル補正 | 共通する輝度の端点を測り、RGB に同じ輝度ゲインを適用します。チャンネルごとに別々に引き伸ばさず、チャンネルの比を保ちます。 |
| 自動カラー補正 | 残った色かぶりをニュートラルの候補に当てはめます。当てはめが、未使用の別の輝度の帯を予測するときだけチャンネルの傾きを使い、それ以外はゲインを使います。弱い代替の根拠には、補正を控えめにします。 |

自動トーンは、最初の提案をレンダリングしたプレビューで確かめます。さらに露出やホワイトポイントを変える提案が出たら、その候補もレンダリングし、中間調、端点、トーンの範囲、クリップのスコアが良くなるときだけ受け入れます。これは限度のある補正で、唯一の理想的な描画を探すものではありません。コマンドを繰り返しても、設定は積み重ならず、割り当て直されます。自動トーンをリセットしても、ユーザーの色のコントロールは保たれます。

解析は、リニア RGB で面積に重みを付けた平均を使い、長辺を制限します。トーンとホワイトバランスは sRGB のプレビューを使うので、クリップはセンサーの飽和ではなく、プレビューのチャンネルのクリップです。これらの推定は、すべての被写体の色を光源の色かぶりと区別することはできず、測定したフィルムの色の正確さを保証するものでもありません。MAIN/CS の自動バランスと、彩度の低いシーン向けのバイブランスは、反転の段階に属します。

## カラーマネジメント

入力に有効な ICC があれば、その色空間を読みます。内部の計算は固定のリニア作業空間で行い、出力空間への切り替えは、表示、ソフトプルーフ、書き出しで行います。

主に対応する出力:

- sRGB
- Display P3
- Adobe RGB
- ユーザーが選ぶ RGB プリンターまたは出力 ICC

プリンタープロファイルの名前、バイト数、SHA-256 は、書き出しの開始時に固定します。描画中にファイルが変わると、実行は止まります。

現在の Core Image と ColorSync の経路が、すべての macOS のバージョンでレンダリングインテントとブラックポイント補正をビット単位で同一にすると主張はしません。その保証には、別の ColorSync バッファ経路と、大きな16bit 画像のためのメモリ確認が先に必要です。

## 出力のエンコード

形式の設定は色のパイプラインの外にありますが、納品されるファイルに何が残るかを決めます。

JPEG は、エンコーダーがサブサンプリングのしきい値を超えない限り、色を輝度より低い解像度で保存します。それより下では、色差が水平方向にも垂直方向にも半分になり、輝度のディテールは保たれたまま、彩度の高いエッジがやわらぎます。そのため、品質95%以上はクロマサブサンプリングなしでエンコードし、それより低い設定は、より小さいファイルを求めたことになるので、選んだ値のままにします。PNG と TIFF は可逆で、サブサンプリングしません。品質の調整は、チャンネルあたり8bit か16bit のビット深度だけで、ディザは量子化の縞を隠せる8bit でのみ適用します。

## パフォーマンスと安全

- `CIContext` は目的ごとに再利用します。
- 調整は低解像度のプレビューを使い、書き出しは元ファイルから作り直します。
- 時間のかかる処理は、結果を適用する直前に、フレーム ID、編集バージョン、セッションを確かめ直します。
- メモリが少なくなると、サムネイルやプレビューなどのキャッシュを捨てます。
- 元ファイルと編集履歴は、キャッシュから分けて保ちます。

## 検証の段階

1. 式のテスト: カーブの単調性、アンカー、逆関数
2. 合成画像: 既知の入力と出力、クリップ、向き、色空間
3. 合成 IT8: 264パッチでの数学的な往復
4. 実際の撮影統計: `realOnly` のプロファイル
5. REAL/TARGET のペア: 別の検証資料を持つ機器の品質判定
6. 実機: 実際のスキャナー、フィルム、ディスプレイ、プリント

合成 IT8 の結果が良くても、実際のネガでの絶対的な正確さは証明されません。スキャナープロファイルの品質の判断は、[スキャナープロファイル品質判定](../reference/PROFILE_QUALITY_GATE.md)と[IT8色検査](../reference/IT8_COLOR_VALIDATION.md)に従います。

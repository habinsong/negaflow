# Chroma Engine

[ドキュメントホーム](../README.md)

Chroma Engine は、フィルムを反転して現像します。コードは `Chromabase` モジュールにあります。アプリと CLI は同じモジュールを使うので、同じ入力は同じ順序の段階を通ります。

| ひと目で | 内容 |
|---|---|
| 既定の現像 | `MAIN`、自動バランス ON |
| フィルムベース | 自動測定、スポイト、RGB の直接入力 |
| 内部の色 | 浮動小数点のリニア色空間(macOS は 16bit half float、Windows は 32bit float) |
| 自動機能 | 自動バランス ON |
| 出力の色空間 | sRGB、Display P3、Adobe RGB、書き出し用の RGB プリンター ICC `prtr`(ソフトプルーフは `prtr`/`mntr`/`spac`) |

> [!IMPORTANT]
> 初期値は `MAIN` と自動バランス ON です。スイッチは、ターゲット見出しの右にある小さなピル型です。カラー・白黒ネガの MAIN(PRINT を含む)と CS でのみ表示されます。現在の写真に合わせて色と明るさを整え、オフにするとこの処理を省きます。自動トーン、自動ホワイトバランス、自動レベル補正、自動カラー補正は別の機能で、初期値はオフです。

## 最初に守ること

1. フィルムベースを測れるときは、名前で選んだ既定値より測定が優先されます。
2. フィルムの性質、スキャン光源、スキャナーのスタイル、シーンの自動補正は分けて扱います。
3. 自動トーンや自動ホワイトバランスなどの機能は、自分で実行したときだけ有効になります。
4. 同じ元ファイル、編集値、プロファイルの組は、同じ順序の段階を通ります。
5. 合成テストと実機での検証を、同じ証拠として並べません。

## 段階の順序

作業用の画像は、浮動小数点のリニア色空間で処理します。macOS は Core Image の 16bit half float、Windows エンジンは 32bit float で、どちらも 0 未満と 1 超の値を残します。カラーミキサー、カラーグレーディング、キャリブレーション、ポイントカーブは、`[0, 1]` 範囲の知覚的 sRGB エンコードで動きつつ、範囲外(`< 0` または `> 1`)の値をそのまま保ちます。最終的な画面表示やファイル書き出しのエンコードの前に、`DisplayGamutMap` が色域外の色を色相をずらさず出力色空間のリニア原色の中へ収めます。

1. ファイルを読み、向きを直す。
2. リニア入力(RAW ではカメラ RGB)。
3. フィルム種別: ポジはポジの処理へ、ネガはベースを測る。
4. 光学濃度と反転、続いて自動バランス ON/OFF、そのあと RAW のカメラ行列。
5. `EXPIRED` 復元補正(選択時)、続いてホワイトバランス、露出、基本トーン、パラメトリックカーブ。
6. スキャナーターゲット(`HS`、`SP`、`F135`、`HR`)と同梱スキャナープロファイル。
7. ポイントカーブ、カラーミキサー、カラーグレーディング、キャリブレーション。
8. `CS` カスタムターゲットと、デジタル元ファイル向けのデジタルフィルムルック。
9. ソフトウェアによる欠陥除去とノイズ軽減。
10. 部分的な覆い焼き・焼き込み、ディテール・テクスチャ、幾何補正。
11. `DisplayGamutMap` と表示用または出力色空間のエンコード。

`CIContext` はレンダリングごとに作り直さず、表示、解析、書き出しという目的ごとに再利用します。プレビューは必要なサイズと最新の編集バージョンだけを計算し、書き出しは元のサイズで描画し直します。

- [CIContext](https://developer.apple.com/documentation/coreimage/cicontext)

## フィルムベース

### 測る理由

ネガの未露光の部分は、フィルム、現像、スキャン光源がひとつになった基準点です。カラーネガのオレンジマスクもその中にあります。ベースを誤ると、その後のすべての濃度とチャンネルの関係が狂います。Kodak の Portra 400 の資料も、最小濃度、特性曲線、染料の分光濃度を別々に記しています。

- [Kodak Professional Portra 400 technical data](https://www.kodakprofessional.com/sites/default/files/wysiwyg/pro/resources/e4050_portra_400.pdf)

### 自動測定

`FilmBaseEstimator` は、フレーム全体で明るいピクセルの空間的な分布を評価して、未露光のベースを見つけます。

- フィルムのピクセルが未露光のベースより明るくなることはありません。
- それよりずっと明るいものは、バックライト、パーフォレーション、フィルムの外側かもしれません。
- 本物のベースは、フレームの端に沿って広い帯になりやすい傾向があります。
- 1枚のシートに複数のストリップがあるときは、離れた領域をまとめて読めます。
- ホルダーとフィルムが混ざる境界は、内側よりも信頼しません。

縮小した解析画像で明るさの分布を求め、つながった領域をまとめてから、フィルムの外にある候補を除きます。条件に通ったストリップが複数あれば、まとめて計算します。結果には、どの方法を選んだかと確信度も記録されます。

### 方法の選び方

| モード | 動作 |
|---|---|
| `Manual` | 入力した RGB を Dmin として使います。スポイトで取れた値もここに入ります。 |
| `Film` | 測定できれば測定した `Dmin` を使い、失敗したときだけフィルムの既定の `Dmin` に戻ります。フィルムの相対濃度範囲係数(`relativeRangeFactor`)を与え、カラーネガではニュートラル以外の光源ゲインを、測定値と既定値の両方を含む確定した `Dmin` に適用します。 |
| `Auto` | 空間解析を使い、失敗するとエッジに基づく方法に戻ります。 |

手動の値がない、またはフィルム ID が間違っているときは、次の安全な方法に移ります。シーンでもっとも明るいものを、そのままフィルムベースとすることはありません。

## 光学濃度と反転

濃度は、リニアな透過率 `T` とチャンネルごとのベース `Dmin` から求めます。

```math
D = \log_{10}\left(\frac{D_{\min}}{T}\right)
```

`D = 0` は、入力が未露光のベースと等しいことを意味します。パーフォレーションやバックライトは負になりえます。その値は有限のまま保ち、その場で切り捨てません。

### フィルム種別のデータ

現在の表には、フィルム名が27個(C-41 カラーネガ23種と ECN-2 映画用ネガ4種)あります。このデータは次のために使います。

- ベースを測れないときの Dmin の既定値
- フィルムに対して相対的な、固定の濃度係数

一部の値は公開資料のカーブを読んで近似し、一部は控えめに決めました。名前27個が検証済みの色プロファイル27個ではなく、ベースを測れたなら測定が優先されます。

### MAIN/PRINT と CS

自動バランス ON では、チャンネルごとにシーンでもっとも濃い0.2%パーセンタイルを使い、範囲を1.8Dに制限したうえで、`shoulder-print-response-v4` カーブと、彩度の低いシーン向けのバイブランスを適用します。OFF は同じカーブに固定の公称範囲(カラー1.55D、白黒2.17D)を使います。OFF はカラーネガで、同じロールの3フレーム以上から決めたスキャナーとフィルムのチャンネル範囲補正も掛けます。

ON は、シーンの内容によって明るさと色の両方が変わることがあります。どちらのモードも、測定したフィルムの色の正確さを保証しません。式、1.8Dの制限、RAW の順序は次にあります。

[ネガ反転応答](../reference/PRINT_RESPONSE.md)

## 3種類のプロファイル

| 種類 | 答える問い | 値 |
|---|---|---|
| フィルム種別 | フィルムのベースと濃度範囲はどうか | Dmin/Dmax、フィルム種別 |
| 光源 | スキャン光源が各チャンネルにどう影響したか | チャンネルゲイン、ベースに基づく補正 |
| スキャナーターゲット | 結果のトーンと色のスタイルはどうか | このプロジェクトのために撮影したスキャンの相対統計 |

3つを分けておくと、フィルム名ひとつが、乳剤の性質、光源の色、ラボの出力スタイルを一度に代表してしまうことを避けられます。実際のベースを測れれば、その測定値がフィルムの既定の `Dmin` より優先され、カラーネガではニュートラル以外の光源ゲインが確定した `Dmin`(測定値と既定値の両方)にそのまま適用されます。スキャナーの統計は、シーンの絶対的な色行列としては使いません。

データは[フィルムプロファイル](FILM_PROFILES.md)で説明しています。

## 現像ターゲット

### `MAIN`

自動バランスがオンの、既定のターゲットです。スイッチについてはこの文書の冒頭に書きました。

### `PRINT`

作業用の画像は `MAIN` と同じです。有効な RGB プリンター ICC は、書き出しの最後に1回だけ適用します。プロファイルがない、または不正なときは、sRGB や任意の用紙の値で代用せず、失敗します。

### `HS`, `SP`

固定のレンダリングです。ホワイトバランス、露出、基本トーンのスライダー、パラメトリックカーブのあと、ポイントカーブ、カラーミキサー、カラーグレーディング、キャリブレーションの前に入ります。ラボでも、オペレーターの濃度・色の補正はスキャンに先にかけ、プリントの曲線は固定したままです。写真から何も読み取らないので、同じピクセルはどの写真でも同じ結果になります。フレームごとの露出と色は、反転と、右側の自動トーン、自動ホワイトバランス、自動レベル補正、自動カラー補正のボタンが受け持ちます。ニュートラルのスポイトはレンダリング前の値を測るため、`HS` のグレー軸の傾きはスポイトのあとも残ります。

レンダリングは、輝度のトーンカーブ、明るさに応じた彩度ゲイン、そして `HS` ではグレー軸のわずかな傾きでできています。すべてのカーブは単調な3次カーブなので、節で折れ曲がりません。

- `SP` は、同じロールの4フレームを、実際の SP-3000 とこのプロジェクトのスキャナーでスキャンし、画素単位で合わせた資料から作りました。トーンカーブは、SP-3000 の185フレームのパーセンタイルから4分の1の重みを取っています。その4フレームで、SP-3000 のスキャンに対する CIEDE2000 の中央値は、`MAIN` の約7.4から3.9に下がります。暗いフレーム1枚はほとんど動きません。ラボがそこで赤いシャドウの色かぶりをフレームごとに取り除いており、固定のレンダリングにはそれができないからです。
- `HS` には画素ペアがありません。`SP` から出発し、フィルムとロールの名前が合う3ロールでの、2台の機械の中央値の差を足します。中間調がわずかに暗く、白がやや高く、色のついた画素は彩度0.88倍、明るい側のグレーは緑寄りになります(a* で約 −1〜−4)。
- `HS` は明るさチャンネルをシャープにします。半径は、機械の35mm出力(長辺3089px)で0.9pxで、解像度に比例して変わるので、プレビューと書き出しが一致します。強さは測っていません。

同梱のプロファイルを選ぶと、2台の機械で名前と画像数が合うロールの相対差である `scannerSignature` がさらに足されます。現在はすべてのプロファイルが `realOnly` です。

- 相対差は、ロール名と画像数が十分に近いときだけ計算します。
- 向きが逆転する値は適用しません。
- 白黒では色成分を捨てます。
- ファイルまたはマニフェストのどれかの SHA-256 が合わなければ、プロファイルのバンドル全体を拒否します。

### `F135`, `HR`

このプロジェクトには、Pakon F-135 や Kodak HR-500 で得た基準スキャンがないため、どちらのターゲットも、その機械とは照らし合わせていません。また、どちらも、ラボや利用者がその機械について残した記述から、それぞれ別の表を作っています。そのため、`SP` の数値からは出発していません。さらに、グレー軸はどちらもニュートラルです。一方、Pakon の利用記では色かぶりが黄・緑・青と食い違っており、フレームごとに違ったシーンバランスの跡です。

- `F135`(Kodak Pakon F-135、一般向けの TLX/PSI スキャナー)。Noritsu より彩度が低く、ホワイトバランスが合うことが多く、ハイライトとシャドウにディテールが残り、一部のスキャンは平坦に見えるという利用記が根拠です。モノクロを明るく出すという利用記もあります。18% グレーは一般向けのプリントのように 0.3 段明るくしています。中間調の局所コントラストは 0.8〜1.0 で、`SP` の 1.2〜1.35 より低くなります。トウを持ち上げて −6 段が 0.101(`SP` は 0.073)、ハイライトは長く寝かせ、反転がシーンの白に置く線形 0.70 は sRGB 231 に来ます。彩度ゲインは 0.68〜0.74 で、どの明るさでも `HS` より低い値です。
- `HR`(Kodak Professional HR 500)。raw に近いスキャンで後から手を入れる前提だというラボの話、色の扱いがよいという評価、ノイズのないシャドウのディテールが根拠です。18% グレーは 0.1 段濃く、中間調の局所コントラストは 1.15〜1.2 です。シャドウは 1.2〜1.3 で `MAIN` の線形のシャドウより濃く締まり(−6 段で 0.018)、段ごとの階調は `SP` の 1.6 倍開きます。ハイライトは `SP` のようには寝かせず 1.2〜1.35 で立ち上がり、シーンの白は sRGB 242 に来ます。彩度は 1.0 を保ち、ハイライトで 0.88 に下がります。`SP` は同じ所で彩度を上げます。

それぞれのレンダリングを、ターゲットが始まる段階まで現像した実際のネガ 7 枚(2 本のロール、診断にのみ使用)に重ねて測りました。写真ごとに平均すると、`MAIN` と四つのターゲットのどの組も CIEDE2000 で 2.9 以上離れます。測定から作った `SP`–`HS` は 4.3 です。1 枚の中では、ハイキーや中間調の多い場面で `MAIN`–`HR` と `F135`–`HR` が 2.0〜2.6 まで下がります。どちらのターゲットも、機械と照らし合わせるには `SP` にあったもの、つまり実機で同じネガをスキャンした資料が必要です。

### `EXPIRED`

古いフィルムのための復元ターゲットです。一律の彩度低下や範囲の引き伸ばしはせず、現在の根拠が裏づける限定的な補正にとどまります。

### `CS`

`CS`(Custom)は、18のカラースタイルを3つのまとまりで持ちます。Emulsion、Reversal、Dye Transfer、Skip Bleach、Plate Glass、Amber Glass、Ultramarine、Terracotta、Celadon、Nacre、Dichroic の11個と、Wetzlar、Classic、Studio、Rochester の4個、そして Slide Show、Cinema、Point & Shoot の3個です。

Custom ターゲットは、自動バランス付きの `MAIN` の反転を使い、そのあとで custom-3 のトーン・濃度・彩度の応答を適用します。スキャナープロファイルは併用しません。CLI も同じ ID を受け取ります。例: `--target classic`。

## デジタル由来の画像のフィルムルック

フィルムタブには、5種類にわたる42銘柄が入っています。リバーサル7種、カラーネガ16種、ECN-2 映画用4種、白黒ネガ13種、白黒リバーサル2種です。

この段階は `Digital Color` と `Digital B&W` の元ファイルにのみ適用されます。フィルムスキャンにはすでに乳剤の応答が入っているため、この段階を完全に飛ばします。

`Digital Color` は4つの段階を順に実行します。

1. リニア領域での散乱と赤に重みを置いたハレーション(`DigitalHalation`)。
2. チャンネルカーブ、分光行列、シャドウ・ハイライトの色味、彩度、データシートの MTF アキュータンスをまとめたポジ領域の 33³ 3D LUT(`FilmEmulationStage`)。
3. 半分の強さで適用する補助の銘柄色プリセット(`DigitalFilmColorPresetStage`)。
4. 濃度に応じたフィルム粒子(`DigitalFilmGrain`)。

`Digital B&W` は無彩色のハレーション、乳剤のトーンカーブを伴う分光 RGB-グレースケール変換(`digitalBWFilm`)、MTF アキュータンス、無彩色の濃度連動粒子の順に進みます。

## 現像のコントロール

| グループ | 項目 |
|---|---|
| トーン | 露出、コントラスト、濃度、ハイライト、シャドウ、白レベル、黒レベル、パラメトリックカーブ、RGB とチャンネルごとのポイントカーブ |
| 色 | 色温度、色かぶり補正、自然な彩度、彩度、色の深み、8色の HSL、3領域のカラーグレーディング、チャンネル補正、白黒変換とトーニング |
| ディテールとエフェクト | シャープネス、明瞭度、フィルム粒子、周辺光量、ハレーション、ノイズ軽減 |
| 部分補正 | 円形、線形、多角形、ブラシのマスク、覆い焼きと焼き込み |
| 変形 / ジオメトリ | 遠近補正と角度補正 |

基本補正のトーンスライダーとパラメトリックカーブは、どの組み合わせでもトーンを反転させません。基本補正はコントラスト、濃度、ハイライト、シャドウ、白レベル、黒レベルをこの順に、前の段の結果へひとつずつ適用します。各段はそれだけで単調です。パラメトリックカーブの 4 つのスライダーは、写真の輝度の 10・35・65・90% の位置に置いたノットをひとつずつ動かし、ノットの間は単調な 3 次曲線でつなぎます。ノットは互いに、また黒と白から sRGB で 0.10 以上離れています。そのためスライダーを端まで動かすと、どの写真でもノットが sRGB で 0.045 以上動きます。

カラーミキサー、カラーグレーディング、キャリブレーション、ポイントカーブは、`[0, 1]` 範囲の知覚的 sRGB エンコードで動きつつ、0 未満や 1 超の値をそのまま保ちます。出力エンコードの前に、`DisplayGamutMap` が色域外の色を色相をずらさず出力色空間のリニア原色の中へ収めます。

これらの値は、段階ごとの編集履歴として保存されます。GrainMend と通常の部分補正は、目的も保存の方法も異なります。

### 自動補正

| コントロール | 動作 |
|---|---|
| 自動トーン | 露出、コントラスト、濃度、ハイライト、シャドウ、白レベル、黒レベルを割り当てます。露出はシーンの対数平均輝度をシーンキーに合わせます。明るい写真は下げ、暗い写真は上げ、明るいシーンほどキーを高くします。ほかのスライダーは基本補正が適用する順に、前の段を反映した値から計算します。拡散白より暗いのに最も明るいチャンネルが新たに上限に届く画素は 0.5% までに抑えます。拡散白より明るい鏡面反射と光源は飛んでもかまいません。彩度の高い色が飛びそうなときは、白レベル、露出、濃度とコントラストによる持ち上げの順に譲ります。露出を控えて暗く残った中間調は濃度が補います。このために譲る露出と測ったシーンキーは 1 段までで、色を守るのにそれ以上かかるときはクリップを受け入れます。ユーザーの色のコントロールとカーブは保ちます。 |
| 自動ホワイトバランス | ニュートラルに近い輝度の帯から色温度と色かぶり補正を推定します。RGB のチャンネルが飛んだサンプルは除き、ニュートラルの根拠が少ない、またはトーンの範囲が狭いときは補正を弱めます。 |
| 自動レベル補正 | 共通する輝度の端点を測り、RGB に同じ輝度ゲインを適用してチャンネルの比を保ちます。ネガでは端点を反転の黒と拡散白の基準点(カラーは線形 0.70、モノクロは 0.85)に合わせます。露出のショルダーが始まるニー自体はどちらも線形 0.70 に固定され、ヘッドルームが各フィルム種別の白の基準点に合わせてスケールされます。 |
| 自動カラー補正 | 残った色かぶりをニュートラルの候補に当てはめます。当てはめが、未使用の別の輝度の帯を予測するときだけチャンネルの傾きを使い、それ以外はゲインを使います。弱い代替の根拠には、補正を控えめにします。チャンネルの傾きは最も暗い根拠の帯から白までだけで使い、それより暗い所には根拠の下端の補正をそのまま使います。 |

自動トーンは、最初の提案をレンダリングしたプレビューで確かめます。さらに露出やホワイトポイントを変える提案が出たら、その候補もレンダリングし、中間調、端点、トーンの範囲、クリップのスコアが良くなるときだけ受け入れます。ここでさらに明るくするときも同じチャンネルの上限を守ります。確認用のレンダリングをニュートラルなレンダリングと画素ごとに比べ、そうした画素が新たに 0.5% を超えてクリップすると(スキャナーターゲットとカーブを含む)、白レベル、次に露出を下げ、上限内で最も明るい値を探すためにプレビューを最大 3 回レンダリングし直します。2 つのレンダリングから選ぶときは、クリップの少ない方がスコアの比較より先です。これは限度のある補正で、唯一の理想的な描画を探すものではありません。コマンドを繰り返しても、設定は積み重ならず、割り当て直されます。自動トーンをリセットしても、ユーザーの色のコントロールは保たれます。

解析は、リニア RGB で面積に重みを付けた平均を使い、長辺を制限します。トーンとホワイトバランスは sRGB のプレビューを使うので、クリップはセンサーの飽和ではなく、プレビューのチャンネルのクリップです。これらの推定は、すべての被写体の色を光源の色かぶりと区別することはできず、測定したフィルムの色の正確さを保証するものでもありません。MAIN/CS の自動バランスと、彩度の低いシーン向けのバイブランスは、反転の段階に属します。

## カラーマネジメント

入力に有効な ICC があれば、その色空間を読みます。Windows では、埋め込まれた広色域 ICC 入力を内部の Rec.2020 中間プロファイル経由で変換し、Gray ICC のモノクロスキャンにも対応します。内部の計算は固定のリニア作業空間で行い、出力空間への切り替えは、表示、ソフトプルーフ、書き出しで行います。

主に対応する出力:

- sRGB
- Display P3
- Adobe RGB
- ユーザーが選ぶ RGB ICC: プリンター出力の書き出しには ICC プリンタークラス `prtr` の RGB プロファイルが必要で、ソフトプルーフは出力可能な RGB プロファイル(`prtr`、`mntr`、`spac`)を受け付けます

プリンタープロファイルの名前、バイト数、SHA-256 は、書き出しの開始時に固定します。描画中にファイルが変わると、実行は止まります。Windows で従来の ICM が LUT プリンター ICC の Relative Colorimetric を拒否したときは、Perceptual または WCS v4 の経路に切り替えます。

現在の Core Image と ColorSync の経路が、すべての macOS のバージョンでレンダリングインテントとブラックポイント補正をビット単位で同一にすると主張はしません。その保証には、別の ColorSync バッファ経路と、大きな16bit 画像のためのメモリ確認が先に必要です。

## 出力のエンコード

形式の設定は色のパイプラインの外にありますが、納品されるファイルに何が残るかを決めます。

JPEG は、エンコーダーがサブサンプリングのしきい値を超えない限り、色を輝度より低い解像度で保存します。それより下では、色差が水平方向にも垂直方向にも半分になり、輝度のディテールは保たれたまま、彩度の高いエッジがやわらぎます。そのため、品質95%以上はクロマサブサンプリングなしでエンコードし、それより低い設定は、より小さいファイルを求めたことになるので、選んだ値のままにします。PNG と TIFF は可逆で、サブサンプリングしません。品質の調整は、チャンネルあたり8bit か16bit のビット深度だけで、ディザは量子化の縞を隠せる8bit でのみ適用します。

## パフォーマンスと安全

- `CIContext` は目的ごとに再利用します。
- 調整は低解像度のプレビューを使い、書き出しは元ファイルから作り直します。
- 時間のかかる処理は、結果を適用する直前に、フレーム ID、編集バージョン、セッションを確かめ直します。
- メモリが少なくなると、サムネイルやプレビューなどのキャッシュを捨てます。
- 元ファイルと編集履歴は、キャッシュから分けて保ちます。

## 検証の段階

1. 式のテスト: カーブの単調性、アンカー、逆関数
2. 合成画像: 既知の入力と出力、クリップ、向き、色空間
3. 合成 IT8: 264パッチでの数学的な往復
4. 実際の撮影統計: `realOnly` のプロファイル
5. REAL/TARGET のペア: 別の検証資料を持つ機器の品質判定
6. 実機: 実際のスキャナー、フィルム、ディスプレイ、プリント

合成 IT8 の結果が良くても、実際のネガでの絶対的な正確さは証明されません。スキャナープロファイルの品質の判断は、[スキャナープロファイル品質判定](../reference/PROFILE_QUALITY_GATE.md)に従います。また、[IT8色検査](../reference/IT8_COLOR_VALIDATION.md)もあわせて参照してください。

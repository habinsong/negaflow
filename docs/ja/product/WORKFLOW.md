# ライブラリからプリントまで

[ドキュメントホーム](../README.md)

このガイドは、読み込み、フォルダー現像、設定の受け渡し、スキャナーのサムネイル、プリント出力を扱います。ライブラリのフォルダーは、各元ファイルの実際の親フォルダーに従います。

> [!IMPORTANT]
> 写真を別のフォルダーに自分で移さない限り、元ファイルは変わりません。フォルダーをライブラリから外すことと、Finder でファイルを削除することは別の操作です。

## 読み込み

読み込みのコントロールの下に、進行バー、パーセント、完了数、全体の数が表示されます。メタデータはメインスレッドの外で読み、新しいフレームをまとめて登録するので、大きなフォルダーでもライブラリの索引を何度も作り直しません。

読み込んだ写真の自動現像は**初期状態でオフ**です。読み込みは次のように進みます。

1. 元ファイルを登録します。
2. 元のサムネイルとフォルダーが先に現れます。
3. フォルダーにプロセスとターゲットを適用するか、現像画面に入ると、現像が始まります。

読み込んだ写真をすべて自動で現像するには、**設定 → ワークフロー → 新しく読み込んだ写真を自動現像** をオンにします。選択は起動をまたいで保たれます。この設定はその読み込みで登録されたフレームにだけ効き、すでに現像した状態を置き換えません。現像済みの写真を処理し直すのは、フォルダーで**適用**を明示的に押したときか、設定を貼り付けたときだけです。

スキャナーのキャプチャは違います。フィルム種別、プロセス、ターゲットはスキャン中に決まるので、スキャン結果が公開された後に現像が始まります。現像とプリントのフィルムストリップでは、カラーネガ、ポジ、白黒ネガ、白黒ポジの元ファイルに現像済みのサムネイルを使います。ライブラリは、元ファイルの確認のために元のサムネイルを保ちます。

## フォルダー一覧

- 折りたたみと展開の状態は保たれます。フォルダーを作ったり、アプリを開き直したりしても、ほかのフォルダーは展開されません。
- フォルダーの行にはどれも同じ `×` のコントロールがあります。これはそのフォルダーと写真を**ライブラリからだけ**外します。元ファイルは Finder に残ります。
- 現像画面のフォルダー内の写真リストには、高さを制限した専用のスクロール領域があります。リストが長くても、ウィンドウが小さくても、サイドバーの残りが押しのけられません。

### 写真を別のフォルダーに移す

写真1枚、または選択した写真を別のフォルダーの行にドラッグすると、実際のファイルを移し、カタログも一緒に更新します。読み込んだフォルダー、アプリが作ったフォルダー、スキャナーのキャプチャを含むフォルダーのどれにも同じ規則が当てはまります。

移動先に同じ名前があっても上書きしません。`frame.tiff` があれば、negaflow は `frame 2.tiff`、`frame 3.tiff` の順に試します。スキャナーの元ファイルに付く IR ファイルは、同じトランザクションで移ります。

### Finder での変更

negaflow は、登録された実際の元フォルダーを監視します。短いデバウンスの後に次を検知したら、変更のあったフォルダーだけを再スキャンします。

- 元ファイルの移動または名前の変更
- 登録済みフォルダーの移動または名前の変更
- 登録済みフォルダーの直下にできた新しい画像

元ファイルの永続ブックマークが新しい場所を解決できれば、既存のフレームを再リンクします。移動したフォルダーは、フォルダー ID と追加日を保ちます。新しく加わったファイルは、すでに知っているファイルと重複しないように読み込みます。

これはイベント駆動のフォルダー監視で、定期的にライブラリ全体をスキャンするものではありません。実際の親フォルダーが同じフレームは1つの監視を共有し、変更を報告したフォルダーだけを調べます。

## フォルダー単位の現像

フォルダー名の横でプロセスとターゲットを選び、**適用**を押します。別にオンとオフを切り替えるスイッチはありません。

適用は、以前に現像した写真も含めて、フォルダー内のすべての写真を再レンダリングします。新しいプロセスとターゲットが使われ、露出やコントラストなど、ほかのユーザー調整は残ります。すでにレンダリング中のフレームがあれば、フォルダーのジョブはそのレンダリングの終了を待ちます。

適用の横に、進行バー、パーセント、完了数、全体の数が表示されます。大きなバッチでは、写真ごとにタスクを起こさず、レンダリングの枠の数だけワーカーを保ちます。

## 傾き補正と変形

現像画面の右側で ジオメトリ → 切り抜き を開きます。⌘(Windows では Ctrl)を押したまま、水平であるべき縁に沿ってドラッグして離すと、その線が水平になるように写真が回ります。縦に近い線を引いた場合は垂直に合わせます。⌥(Windows では Alt)を押している間は、切り抜きの上に細かいグリッドが出ます。どちらのキーも 設定 → ショートカット で変えられますが、同じキーにはできません。Mac では ⌃ クリックが右クリックになるため、基準線のキーに ⌃ は選べません。

変形セクションは キャリブレーション と ディテールと効果 の間にあります。オフは写真をそのままにします。自動・水平・垂直・フルは、写真の中のまっすぐな線を一度探して補正します。水平は写真を回すだけで、垂直は上にすぼまる縦の線も立てます。フルは縦と横の遠近を両方直します。自動はフルと同じ処理をしつつ、大きな補正を抑えます。ガイド付きは、写真の上に引いたガイド 2〜4 本に従います。

垂直方向、水平方向、回転、縦横比、拡大・縮小、X オフセット、Y オフセットのスライダーは、モードが求めた値に加わります。スライダーをダブルクリックすると初期値に戻ります。切り抜きを制限 をオンにすると、空いた角のない最大の長方形で切り抜きます。オフのときは空いた角が画面でも書き出したファイルでも白です。ヒストグラム、クリッピング警告、自動トーン、自動ホワイトバランスはその部分を写真として数えません。90° 回転や反転をしても補正はそのまま付いてきます。すべての補正をリセット は、切り抜き・角度と一緒に変形も消します。

## プリセットとコピー・ペースト

現像設定には、個別に選べるグループが7つあります。

| グループ | 値 |
|---|---|
| 入力ガンマ | 元ファイルの伝達特性の解釈 |
| ベーススケール | フィルムベースのスケール |
| ベース | フィルム種別とプロセス、ターゲット、スキャナープロファイル、フィルムベース、チャンネル範囲補正、自動バランス、自動レベル、ニュートラルバランス |
| トーン | 露出、コントラスト、濃度、ハイライト、シャドウ、白レベル、黒レベル、トーンカーブ |
| 色 | 色温度、色かぶり補正、色の深み、自然な彩度、彩度、ミキサー、グレーディング、キャリブレーション、白黒のトーニング、フィルムエミュレーション |
| ディテール | 粒子、シャープネス、ハレーション、明瞭度、周辺光量、ノイズ軽減、GrainMend の強さ、部分補正 |
| ジオメトリ | 切り抜き、回転、左右・上下の反転、傾き補正、切り抜きの縦横比、変形 |

全体のペーストやユーザープリセットは、対象の現像設定をまるごと置き換えます。範囲を指定したペーストは、選んだグループの有効な値だけを置き換え、残りは保ちます。ルックの一部だけを貼り付けるときは、ルックのトーン、色、質感の寄与を値に取り込み、ルックへの参照を消すので、古いルックが二重に加わりません。同じ設定を繰り返し貼り付けても、状態は同じです。メニュー、ショートカット、パネルは同じペースト範囲を使います。

ペーストとユーザープリセットは、選択したすべての写真に適用されます。取り消しとやり直しは1回で選択全体に効き、Windows ではどれかを変える前にすべての対象を検証します。サムネイルとアクティブなプレビューは、新しいレシピで更新されます。元ファイル、評価、元ファイルに結び付いた欠陥の編集はコピーされません。

ユーザープリセットは、現像状態の全体とジオメトリを保存します。ジオメトリのない古いプリセットやペースト範囲には、互換のためジオメトリが含まれます。名前が空なら、空いている最初の番号付きの名前が付き、保存しても、名前が同じというだけで既存のプリセットを上書きすることはありません。

## スキャナープラグインなしで

起動時にスキャナープラグインが入っていなくても、共通のライブラリと現像のサイドバーに、プラグインがないことの説明、再スキャンのコントロール、シミュレーターのブロックは自動では表示されません。画像の読み込みはそのまま使えます。

スキャナーの再スキャンとシミュレーターのサポートはそのままあります。スキャナーの入口と設定から使え、プラグインを入れるか、シミュレーターを明示的に有効にすると、既存のスキャナー UI が現れます。

## プリントレイアウトと出力数

プリントには8つのレイアウトがあります。単一画像、コンタクトシート、ピクチャーパッケージ、カスタムパッケージ、サイアノタイプ、ガラス乾板、ゼラチンシルバー、ウォーターマークです。単独画像系の5つは、選んだ写真ごとに完成したページを縦スクロールで見せます。ウォーターマークは独立したレイアウトで、ほかは既存のコントロールを保ちます。

書き出しとクイック書き出しは、完成したページを数えます。たとえば、写真39枚の 6 × 7 コンタクトシートは合成した1ファイル、4枚組のピクチャーパッケージは10ページ、既定のカスタムパッケージは1ページになり、単独画像系の5つは上限付きのバッチで39ファイルになります。

パッケージのプレビューは、既存のサムネイル、現像画像、RAW プレビューを再利用し、どれもないときだけ小さな高速プレビューを作ります。最終の書き出しは、元ファイルのメタデータから配置ごとの位置を計算し、その配置に必要なピクセルだけを現像し、元ファイルを2〜4個ずつ同時に準備して、最後のページを描画するまで Core Image のグラフをつないだままにします。共有のレンダーコンテキストと1ページあたり512MiBの元ラスター予算が、1ページが際限のない全解像度の中間画像に膨らむのを防ぎます。

## プリントのウォーターマーク

レイアウトの種類メニューで、ゼラチンシルバーの次のウォーターマークを選びます。写真を切り抜かずに各写真の下に枠を足し、同じ高さの上の枠も足せます。写真用紙のサイズは、写真と枠を合わせた大きさに従います。

下の枠の左には、カメラとその下にレンズが表示されます。右にはロゴ、その横に焦点距離、絞り、シャッタースピード、ISO が表示され、その下に日付が表示されます。ロゴをオンにすると1つ追加でき、ファイルを選ばなければ negaflow のロゴを使います。negaflow はメーカーのロゴを同梱しないので、JPEG や PNG などの画像ファイルを自分で選んでください。設定とテンプレートにはファイルのパスだけを保存します。描画時にファイルを確かめ、サイズと更新時刻が変わらない間はキャッシュしたロゴを再利用します。ファイルが移動または削除されていれば、ロゴだけが抜け、下部の状態を示す点と診断レポートに記録されます。空のカメラ、レンズ、露出、日付の欄は空のままで、入力したテキストだけを描画します。テキストが長いとき、または縦位置の写真のように枠が狭いときは、枠の中のすべての項目が同じ割合で縮むので、テキストが写真からはみ出したり切れたりしません。

枠は、白、黒、写真のぼかしから選べます。白ではテキストが黒で、2行目はグレーです。黒ではすべてのテキストが白です。ぼかしでは、テキストとヒストグラムの色を黒か白から選びます。ヒストグラムは点の柱で描きます。名前とヒストグラムの位置の規則は[プリントレイアウトとC-printプレビュー](../reference/C_PRINT.md)にあります。ぼかしとヒストグラムは、使えるフィルムストリップのサムネイルがあれば再利用し、なければ縮小した写真の画像を使います。テンプレートは、用紙の色と、テキストやロゴのパスを含むすべてのウォーターマーク設定を保存します。

## プリントのプロファイル

プリントにある ICC のコントロールは、それぞれ役割が違います。

| 設定 | 画面のプレビュー | プリント書き出し | 現像のプレビュー |
|---|---|---|---|
| プリンター出力プロファイル | プリントの結果を見せる | 完成したページに適用 | 適用しない |
| C-print のプルーフプロファイル | ラボと用紙の工程をソフトプルーフする | 納品ファイルには焼き込まない | 適用しない |
| 一般のソフトプルーフ | 設定した表示の範囲で使う | 表示の補助だけ | 自身の設定に従う |

プリンター出力プロファイルは、元ファイルを複製する前のその元ファイルには適用しません。コンタクトシート、ピクチャーパッケージ、カスタムパッケージを先に組み、そのあとでページ全体にプロファイルを1回適用します。そのため、1つの元ファイルを繰り返し配置したレイアウトも、複数の元ファイルを混ぜたレイアウトも、同じ出力変換を受けます。

C-print のプルーフプロファイルは、ラボが提供する工程のプレビューです。出力プロファイルとして黙って差し替えられることはありません。プロファイルの要件と精度の限界は[プリントレイアウトとC-printプレビュー](../reference/C_PRINT.md)にあります。

## DNG の書き出し

DNG は、現像した絵を、選んだ出力色空間(sRGB、Display P3、Adobe RGB)の非圧縮16bit リニア RGB ファイル(`PhotometricInterpretation = LinearRaw`)として書き出します。トーンと色はすでに焼き込まれているので、ほかのアプリは出力基準のファイルとして読みます。ファイルには、TIFF と同じメタデータの方針に従って、著作権、スキャナー、ソフトウェア、日付、フィルムのメモが入ります。元のカメラの EXIF、IPTC、GPS はコピーしません。1ピクセルあたり6バイトなので、24メガピクセルのフレームは約144MBです。

DNG を使えるのは、圧縮されていない元ファイル(TIFF、カメラ RAW、DNG)です。JPEG、PNG、HEIC の元ファイルは DNG に書き出せません。現像、`PRINT` ターゲット、プリントレイアウトのどれも DNG に対応しています。プリントの DNG は、組んだページを ColorMatrix 付きの標準 RGB で記録し、プリンター ICC の変換は省きます。DNG の書き出しは、書き出しで選んだフォルダーを使い、`.dng` の拡張子を保ちます。最終ファイルが公開されて検証されて、はじめて完了です。exiftool と Apple の画像デコーダーがファイルを読めます。ほかの RAW 編集ソフトでの描画は測っていません。

## 元ファイルを変える操作

| 操作 | Finder の元ファイル | カタログと編集 |
|---|---|---|
| フォルダーの `×` | そのまま | フォルダーと写真がライブラリから外れる |
| 別のフォルダーへドラッグ | 移動。名前が重なれば新しい名前を選ぶ | 新しい場所に再リンク |
| Finder での移動・名前変更 | ユーザーの変更を保つ | ブックマークで自動的に再リンク |
| フォルダー現像の適用 | そのまま | プロセスとターゲットを更新して再レンダリング |
| プリセット、コピー・ペースト | そのまま | 選んだ現像とジオメトリの値を更新 |
| プリント書き出し | そのまま | 別の出力ファイルとレンダー記録を作成 |

## 大規模ライブラリの確認

写真が256枚を超えると、選択が変わるたびにフィルムストリップが長い自動スクロールをしなくなります。見えているカードとフォルダーの行は、必要になってから作ります。

2,000フレームの負荷確認は、24MP、40MP、60MP、3200 DPI、4800 DPI のピクセルフィクスチャーを50個のフォルダーに読み込みます。すべてのプロセスとターゲットを混ぜ、カラーネガを半分以上にして、切り抜きと向きの変更を適用し、現像、サムネイル、カタログの往復を検証します。`negaflow-mac/` で実行します。

```bash
bash scripts/performance/run-virtual-library-stress.sh
```

負荷確認は自分で有効にする方式で、通常の `swift test` では飛ばされます。

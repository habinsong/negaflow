## 3. 측정 방법

```bash
negaflow-cli --grain-mend-detect "<source.tiff>" <dmin-r> <dmin-g> <dmin-b> [sensitivity] [guided]
```

다섯 장 한 번에:

```powershell
$cli = "out\build\native\x64-release\Release\negaflow-cli.exe"
$dir = "C:\Users\habin\OneDrive\바탕 화면\negaflow_test"
foreach ($n in 2,3,4,5,7) {
  $src = Join-Path $dir "OpticFilm8100_frame_$n.tiff"
  Write-Host "frame_$n"
  & $cli --grain-mend-detect $src 0.42 0.30 0.22 1.0
}
```

### 3.1 주의 — 검출 입력은 cleaned raw 다

macOS `AppModel.runRegionDetect` 는 `cleanedRawImage`(현상 전 선형 스캔)에서
`SoftwareDefectRemoval.detectComponents` 를 돌린다. dmin·반전·톤·필름룩은 검출 입력이
아니다. 예전 계측기의 `0.42 0.30 0.22` / `auto` dmin 은 호환용 인자일 뿐이며 지금은
쓰지 않는다(`input_domain: cleaned_raw`).

양화 뒤에서 검출하면 먼지 대비가 통째로 달라져 숫자가 맞을 수 없다.

### 3.2 민감도

macOS 자동의 기본은 슬라이더 최대(6.0) → 검출기 민감도 1.0 입니다
(`GrainMendSensitivity.defaultValue(automatic:)` = `automaticRange.upperBound`).
계측기의 기본 `sensitivity` 도 1.0 이라 같습니다.

### 3.3 미세 입자

macOS 자동은 `detectMicroSpecks` 가 켜져 있습니다(설정 기본값). 계측기도 켬 고정입니다.

## 4. 합격 기준

각 프레임에서 **분류별 개수가 macOS 의 ±20% 안**에 들 것. 미세 입자처럼 수백~수천 개인
분류는 개수 자체보다 **자릿수와 비중**이 맞아야 합니다.

절대 안 되는 것:

- 어떤 분류가 macOS 는 있는데 Windows 는 **0** (지금 먼지·핀홀·미세입자가 그렇습니다)
- 어떤 분류가 macOS 의 **3배 이상** (오검출 폭증)

# 06 — 검출 기준값 (macOS 정답지)

사용자가 macOS negaflow 에서 직접 뽑은 **자동 검출** 결과입니다. 이 표가 Windows 검출
작업의 채점표입니다.

원본: `C:\Users\habin\OneDrive\바탕 화면\negaflow_test\OpticFilm8100_frame_*.tiff`
(5088×3401 급 컬러 네거티브, OpticFilm 8100)

**미세 입자가 전체의 대부분입니다.**

|---|---:|

| frame_3 | 76.2% |
| frame_4 | 86.8% |

| frame_7 | 77.0% |

→ **미세 입자를 못 내면 검출의 4/5 를 못 내는 것입니다.** Windows 는 지금 0개입니다.

**먼지가 두 번째로 큽니다.** 13~175개. Windows 는 0개입니다.

**스크래치는 자릿수가 작습니다.** 가로 5~34, 세로 10~21, 대각 0~11. Windows 가 frame_4 에서
가로 3 · 세로 11 · 대각 1 을 내고 있으니 **스크래치 경로만 살아 있습니다.**

**핀홀은 2~8개로 일정합니다.** 적지만 0 은 아닙니다.

**유제 손상은 frame_2 에서만 1개.** 아주 드문 분류입니다.

**프레임마다 더러움이 8배 차이납니다**(227 ~ 1,720). 그래서 한 프레임만 보고 임계를 맞추면
안 됩니다 — 최소 이 다섯 장을 다 돌려야 합니다.

## 3. 측정 방법

```bash
negaflow-cli --grain-mend-detect "<source.tiff>" <dmin-r> <dmin-g> <dmin-b> [sensitivity] [guided]
```

다섯 장 한 번에:

```powershell
$cli = "out\build\native\x64-release\Release\negaflow-cli.exe"
$dir = "C:\Users\habin\OneDrive\바탕 화면\negaflow_test"
foreach ($n in 2,3,4,5,7) {
  $src = Join-Path $dir "OpticFilm8100_frame_$n.tiff"
  Write-Host "frame_$n"
  & $cli --grain-mend-detect $src 0.42 0.30 0.22 1.0
}
```

### 3.1 주의 — dmin 을 맞춰야 합니다

위 예의 `0.42 0.30 0.22` 는 **임의값**입니다. 앱이 쓰는 dmin 은 프레임마다 다르며 카탈로그에
저장돼 있습니다. dmin 이 다르면 현상 결과가 달라지고 검출 입력도 달라집니다.

**할 일**: 앱이 각 프레임에 쓰는 dmin 을 뽑아 이 문서에 적고, 계측기가 그 값을 쓰도록
합니다. 그래야 macOS 기준값과 같은 조건이 됩니다. (또는 계측기가 카탈로그에서 프레임
설정을 읽게 만드는 편이 확실합니다.)

### 3.2 민감도

macOS 자동의 기본은 슬라이더 최대(6.0) → 검출기 민감도 1.0 입니다
(`GrainMendSensitivity.defaultValue(automatic:)` = `automaticRange.upperBound`).
계측기의 기본 `sensitivity` 도 1.0 이라 같습니다.

### 3.3 미세 입자

macOS 자동은 `detectMicroSpecks` 가 켜져 있습니다(설정 기본값). 계측기도 켬 고정입니다.

## 4. 합격 기준

각 프레임에서 **분류별 개수가 macOS 의 ±20% 안**에 들 것. 미세 입자처럼 수백~수천 개인
분류는 개수 자체보다 **자릿수와 비중**이 맞아야 합니다.

절대 안 되는 것:

- 어떤 분류가 macOS 는 있는데 Windows 는 **0** (지금 먼지·핀홀·미세입자가 그렇습니다)
- 어떤 분류가 macOS 의 **3배 이상** (오검출 폭증)

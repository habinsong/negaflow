# CIVibrance — 수식 대신 잰 사상

기준일: 2026-08-16

## 왜 표인가

`CIVibrance` 는 Apple 내장 필터라 커널 소스가 없습니다. 웹에도 Apple 이 내장 필터의 커널을
공개하지 않는다는 것만 확인됩니다. 그래서 **수식을 되짚지 않고 잰 값을 그대로 씁니다.**

맥이 세 차례 보내 준 격자에서 두 가지가 나왔습니다.

**1. 화소마다 정확히 아핀입니다.** 세 채널을 `α·in + β` 로 맞춘 잔차:

| 판 | 점 수 | 잔차 최대 |
| --- | ---: | ---: |
| 17³ a0.259 | 4,913 | 7.5 × 10⁻⁸ |
| 33³ a0.50 | 35,937 | 1.2 × 10⁻⁵ |
| **65³ a0.25** | **274,625** | **6.3 × 10⁻⁶** |

274,625 점에서도 성립하므로 우연이 아닙니다.

**2. 앵커는 산술 평균입니다.** `(R+G+B)/3` 로 풀면 최대 0.0004, 중앙값 0.0000. Rec.709
휘도로 풀면 최대 0.3821 어긋납니다. Windows 는 휘도를 쓰고 있었습니다.

그러므로 화소마다 필요한 것은 스칼라 하나입니다.

```
out = A + (in − A) · f,   A = (R+G+B)/3,   f = 1 + amount · g(R,G,B; amount)
```

`g` 는 채도·크로마·명도 어느 하나의 함수도 아닙니다(구간 내 퍼짐 0.122 / 0.111 / 0.095).
색상까지 넣어야 0.033 으로 줄어듭니다 — 문서가 말하는 피부색 보호와 맞습니다. 여기서 수식을
지어내면 이 조사의 아홉 번째 가설이 됩니다.

## 표의 모양

| 항목 | 값 |
| --- | --- |
| 격자 | 33³ (축마다 0…1 을 32 등분) |
| amount 판 | 0.05 / 0.25 / 0.50 세 장 |
| 담는 값 | `g`, uint16 양자화(눈금 3.82 × 10⁻⁵) |
| 크기 | 107,811 항목 = **211 KiB** |

판을 열 장으로 늘려도, float32 로 담아도 오차가 달라지지 않아 셋·uint16 으로 둡니다.

| 구성 | 실사진 RMS | 65³ RMS | 크기 |
| --- | ---: | ---: | ---: |
| 10판 float32 | 45.5 | 48.6 | 1404 KiB |
| 10판 uint16 | 45.5 | 48.6 | 702 KiB |
| **3판 uint16** | **45.5** | **48.6** | **211 KiB** |
| 2판 uint16 | 45.5 | 48.6 | 141 KiB |

## 검증 — 표를 만들 때 쓰지 않은 자료로만

표는 33³ 격자로 만들었습니다. 아래는 전부 그 격자가 아닌 자료입니다.

**65³ 격자 (a=0.25, 274,625 점)**

| | 최대 | RMS |
| --- | ---: | ---: |
| 표 | 1076 | **48.6** |
| 지금까지의 수식 | 6337 | 1630.5 |

**실제 프레임 사다리** — 맥이 같은 사진을 여섯 amount 로 통과시킨 것. 표를 맞출 때 쓴
`a0.259` 판과 별개입니다.

| amount | 표 RMS | 지금까지의 수식 |
| ---: | ---: | ---: |
| 0.05 | 8.7 | 146.2 |
| 0.10 | 17.4 | 288.5 |
| 0.15 | 26.0 | 426.8 |
| 0.25 | 43.4 | 691.9 |
| 0.35 | 60.9 | 942.1 |
| 0.50 | 87.2 | 1291.0 |

**파이프라인이 실제로 내는 amount (0.259)** — 이 판은 표에 없습니다.

| | 최대 | RMS |
| --- | ---: | ---: |
| 표 | 921 | **45.5** |
| 지금까지의 수식 | 2071 | 706.9 |

RMS 45.5 는 16비트이고 8비트로 **0.18 레벨**입니다.

## 최종 픽셀 — V700

`a-default-main-srgb`, macOS 골든 대비:

| | 표 넣기 전 | **표 넣은 뒤** | macOS |
| --- | ---: | ---: | ---: |
| R median | 45654 (+746) | **44924 (+16)** | 44908 |
| G median | 47946 (+50) | 47951 (+55) | 47896 |
| B median | 49500 (−365) | **49929 (+64)** | 49865 |
| B max | 61077 | **61186 (일치)** | 61186 |
| R mean | 41624 (+638) | **41003 (+18)** | 40985.7 |
| B mean | 45273 (−380) | **45685 (+32)** | 45653.3 |

8비트로 R **2.9 → 0.06 레벨**입니다.

**8100 은 그대로입니다.** 그 장면은 `meanSat 0.41 > 0.24` 라 amount 가 0 이고 단계 자체를
건너뜁니다. 맥도 같습니다(전/후 sha256 동일). 표를 넣어도 안 바뀌는 것이 맞고, 실제로 안
바뀌었습니다 — R min 58, G min 71, B max 62256 이 여전히 정확히 일치합니다.

## 넣지 않은 곳

**ColorModel 의 vibrance 슬라이더는 예전 수학 그대로 둡니다.** macOS 도 그 슬라이더에
`CIVibrance` 를 쓰지만 amount 가 `슬라이더 × 0.8` 이라 **±0.8 까지 가고 음수도 납니다.**
맥에서 잰 구간은 0.05…0.50 이므로 그 범위를 덮지 않습니다. 재지 않은 곳에 표를 뻗으면
"잰 사상" 이 아니라 지어낸 값이 됩니다. 그 구간의 골든을 받은 뒤에 옮깁니다.

## 남은 것

- 채도 낮은 컬러 네거티브 스캔이 맥 쪽에 하나뿐이라, amount 가 0.259 아닌 **다른 사진**의
  실측 검증은 아직 없습니다. 사다리(같은 사진, 여섯 amount)로 대신했습니다.
- ColorModel 범위(−0.8…+0.8) 골든.

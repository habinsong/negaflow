# 적외선 결함 검출 — 실제 필름에서 먼지를 찾고 1화소로 정렬합니다

기준일: 2026-08-15

## 무엇을 확인했는가

`2026-08-15-infrared-on-real-film.md` 는 IR 채널이 결함 신호를 담고 있다는 것까지 확인하고,
"그 지도가 GrainMend 복원과 맞는지는 모른다" 로 끝냈습니다. 여기서 그 중간 단계 —
**검출** 을 확인합니다.

입력은 같은 스캔의 두 패스입니다. Epson V700(GT-X900), 검출기가 찾아 준 컷
(x 62.31, y 93.82, 23.96×36.00 mm)을 1200 dpi 로 찍은 본 스캔과 그 IR 채널.

```
main 1128x1709 spp=3   ir 1128x1709 spp=1
```

## 결과

```
status=Ok  clusters=6
coverage=0.4179%  medianGain=4.0000  candidates=122  confirmed=117
alignment=Aligned  offset=(1,0)  peak=0.017  runnerUp=0.010
components: Dust area=13 / 2 / 4 / 25 …  (conf 0.30)
```

읽는 법:

- **정렬 오차가 (1,0) 입니다.** 두 패스가 가로로 1 화소 안에서 겹칩니다. 이것이 이번에 가장
  중요한 값입니다 — macOS `3d9c3d3` 이 초점을 두 패스에 같이 주라고 한 이유가 정확히 이것이고
  ("두 패스의 초점면이 다르면 배율이 달라져 결함 지도가 결함에서 몇 px 옆에 놓인다"),
  초점을 이식한 결과가 여기서 숫자로 나타납니다.
- **122개 후보 중 117개가 확인됐습니다.** 검출기가 후보를 만들고 거르는 두 단계를 모두 지납니다.
- **먼지로 분류됩니다.** 면적 2~25 화소의 작은 성분들로, 필름 먼지의 크기와 맞습니다.
- 덮는 면적은 0.42% 입니다. 앞선 문서에서 IR 값이 베이스의 97% 아래로 떨어진 화소가
  0.325% 였는데, 팽창(dilate)을 거친 검출 결과가 그보다 조금 넓은 것은 그래야 맞습니다.

## 이제까지의 사슬

전 구간이 실제 장비와 실제 필름으로 이어졌습니다.

1. 플러그인이 자기 INF 로 스캐너를 엽니다(벤더 소프트웨어 없이)
2. 전체 판 프리뷰 → 검출기가 18컷을 23.96×36.00 mm 로 찾습니다
3. 찾은 좌표를 그대로 넣어 본 스캔 + IR 패스
4. IR 채널의 필름 베이스가 0.808(macOS 기록 0.81), 잘림 0%
5. **결함 검출이 먼지를 찾고 두 패스가 1화소로 정렬됩니다**

## 확인하지 않은 것

- **GrainMend 가 이 지도로 고친 자리가 정확한지.** 검출과 복원은 다른 단계입니다. 결함을
  찾았다는 것이 고친 결과가 옳다는 뜻은 아닙니다.

  시도했고 어디서 막혔는지 적어 둡니다. 복원을 돌리려면 검출 결과를 **결함 레시피**로 만들어
  프레임에 얹어야 하는데(`DefectRecipeSnapshot` → `DefectRecipeProjector` → 요청),
  검출기가 준 클러스터를 손으로 `DefectEditItem` 으로 옮기니 검증기가 거절했습니다. 마스크와
  감쇠 바이트 수는 정확히 맞고(808×808 → 2,611,456 / 1,305,728), ROI 도 통과하며, 512 MiB
  예산에도 한참 못 미칩니다. 남은 후보는 항목 수준의 요건(라벨·요약의 종류별 필수 값)입니다.

  **여기서 얻을 교훈은 손으로 옮기지 말라는 것입니다.** 셸에는 이미 검출 결과를 레시피로
  바꾸는 코드가 있고(`InfraredDefectRecipeCoordinator.RunFiles` — 자동 검출 버튼이 부르는
  것), 검증용으로 같은 변환을 두 번째로 구현하면 검증하는 것이 제품이 아니라 사본이 됩니다.

  그 경로로 다시 돌렸습니다. **검출과 레시피 생성까지는 통과합니다.**

  ```
  apply status=PersistenceFailed
    detect clusters=6 confirmed=117 coverage=0.4179% offset=(1,0)
  ```

  즉 제품의 변환기는 이 검출 결과를 **받아들입니다** — 앞서 손으로 만든 항목을 검증기가
  거절한 것과 대조적입니다. 남은 것은 저장뿐이고, 이유는 분명합니다: 이 프레임을 카탈로그에
  **가져오기 한 적이 없습니다.** 결함 사이드카는 존재하는 프레임에 붙습니다.

  가져오기부터 다시 했더니 **전 구간이 통과했습니다.**

  ```
  import rows=1 rejected=0
  apply status=Applied   recipe items=1 revision=1
  repair=False irEdits=0  succeeded=True
  repair=True  irEdits=1  succeeded=True
  ```

  즉 스캔 → 가져오기 → IR 적용 → 레시피 → 현상 요청 → 내보내기가 실제로 이어집니다.

## 복원이 픽셀을 바꿉니다 — 다만 예상보다 훨씬 넓게 바꿉니다

복원을 켜고/끄고 낸 두 TIFF(11,583,556 바이트로 크기 동일)를 16비트 낱말로 비교했습니다.

| 항목 | 값 |
| --- | --- |
| 달라진 낱말 | 5,684,774 / 5,791,777 (**98.15%**) |
| 최대 차이 | 25,202 (65535 의 38%) |

**이것은 정상이 아닙니다.** 처음에는 "IR 보정이 ROI 전체 노출을 되돌리는 성격일 수도 있다" 고
적었는데, macOS 소스를 읽어 보니 아닙니다. 맥을 띄우지 않고도 답이 나옵니다.

macOS 의 복원은 **마스크를 통해 합성합니다** — `SoftwareDefectRemoval.repair` 가
`CIBlendWithMask` 에 `inputMaskImage` 로 마스크를 주고, 고친 그림을 원본 **위에**
`composited(over:)` 합니다.

```swift
let blendMask = repairResult?.blendMask ?? mask
… "inputMaskImage": blendMask …
return repaired.composited(over: image).cropped(to: image.extent)
```

즉 **마스크 밖의 화소는 원본이 그대로 지나갑니다.** 결함이 0.42% 인 프레임에서 98% 가 달라질
수 없습니다.

## 확인된 결함

마스크 비율을 셌고, 답이 나왔습니다.

```
detect clusters=6 confirmed=117 coverage=0.4179%
  mask 808x808: R!=0 0.000%  A!=0 0.000%
  mask 400x808: R!=0 0.000%  A!=0 0.000%
  mask 808x848: R!=0 0.000%  A!=0 0.000%
```

**core mask 가 통째로 0 입니다.** 빨강 채널도 알파도 0 이 아닌 화소가 하나도 없습니다.
검출기는 같은 호출에서 결함 117개와 덮는 면적 0.4179% 를 보고하면서, 클러스터의 마스크는
비워서 돌려줍니다.

### 검출기는 정상입니다 — 처음 적은 진단이 틀렸습니다

"검출기가 마스크를 안 채운다" 고 적었는데 **아닙니다.** 코어 화소의 기준이
[infrared_defect_detector.cpp:19](../../src/Native/imaging/infrared_defect_detector.cpp) 의
`kCoreCut = 0.5F` 이고, 1148 행이 **감쇠 0.5 이상**인 화소만 코어로 담습니다.

이 프레임의 감쇠 최댓값을 앞 문서의 IR 값으로 계산하면
`1 − 31291/52920 = 0.409` 입니다. **가장 심한 화소조차 0.5 에 못 미칩니다.** 그러므로
`core_pixels` 가 비는 것이 맞고, 검출기는 설계대로 동작하고 있습니다 — 이 필름의 먼지가
빛의 절반을 가릴 만큼 두껍지 않을 뿐입니다.

### 남는 결함은 하나입니다

**복원이 빈 마스크를 "전부 고쳐라" 로 읽습니다.** 마스크가 비었으면 아무것도 바꾸지 않아야
맞습니다 — macOS 는 마스크로 합성하므로 빈 마스크는 원본 그대로가 됩니다. Windows 는 98% 를
바꿉니다. 코어가 없는 가벼운 먼지는 흔하므로, 이 상태로는 **먼지가 옅은 프레임일수록 그림이
크게 망가집니다.**

**다음에 할 일:** 복원 쪽에서 코어 마스크가 비면 그 클러스터를 건너뛰게 하십시오. macOS 의
 가 자연히 갖는 성질을 Windows 는 명시적으로 만들어야 합니다.

경로는 이미 확인했습니다 — ABI 의  복사도, 검출기의
채우기 루프(883 행)도 정상입니다. 고칠 곳은 마스크를 만드는 쪽이 아니라 **쓰는 쪽**입니다.

이 문서는 "복원이 픽셀에 닿는다" 까지만 확인했고, **그 결과는 틀렸으며 원인은 위와 같습니다.**
- macOS 가 같은 컷에서 낸 클러스터·성분과의 대조. 맥 호스트가 필요합니다.
- `peak=0.017` 은 상관 최댓값이 낮습니다. 검출기 자신은 `Aligned` 로 판정했지만, 이 값이
  이 정도로 낮아도 되는지는 macOS 와 대조하지 않았습니다.

# 출력 색공간이 실촬영 스캔에서 실제 파일에 닿는가

기준일: 2026-08-14

## 무엇을 확인했는가

`2026-08-14-output-color-space-matrices.md` 는 행렬과 프로파일이 **맞다**는 것만 말했고, 그 문서
끝에 "아직 내보내기 경로에 연결되지 않았다" 고 적어 두었습니다. 여기서는 그 연결을 확인합니다 —
설정에서 고른 색공간이 픽셀을 실제로 옮기는지, 파일에 붙은 프로파일이 그 공간의 것인지,
그리고 **sRGB 를 고른 결과가 이 변경 이전과 바이트까지 같은지**입니다.

## 어떻게

셸이 쓰는 것과 같은 경로 그대로입니다. `ExportSettings.ColorSpace` →
`ToEncodingOptions` → `DevelopRequestFactory.Create` → ABI v32 → `NativeDevelopExporterAdapter`.
입력은 사용자의 실제 스캔 `OpticFilm8100_frame_1.tiff`(5088×3401, 16-bit, Plustek OpticFilm 8100).
설정은 TIFF16 · 300 DPI · 긴 변 2048 · LZW · 선명도 0 으로 고정하고 **색공간만** 바꿨습니다.
네이티브는 x64 Release, ABI 0.46 입니다.

나온 TIFF 는 IFD 를 직접 읽어 태그 34675(InterColorProfile)의 바이트 수와 프로파일 `desc` 태그를
꺼냈습니다.

## 결과

| 색공간 | 파일 바이트 | SHA-256 | ICC 바이트 | 프로파일 이름 | 시간 |
| --- | --- | --- | --- | --- | --- |
| sRGB | 21,982,578 | `A316EB46…0FE9` | 3,144 (태그 17개) | `sRGB IEC61966-2.1` | 1,125 ms |
| Display P3 | 21,937,152 | `0E5B16F3…E1A4` | 6,720 (태그 9개) | `Display P3` | 1,115 ms |
| Adobe RGB | 21,938,662 | `E6E370B4…6B20` | 6,724 (태그 9개) | `Adobe RGB (1998)` | 1,063 ms |

원본 SHA-256 은 세 번 모두 `F281DEEC…872B` 로 그대로입니다.

읽는 법:

- **세 SHA-256 이 모두 다릅니다.** 색공간이 프로파일만 갈아 끼우는 것이 아니라 픽셀까지
  닿는다는 뜻입니다.
- **sRGB 파일의 SHA-256 이 `2026-08-14-export-settings-real-scan.md` 의 "선명도 0" 파일과 정확히
  같습니다**(`A316EB46…0FE9`). 색공간 코드가 들어오기 전에 찍은 값이므로, 기본값 경로가 이
  변경으로 **한 바이트도 달라지지 않았음**을 확인한 것입니다. 이것이 이 검증에서 가장 중요한
  줄입니다.
- sRGB 만 프로파일이 3,144 바이트에 태그 17개입니다 — Windows 가 가진 시스템 프로파일을
  그대로 쓰기 때문입니다. 나머지 둘은 우리가 만든 6.7 KiB · 9태그 v2 프로파일입니다.
- 시간 차이는 측정 잡음 범위입니다. 화소당 3×3 곱은 현상 비용에 묻힙니다.

## JPEG

JPEG 은 sRGB 만 냅니다. 두 겹으로 막혀 있습니다.

- 엔진: 넓은 색역 + JPEG 요청을 `jpeg_requires_srgb` 로 **거절**합니다. 색을 잘못 표시한 파일을
  내느니 거절하는 쪽이 낫기 때문입니다. `native.develop_export_abi` 가 이 거절과, 알 수 없는
  색공간 값, 더러운 예약 필드까지 함께 봅니다.
- 셸: `ExportSettings.EffectiveColorSpace` 가 JPEG 일 때 sRGB 로 되돌리므로 사용자가 거절을
  마주치지 않습니다. 설정 화면의 "내보내기" 요약 줄도 고른 값이 아니라 이 값을 적습니다.

## UI 자리

macOS 는 이 선택을 **현상 화면이 아니라 설정 → 내보내기 탭 맨 아래 "색상 관리" 구획**에
둡니다(`ColorManagementSettingsSection.swift`, `AppSettingsView.swift:273`). Windows 도 같은
자리에 같은 순서로 넣었습니다 — 색상 / 작업 공간 / 내보내기. 라벨은 macOS 문자열표에서 그대로
가져와 6개 로케일에 넣었고, 색공간 이름 세 개는 `ExportColorSpace.uiLabel` 과 같은 문자열이며
번역하지 않습니다.

현상 화면의 품질 탭에는 **넣지 않았습니다.** macOS 에 없는 자리이기 때문입니다.

## 확인하지 않은 것

- **macOS 가 같은 설정으로 낸 파일과의 대조.** macOS 호스트가 필요합니다. 여기서 확인한 것은
  "값이 픽셀과 프로파일에 닿는다" 이지 "macOS 와 같은 바이트가 나온다" 가 아닙니다.
- macOS 는 `CGColorSpace(name:)` 이 주는 시스템 프로파일을 붙이고 우리는 만든 프로파일을
  붙이므로, **프로파일 바이트는 애초에 같을 수 없습니다.** 같아야 하는 것은 프로파일이 기술하는
  공간과 픽셀 값입니다.
- 소프트 프루프 관련 행(프루프 토글 · 프로파일 선택 · 색역 경고)은 macOS 의 같은 구획에 있으나
  아직 옮기지 않았습니다.
- 색역을 벗어나는 색의 처리는 여전히 행렬 뒤 0…1 클램프뿐입니다.

# 실제 촬영 네거티브 15장 batch 체크포인트

기준일: 2026-08-10

사용자가 제공한 Plustek OpticFilm 8100 코퍼스 **전체 15장**을 x64 Release CLI 로 현상·게시한
결과입니다. 종전 체크포인트는 2장만 계측했고, 대형 batch 처리량과 장기 peak 는
`next-steps.md` 에 미해결로 남아 있던 항목입니다.

요청은 전부 동일합니다 — 수동 Dmin `(0.25, 0.14, 0.07)`, color negative, 노출 0.5, 대비 0.3,
4밴드 파라메트릭 커브, PNG16 게시.

## 결과

15장 **전부 통과**했습니다. `status:"ok"`, `pixels_verified:true`, `published:true`, stderr 0바이트.

| 5 | 4,271 | 13 | 4,546 |

- 합계 **78,103 ms**, 장당 평균 **5,207 ms** (5088×3401 = 17.3 MP)
- **peak working set 389.46 MiB** — 15장을 연속 처리하는 동안 누적 증가가 없습니다.
  프로세스가 장마다 새로 뜨는 구성이므로 이 값은 *한 장의 상한*이며, 이미지가 커도
  working RGBA32F(약 277 MB)와 인코딩 버퍼 위로 크게 벗어나지 않는다는 것을 보여 줍니다.
- **원본 15개 전부 SHA-256 불변.**

느린 쪽(4·6·7·12·14·15)은 LZW 압축본입니다. frame_12 는 big-endian LZW + alpha + ICC 로
디코드만 약 2.25초를 씁니다. 압축 해제와 ICM 변환 비용이며 예상된 차이입니다.

## 이번에 함께 확인한 입력 형식

| | frame_1 | frame_12 | `Untitled (4).tif` | `Untitled.tif` |
|---|---|---|---|---|
| 배열 | LE | **BE** | LE | LE |
| 압축 | none | **LZW** | none | none |
| 채널 | RGB16 | **RGBA16** | RGB16 | **RGB8** |
| ICC | 없음 | **있음** | 없음 | **있음** |
| IFD | 1 | 1 | **2** | **2** |

네 파일이 디코더의 서로 다른 경로를 밟고 전부 게시까지 통과합니다.

## 검증하지 않은 것

- **동시** batch. 이 측정은 한 번에 한 장이며, 여러 장을 동시에 현상할 때의 스레드 예산과
  peak 는 아직 측정하지 않았습니다.
- GrainMend·Texture 같은 공간 필터를 켠 batch. CLI 가 그 인자를 노출하지 않습니다.
- 같은 입력의 macOS pixel golden.
- ARM64 실기 실행.

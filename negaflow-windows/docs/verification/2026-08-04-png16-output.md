# 2026-08-04 PNG16 출력 검증 기록

기준일: 2026-08-04
대상: CPU 수직 경로의 phase-0 PNG16 encode·readback·단일 파일 게시

## 검증 범위

- extended-linear-sRGB working float의 sRGB OETF와 RGB16 quantization
- non-finite, non-opaque alpha, 크기·메모리 한도 거부
- Microsoft 기본 WIC PNG encoder/decoder와 exact 48bpp RGB
- Windows 등록 sRGB ICC 삽입과 exact byte readback
- bounded PNG 구조 검사와 전체 pixel readback
- 기존 목적지와 publish 경합 보존, 실패 staging cleanup
- 이미지 SHA-256 기본 `off` 유지
- x64 Debug/Release 실행, ARM64 Debug/Release 교차 빌드와 기존 ABI 회귀

## 실행한 명령

```powershell
cmake --preset x64-debug
cmake --build --preset x64-debug
ctest --test-dir .\out\build\native\x64-debug -C Debug --output-on-failure

cmake --preset x64-release
cmake --build --preset x64-release
ctest --test-dir .\out\build\native\x64-release -C Release --output-on-failure

cmake --preset arm64-debug
cmake --build --preset arm64-debug
cmake --preset arm64-release
cmake --build --preset arm64-release

powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-interop.ps1 -Preset x64-debug
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test-interop.ps1 -Preset x64-release
```

CLI 실제 연결은 권리 확인된 저장소 TIFF fixture와 ignored `out/` 산출물로 확인했습니다. 사용자 TIFF
코퍼스는 이 출력 검증에서 다시 읽거나 복사하지 않았습니다.

## 결과

| 검사 | 결과 |
|---|---|
| x64 native Debug | CTest 20/20 통과 |
| x64 native Release | CTest 20/20 통과 |
| x64 managed ABI Debug/Release | 각각 13 assertion 통과 |
| ARM64 native Debug/Release | 전체 target 교차 빌드 통과, 실행 미검증 |
| x64/ARM64 DLL exports | `nf_get_abi_version`, `nf_get_build_info_v1` 두 개 유지 |
| x64 Release CLI dependency | Windows 기본 DLL 5개, 제3자/VC++ runtime DLL 0개 |
| working→sRGB16 | breakpoint, midpoint, clamp, padding 제외와 실패 계약 통과 |
| PNG round-trip | 16-bit RGB, 1 ICC, 전체 pixel과 ICC exact 일치 |
| 목적지 사전 존재 | 기존 bytes 유지, staging 없음 |
| publish 경합 | 경합 승자 bytes 유지, staging cleanup |
| artifact/readback 한도 | 게시 없음, staging cleanup |

CLI 수직 경로는 631×403 fixture를 16-bit RGB PNG로 게시했습니다. 관찰값은 encoded pixel
1,525,758 bytes, artifact 1,285,416 bytes, ICC 3,144 bytes, clipped color component 0개였습니다.
structure, pixels, profile과 publish 상태가 모두 `true`였고 source/artifact SHA mode는 모두 `off`였습니다.

같은 목적지로 다시 실행하면 `destination_exists`와 Windows 오류 `0x00000050`을 반환했고 기존 크기와
수정 시각은 변하지 않았습니다. `.negaflow-export-*.tmp` staging 잔여물은 관찰되지 않았습니다.

## 해석 제한

- ARM64는 compile 증거만 있으며 실제 Windows ARM64에서 WIC encode/readback을 실행하지 않았습니다.
- readback은 같은 Microsoft WIC codec 계열을 사용하므로 독립 decoder 동등성 증거가 아닙니다.
- PNG parser는 CRC를 독립 검증하지 않습니다.
- 현재 machine의 등록 sRGB profile을 사용하므로 machine 간 ICC bytes 재현성을 입증하지 않습니다.
- 전체 working float와 packed RGB16을 함께 소유하므로 대형 이미지 memory 목표를 닫지 않았습니다.
- 단일 파일 게시만 검증했으며 전원 장애, network filesystem, catalog transaction 복구는 미검증입니다.

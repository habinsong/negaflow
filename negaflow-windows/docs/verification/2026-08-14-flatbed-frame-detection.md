# 자동 프레임 찾기가 실제로 프레임을 세는가

기준일: 2026-08-14

## 왜 따로 확인했는가

경로가 이어졌다는 것과 검출기가 실제로 프레임을 센다는 것은 다릅니다. 시뮬레이터의 첫 합성
프리뷰는 한 장짜리 장면이라 검출기가 셀 대상이 아예 없었고, 그 상태로는 "연결됨" 이상을 말할 수
없었습니다.

## 무엇이 틀렸는가

처음 만든 합성 스트립으로는 **검출 0개**였습니다. 두 가지가 틀렸습니다.

1. **축이 반대였습니다.** 검출기의 `along` 은 **세로(Y)** 입니다 — 프레임이 위에서 아래로
   이어지고, 스트립의 폭이 가로입니다. 처음에는 가로로 이어지게 그렸습니다.
2. **한 축으로만 변하는 그림이었습니다.** `row_profiles` 의 `detail` 은 **한 행 안에서 가로
   이웃끼리의 차이**입니다. 프레임 내용이 세로로만 변하면 모든 행이 가로로 균일해 detail 이 0 이
   되고, 검출기 눈에는 빈 판과 같습니다.

두 축 모두에서 값이 변하도록 고친 뒤 검출됩니다.

## 결과

A4 판(210×297 mm)에 35mm 풀프레임 다섯 컷을 세로로 놓은 900×1273 합성 프리뷰:

```
asked=5 status=Ok found=5
  r0 c0 x=0.443 y=0.183 w=0.114 h=0.121 conf=0.94
  r0 c1 x=0.443 y=0.312 w=0.114 h=0.121 conf=0.94
  r0 c2 x=0.443 y=0.440 w=0.114 h=0.121 conf=0.94
  r0 c3 x=0.443 y=0.568 w=0.114 h=0.121 conf=0.94
  r0 c4 x=0.443 y=0.697 w=0.114 h=0.121 conf=0.94
```

치수를 밀리미터로 되돌리면 놓은 그대로입니다.

| 항목 | 검출값 | 놓은 값 |
| --- | --- | --- |
| 프레임 폭(가로) | 0.114 × 210 = **23.9 mm** | 24 mm |
| 프레임 길이(세로) | 0.121 × 297 = **35.9 mm** | 36 mm |
| 프레임 간격 | (0.312 − 0.183) × 297 − 35.9 = **2.4 mm** | 2.16 mm |
| 좌측 위치 | 0.443 × 210 = **93.0 mm** | 93 mm |

`ScanSessionController.RefreshRegions` 가 쓰는 정규화 → 밀리미터 환산이 맞다는 것도 이 숫자가
함께 보여 줍니다.

## 확인하지 않은 것

- **실제 필름이 놓인 실제 평판 프리뷰.** 이 확인은 합성 그림입니다. 실제 스캔에는 먼지·퍼포레이션·
  광량 불균일·기울어짐이 있고, 그중 어느 것도 여기서 겪지 않았습니다.
- 여러 줄(스트립 두 줄 이상)과 35mm 이외 규격.
- 이 확인은 네이티브 하네스로 돌렸습니다. Shell 단위 검사는 네이티브를 띄우지 않으므로 여기에
  들어 있지 않습니다.

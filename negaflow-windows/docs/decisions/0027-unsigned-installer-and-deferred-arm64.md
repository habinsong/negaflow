# ADR-0027: 코드 서명 철회, 설치 파일은 서명 없이 배포. ARM64 실기 검증은 사용자 담당

기준일: 2026-08-10

## 상태

채택. **ADR 이전의 "10. 코드 서명 → Azure Trusted Signing 우선" 판단을 대체합니다.**

## 배경

세 가지가 사용자 결정으로 확정됐습니다.

**1. 코드 서명은 전면 철회합니다.** 비용을 들이지 않기로 했습니다. Azure Trusted Signing
월 $9.99 도, 일반 CA 인증서도 쓰지 않습니다.

**2. 설치 파일까지 만드는 것은 그대로 목표입니다.** 서명이 빠질 뿐 배포 산출물은 만듭니다.

**3. ARM64 실기 검증은 사용자가 직접 합니다.** 이 개발 PC 는 x64 이고 ARM64 는 교차 빌드만
가능합니다. 앞으로도 교차 빌드까지만 검증하고, 실기 실행 결과는 사용자가 확인합니다.

## 결정

- **서명하지 않습니다.** 인증서를 사지도, 발급받지도 않습니다.
- **설치 파일은 계속 만듭니다.** 서명이 없으므로 MSIX 의 이점 중 하나(신뢰된 설치)가
  사라집니다. MSIX 는 설치에 서명을 요구하므로, **서명 없는 배포에는 MSIX 가 맞지 않습니다.**
  M17 착수 시 WiX 또는 Inno Setup 기반의 서명 없는 설치 파일로 갑니다.
  ADR 이전의 "8. 배포 형식 → MSIX" 도 이 결정에 따라 다시 열립니다.
- **ARM64 는 교차 빌드까지가 이 저장소의 검증 범위입니다.** 체크포인트에서 ARM64 교차 빌드는
  계속 돌리되, 실기 실행을 통과 조건으로 세우지 않습니다.

## 결과

**SmartScreen 경고가 뜹니다.** 서명 없는 설치 파일은 처음 실행할 때 사용자에게 경고를
보여 주고, 평판이 쌓이기 전까지 계속 그렇습니다. 이것은 서명을 사지 않기로 한 결정의 직접적인
대가이며 숨기지 않습니다.

**MSIX 로 얻으려던 것들이 함께 빠집니다** — 차등 업데이트, 깨끗한 제거, package identity 가
필요한 API, `.appinstaller` 자동 업데이트. 업데이트가 필요해지면 직접 구현해야 합니다
(ADR 이전 "9. 업데이트 → `.appinstaller`" 도 함께 무효입니다).

## 뒤집는 조건

배포 규모가 커져 SmartScreen 경고가 실제 채택을 막는 것이 확인되고, 그때 서명 비용을 낼 뜻이
생기는 경우.

## 1. 세 가지 근거를 **다** 씁니다

### 1.1 Windows 앱 — computer-use (**꼭 필요할 때만**)

`windows-mcp` / `windows-gui` MCP 는 **절대 쓰지 마십시오.** 화면 도구는 computer-use 하나입니다.
computer-use 는 토큰을 많이 씁니다. 위 「화면 도구」절의 **씁니다 / 쓰지 않습니다** 를 먼저 적용하십시오.
코드·시험·스크린샷 50장으로 끝나면 여기 절차를 시작하지 마십시오.

필요할 때만:

```
1. 앱을 띄운다        scripts\run-app.ps1 -Architecture x64 -Configuration Release
2. request_access     negaflow.shell.exe  ← 창을 소유한 프로세스 이름
3. screenshot         전체 화면은 한 번만
4. zoom               구역별로 크롭해서 확대   ← 여기서 판정
```

**`zoom` 없이 전체 스크린샷만 보고 판정하지 마십시오.** 1456×819 로 줄어든 그림에서는
2px 차이도, 잘린 글자도, 정렬 어긋남도 보이지 않습니다.
같은 화면을 여러 번 전체 캡처하지 마십시오.

### 1.2 macOS negaflow — Parsec

**같은 화면을 macOS 에서 열고 같은 구역을 크롭합니다.** 아래 1.3 표에
**파일이 없는 상태**(호버, 드래그 중, 메뉴가 창 어디에 붙는지, 비활성, 오류)는
**Parsec 으로만** 확인할 수 있습니다. 표에 있는 설정·메뉴막대는 Parsec 대신이 아니라
**파일을 연 뒤에** Parsec 으로 위치를 확인합니다.

## 6. 재는 연장 — 2026-08-20에 만든 것

computer-use 를 아끼려면 **자동화로 잴 수 있는 것은 자동화로** 잽니다.
(창을 옮기거나 끌지 않습니다. 보고 재기만 합니다.)

### 6.1 UI 자동화로 자리·크기·상태 재기

```powershell
# 창 찾기 → AutomationId 로 요소 찾기 → BoundingRectangle / ToggleState
Add-Type -AssemblyName UIAutomationClient, UIAutomationTypes
$root   = [System.Windows.Automation.AutomationElement]::RootElement
$cond   = New-Object System.Windows.Automation.PropertyCondition(
              [System.Windows.Automation.AutomationElement]::ProcessIdProperty, $pid)
$window = $root.FindFirst([System.Windows.Automation.TreeScope]::Children, $cond)
```

- **배율을 나누십시오.** 이 기계는 150% 라 UIA 가 돌려주는 값은 **물리 화소**입니다.
  macOS 스크린샷은 1배이므로 **1.5 로 나눠서** 견줍니다(48 → 32).
- `TogglePattern.Toggle()` 로 **여러 번 눌러** 죽는지도 봅니다. 실제로 그렇게 J2 를 확인했습니다.
- 자동화 ID 를 `StackPanel`·`Grid` 같은 **컨트롤 뷰에 안 올라오는 요소**에 달면 안 잡힙니다.

### 6.2 창을 찍기 — `PrintWindow`

`PW_RENDERFULLCONTENT`(플래그 2) 라야 WinUI 3 내용이 나옵니다. 그리고 **찍는 프로세스가
DPI 를 알아야** 합니다 — `SetProcessDPIAware()` 를 안 부르면 `GetWindowRect` 가 논리
좌표를 줘서 창의 일부만 찍힙니다(3862 → 2575 로 잘렸습니다).

### 6.3 ☠️ 맥 스크린샷의 화소값을 색 사양으로 쓰지 마십시오

`현상뷰_우측탭_자동색상+자동레벨.png` 의 `iCCP` 청크에는 **모니터 프로파일**
(`TFG24F07W`)이 들어 있습니다. 즉 그 PNG 의 숫자는 sRGB 도 Display P3 도 아니라
**그 모니터의 장치값**입니다. 그대로 `#RRGGBB` 로 옮기면 틀립니다.

| 스크린샷에서 가져올 것 | Swift 원본에서 가져올 것 |
|---|---|
| 자리·크기·간격·라운딩 비율 | 색(`Color.accentColor`, `Color.primary`) |
| 요소의 유무와 순서 | 불투명도 계수(0.2 · 0.12) |
| 글자 잘림 여부 | 글꼴 크기·굵기 |

확인법: PNG 청크를 훑어 `iCCP`/`cICP`/`sRGB` 가 있는지 봅니다. 프로파일 이름이
모니터 이름이면 장치값입니다.

### 6.4 스크립트는 **UTF-8 BOM** 으로 저장하십시오

Windows PowerShell 5.1 은 **BOM 이 없으면 ANSI(이 기계는 cp949)로** 읽습니다.
한글이 든 `.ps1` 을 BOM 없이 저장하면 주석·문자열이 전부 깨지고, 깨진 바이트가
따옴표·역슬래시로 보여 **파싱이 통째로 무너지기도** 합니다.
2026-08-20 에 `scripts/*.ps1` 6개(`build-release`·`ci-gate`·`run-app`·`symbolize-rva`·
`test-managed`·`verify-installer`)에 BOM 을 넣었습니다.

곁들여: 함수 안에서 `Write-Output` 을 쓰고 호출을 `$null = Show-Element ...` 로 받으면
**출력이 통째로 사라집니다**(함수의 파이프라인 출력이므로). 진단용 줄은 `Write-Host` 로.

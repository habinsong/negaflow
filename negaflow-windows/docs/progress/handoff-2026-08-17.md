## 1. GrainMend — 어디까지 사실인가

**동작이 확인된 것** (실제 스캔 `OpticFilm8100_frame_1.tiff` 5088×3401, 직접 실행):

| 항목 | 결과 |
|---|---|
| 자동 검출 | 검출 이미지 1800×1203, 9,306화소. 크기 질의와 마스크 호출이 같은 값, 작은 버퍼는 `mask_buffer_too_small`로 거부 |
| 민감도 옵션 | 실제로 결과가 달라짐 — legacy 9,306 / current-ui 4,096 / 구조선배제 끔 16,592 / 미세반점 끔 2,587 |
| 확정(수락) | `Region`·`Automatic`·`Enabled`·`Strength 1`·마스크 78,574B(zlib)·ROI 5088×3401 |
| 영속성 | catalog를 닫았다 다시 열어도 남음 |
| 요청 투영 | `projectedRegions`·`projectedOrder` 모두 실림 |

**핵심 결함 — 고쳤습니다 (커밋 `e9ea17c`):**

증상은 "확정한 수리가 화소를 하나도 고치지 않음"이었습니다. 원인은 **마스크 단위 불일치**입니다.

- 수리 커널은 **0~255 손상 가중치**를 받고 `weight > 8`인 화소만 손상으로 봅니다
  (`defect_component_repair.cpp`).
- 검출기는 "받아들인 화소"를 **1**로 표시하는 플래그 마스크를 냅니다.
- `GrainMendRegionEdit.From`이 그 값을 그대로 통과시켜, 실제 스캔에서 마스크는
  `nonzero=295,756 · peak=1 · over_gate=0` — 게이트를 넘는 화소가 **하나도 없었습니다.**
  단계는 `ok`를 반환하며 아무것도 안 했습니다.

수정: `From`이 **플래그 마스크일 때만** 커널의 전체 가중치로 올리고, 계조를 담은 마스크는
그대로 둡니다. 첫 시도는 일괄 255로 올려 128을 뭉갰고 기존 시험
`grain_mend_region_edit_keeps_partial_values`가 그것을 잡았습니다.

**고친 뒤 실측** (`OpticFilm8100_frame_1.tiff`, recipe 있음 vs 없음):

| 경로 | 차이 바이트 | 최대 차이 |
|---|---:|---:|
| preview 900×700 | 12,612 | 125 |
| preview 1600×1200 | 35,358 | 135 |
| preview 2400×1800 | 72,979 | 150 |
| preview 5088×3401 | 299,788 | 169 |
| export 5088×3401 | 차이 있음 | — |
| 대조군(같은 요청 2회) | **0** | — |

preview와 export가 이제 같은 recipe를 냅니다.

**같이 들어간 것 둘:**
- `[nega-defect]`·`[nega-region]`·`[nega-region-mask]` NEGA_DEBUG 줄. 파이프라인이 세던
  `region_applied`·`region_repaired_pixels`를 밖에서 물어볼 방법이 없어서 이 결함이 오래
  숨어 있었습니다. 이제 물어볼 수 있습니다.
- region 마스크 de-interleave. 커널은 화소당 1바이트를 읽는데(브러시 `stride=width`, IR
  `core_mask[row+x]`, 시험 `width*height`) region만 RGBA8(stride `width*4`)을 보내고
  있었습니다. 계약상 옳은 수정이며, 이것만으로는 증상이 안 고쳐졌습니다(원인은 위의 단위
  불일치였습니다).

**아직 손도 못 댄 것:** macOS `DefectLayerSection`(결함 레이어 목록 — 항목별 켜기/끄기·강도·
마스크 표시·삭제·개수 배지·완료 버튼)이 Windows에 **없습니다**. `negaflow-mac/Sources/
negaflowApp/Features/Defects/DefectLayerSection.swift` 179줄이 원본입니다. 브러시·복제·IR의
UI/UX 대조도 하지 않았습니다.

**환경 제약:** 이 세션의 computer-use 도구는 브라우저 전용이라 WinUI 앱을 마우스로 직접
조작할 수 없었습니다. 앱 상태는 PowerShell UI Automation으로 읽었습니다(`AutomationId`가
`negaflow.develop.grainmend.*`로 붙어 있어 조회는 됩니다).

## 3. CI

- **macOS `CI`: 통과.** provenance 게이트가 파일 내용을 소문자로 검사해 테스트 타입명
  `ScanImageTests`가 SANE 바이너리 마커 `scanimage`와 충돌하던 것을 고쳤습니다(책임별로
  `ScanRotationDefaultTests`·`PixelSamplerTests`·`AppLanguageTests`로 분리).
- **Windows CI**: Managed·Native·ARM64 3개 잡 통과. **설치본 잡만 남았습니다.**
  - `Build installer`는 이제 **성공**합니다. 원인은 `build-release.ps1`이 `dotnet publish`가
    `TargetDir\AppX` 레이아웃을 남긴다고 가정한 것인데 publish는 그것을 만들지 않습니다.
    빌드가 만든 unsigned MSIX를 `makeappx unpack`으로 푸는 방식으로 바꿨습니다.
  - 남은 실패: `Verify silent install and uninstall`이 **멈춥니다.** 25분 잡 타임아웃으로
    취소되고 러너가 `Terminate orphan process: pid (968) (Negaflow-1.0.9-x64-setup)`를 찍습니다.
    설치 관리자가 끝나지 않습니다. 유력한 자리는 NSIS가 부르는 `Add-AppxPackage -Register`입니다.
  - `verify-installer.ps1`에 10분 경계와 타임아웃 시 프로세스·패키지 상태 출력을 넣었습니다.
    **다음 실행이 "어디서 멈추는지" 말해 줄 것입니다.** 그 로그부터 보십시오.

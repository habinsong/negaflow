  emulsion(면적 하한 이상 + fill 0.5 이하 또는 두께 8 이상),

- `CandidateMaps` 가 `dust_magnitude`·`thin_magnitude`·`noise_scale` 을 들고 나옵니다

**아직 남은 핵심 결함:** RGB ABI 가 컴포넌트를 밖으로 내지 않습니다. 그래서 위 분류가
관리 코드까지 오지 못하고, `GrainMendRegionEdit.From` 은 여전히 `Dust × acceptedPixels` 를
지어냅니다. **다음 사람이 할 일은 이 채널을 뚫는 것입니다.**

그래서 `src/Shell.Core/Develop/GrainMendRegionEdit.cs` 가 이렇게 지어냅니다:

```csharp
new DefectClassBreakdown(
    [new DefectClassCount(DefectClassification.Dust, checked((int)acceptedPixels))],
    1.0)
```

즉 화면의 "먼지 4,096 · 신뢰도 100%" 는 **검출 결과가 아니라 채택 화소 수**입니다.
핀홀·가로/세로/대각 스크래치·유제 손상·미세 입자는 한 번도 나올 수 없습니다.

**이식해야 하는 것 (macOS 원문 기준):**

- `DefectShape.pcaMetrics` — 2차 모멘트 PCA. `length = floor(√(12λ₁))+1`,
  `thickness = n/length`, `aspect = length/thickness`,
  `angleDegrees = 0.5·atan2(2σxy, σxx−σyy)·180/π` 를 0~180 으로 정규화.
- `DefectClassifier.classify` —
  - scratch: 주축 각도로 가름. `≤30° 또는 ≥150°` 수평, `|a−90|≤30` 수직, 나머지 대각.
  - dust: `polarity > 0.015 && area ≤ pinholeMaxArea && aspect ≤ 2.5 && fillRatio ≥ 0.4` → **핀홀**.
    `area ≥ emulsionMinArea && (fillRatio ≤ 0.5 || thickness ≥ 8)` → **유제 손상**. 나머지 먼지.
  - `pinholeMaxArea = max(16, classificationArea/25)`, `emulsionMinArea = max(200, classificationArea/3)`.
  - confidence = `clamp(0.2 + 0.5·strongFraction + 0.3·min(1, snr/8), 0, 1)`,
    `snr = mean(max(dustMag, thinMag)) / mean(noiseScale)`.
  - polarity = 컴포넌트 평균 `bright` − 주변 링(pad 3, 라벨 픽셀 제외) 평균 `bright`.
- `DefectSpeckDetector.merged` — 미세 입자를 **컴포넌트로** 더한다(겹치면 기존 우선).
- 분류 직전 macOS 는 `dustStrong` 을 `scratchStrong` 에 합칩니다
  (`for i where dustStrong[i] { scratchStrong[i] = true }`). confidence 의 strong 비율 근거입니다.

### 1.4 직선 오검출

사용자가 앱에서 확인한 증상입니다. 건물 모서리 같은 직선 구조물을 스크래치로 잡습니다.
macOS 쪽 대응은 두 가지이고 둘 다 Windows 에 **부분적으로만** 있습니다:

- `rejectLineGrid` — `SoftwareDefectDetector.detectLabeled(rejectLineGrid:)`.

  `grid_line_structure_radius_divisor = 4` 한 상수에 걸려 있습니다

- `protectDetail` — `DefectScratchDetector.candidatesLeveled(protectDetail:)`.
  Windows 도 인자를 받지만 macOS 와 같은 값을 쓰는지 확인하지 않았습니다.
- macOS `DefectLabelField.automaticFalsePositiveRisk` — 후보 밀도가 높으면 **경고만** 하고
  결과를 줄이지 않습니다. Windows 에는 이 개념이 없습니다.

## 2. 앱을 띄우는 법 (고쳤습니다)

```powershell
./scripts/run-app.ps1 -Architecture x64 -Configuration Release
```

전에는 빌드 폴더의 느슨한 exe 를 그냥 실행했고, 그것은 **실행되지 않습니다.**
`WindowsPackageType=MSIX` 라 apphost 가 런타임을 앱 폴더에서만 찾아
`You must install or update .NET` 로 끝납니다. 지금은 배포와 같은 길을 갑니다 —
패키지 빌드 → `makeappx unpack` → 느슨한 레이아웃 등록 → AUMID 로 실행.
등록 단계에는 시간 제한이 붙어 있습니다(CI 설치본 잡이 실제로 여기서 멈춥니다).

`-Unregister` 로 개발용 등록을 치울 수 있습니다.

**빌드가 CS0579(특성 중복)로 무너지면** 프로젝트 폴더 안에 `obj\` 가 생긴 것입니다.
`obj`·`bin` 은 `out\` 으로 옮겨 두었으므로 프로젝트 폴더 안에 있으면 기본 `**\*.cs` 글롭이
생성된 AssemblyInfo 를 함께 컴파일합니다. `Directory.Build.props` 가 이제 막지만,
이미 생긴 것은 지워야 합니다:

```powershell
Get-ChildItem -Path src, tests -Directory -Recurse -Filter 'obj' | Remove-Item -Recurse -Force
```

## 2.6 RGB ABI 컴포넌트 채널 — **뚫었습니다 (2026-08-17)**

### 아직 남은 것

- **미리보기 점이 ABI 로 안 옵니다.** 지금은 분류·신뢰도·면적·경계상자만 나릅니다. 검토
  오버레이를 분류색으로 칠하려면(macOS `RegionDefectOverlay`) 컴포넌트별 화소 좌표가
  필요합니다. `nf_grain_mend_component_v1` 에 `preview_point_count` 를 더하고 IR 의
  `nf_infrared_preview_point_v1` 과 같은 평면 배열을 하나 더 실으십시오.
- **종류별 칩 HUD 가 없습니다.** macOS `RegionDefectOverlay.classChipsBar` — 분류색 점 +
  이름 + 개수 + 평균 신뢰도(%), 누르면 그 종류 전체를 제외/포함. Windows 에는 없습니다.

### 원래 규격 (참고)

IR 경로(`nf_infrared_component_v1`, `negaflow_abi.h:1031`)를 그대로 본뜨십시오.

```c
typedef struct nf_grain_mend_component_v1 {
    uint32_t struct_size;
    uint32_t classification;   /* grain_mend_detail::DefectClassification 과 같은 순서 */
    double   confidence;
    uint64_t area;
    uint32_t minimum_x, minimum_y, maximum_x, maximum_y;
```

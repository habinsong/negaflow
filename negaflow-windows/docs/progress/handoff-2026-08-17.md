## 0. 지금 당장 이어서 할 한 걸음

GrainMend region 마스크의 **내용**을 재십시오. 지금까지 좁힌 결과, 배관은 전부 이어져 있고
수리 커널이 마스크에서 손상 화소를 하나도 찾지 못합니다.

- 커널 판정은 `defect_component_repair.cpp`의 `if (weight > 8U)` 한 줄입니다.
- `src/Native/pipeline/defect_region_stage.cpp`의 `[nega-region]` 로그에 **`weight > 8`인
  바이트 수**를 더해 찍으십시오. 0이면 마스크가 비어 있는 것이고, 그러면 범인은
  `src/Shell.Core/Develop/GrainMendRegionEdit.cs`의 `From`이 마스크를 채우는 부분입니다.
- 재현 명령(고정 입력, 실제 엔진):

```bash
negaflow-windows/out/build/managed/Negaflow.Shell.UnitTests/x64/Release/net10.0/win-x64/Negaflow.Shell.UnitTests.exe --defect-roundtrip <storageRoot> <frameId>
```

`NEGA_DEBUG=1`을 켜면 `[nega-defect]`와 `[nega-region]` 줄이 나옵니다.
카탈로그는 매번 새로 심으십시오 — 같은 frame에 여러 번 수락하면 `accept refused`가 납니다.

```powershell

$exe --diagnose <newRoot>   # frameId 확인
```

## 1. GrainMend — 어디까지 사실인가

**동작이 확인된 것** (실제 스캔 `OpticFilm8100_frame_1.tiff` 5088×3401, 직접 실행):

| 항목 | 결과 |
|---|---|
| 자동 검출 | 검출 이미지 1800×1203, 9,306화소. 크기 질의와 마스크 호출이 같은 값, 작은 버퍼는 `mask_buffer_too_small`로 거부 |
| 민감도 옵션 | 실제로 결과가 달라짐 — legacy 9,306 / current-ui 4,096 / 구조선배제 끔 16,592 / 미세반점 끔 2,587 |
| 확정(수락) | `Region`·`Automatic`·`Enabled`·`Strength 1`·마스크 78,574B(zlib)·ROI 5088×3401 |
| 영속성 | catalog를 닫았다 다시 열어도 남음 |
| 요청 투영 | `projectedRegions`·`projectedOrder` 모두 실림 |

**동작하지 않는 것 (핵심 결함, 미해결):**

확정한 수리가 **화소를 하나도 고치지 않습니다.** preview는 900×700·1600×1200·2400×1800·
**5088×3401(1:1)** 네 크기 모두 `differingBytes 0`입니다. 1:1에서도 0이므로 축소 탓이 아닙니다.

`[nega-defect]` 로그가 직접 말합니다: `region_applied=0 region_repaired_px=0`.

**좁혀 놓은 범위** (전부 코드로 확인, 추측 아님):

- 관리 마샬링은 export·preview 공유(`BuildDefectRegionPayload`) — 배제
- `NativeDevelopExporterAdapter.Preview`는 단순 위임 — 배제
- ABI `map_request_v34`의 둘째 인자는 `require_destination`, 결함 무관 — 배제
- `develop_and_export`·`develop_preview` 모두 같은 `run_develop` 호출 — 배제
- `apply_defect_region_edits`의 건너뛰기 게이트는 **통과**함:
  `enabled=1 strength=1.000000 roi=5088x3401+0+0 mask_bytes=69217152 stride=20352`
- 따라서 `repair_defect_components`가 진입해서 `ok`를 반환하면서 아무것도 고치지 않음
  → 마스크에 `weight > 8`인 바이트가 없다는 뜻

**이번에 넣은 수정 하나 — 효과 없었음(정직하게):**
수리 커널은 마스크를 화소당 1바이트로 읽는데(브러시 `stride=width`, IR `core_mask[row+x]`,
시험 `width*height` — 전부 1바이트) region 경로만 RGBA8(stride `width*4`)을 보내고 있었습니다.
`defect_region_stage.cpp`에서 stride가 정확히 `width*4`일 때만 한 채널로 펴도록 고쳤습니다.
**고친 뒤에도 `region_repaired_px=0`으로 그대로입니다.** 계약상 옳은 수정이지만 이 문제의
원인은 아니었습니다. 네이티브 결함 시험 7개는 그대로 통과합니다.

**아직 손도 못 댄 것:** macOS `DefectLayerSection`(결함 레이어 목록 — 항목별 켜기/끄기·강도·
마스크 표시·삭제·개수 배지·완료 버튼)이 Windows에 **없습니다**. `negaflow-mac/Sources/
negaflowApp/Features/Defects/DefectLayerSection.swift` 179줄이 원본입니다. 브러시·복제·IR의
UI/UX 대조도 하지 않았습니다.

**환경 제약:** 이 세션의 computer-use 도구는 브라우저 전용이라 WinUI 앱을 마우스로 직접
조작할 수 없었습니다. 앱 상태는 PowerShell UI Automation으로 읽었습니다(`AutomationId`가
`negaflow.develop.grainmend.*`로 붙어 있어 조회는 됩니다).

## 3. CI

- **macOS `CI`: 통과.** provenance 게이트가 파일 내용을 소문자로 검사해 테스트 타입명
  `ScanImageTests`가 SANE 바이너리 마커 `scanimage`와 충돌하던 것을 고쳤습니다(책임별로
  `ScanRotationDefaultTests`·`PixelSamplerTests`·`AppLanguageTests`로 분리).
- **Windows CI**: Managed·Native·ARM64 3개 잡 통과. **설치본 잡만 남았습니다.**
  - `Build installer`는 이제 **성공**합니다. 원인은 `build-release.ps1`이 `dotnet publish`가
    `TargetDir\AppX` 레이아웃을 남긴다고 가정한 것인데 publish는 그것을 만들지 않습니다.
    빌드가 만든 unsigned MSIX를 `makeappx unpack`으로 푸는 방식으로 바꿨습니다.
  - 남은 실패: `Verify silent install and uninstall`이 **멈춥니다.** 25분 잡 타임아웃으로
    취소되고 러너가 `Terminate orphan process: pid (968) (Negaflow-1.0.9-x64-setup)`를 찍습니다.
    설치 관리자가 끝나지 않습니다. 유력한 자리는 NSIS가 부르는 `Add-AppxPackage -Register`입니다.
  - `verify-installer.ps1`에 10분 경계와 타임아웃 시 프로세스·패키지 상태 출력을 넣었습니다.
    **다음 실행이 "어디서 멈추는지" 말해 줄 것입니다.** 그 로그부터 보십시오.

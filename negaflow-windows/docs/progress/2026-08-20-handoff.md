## 3. ☠️ 확인 못 한 것 · 새로 찾은 것

### 3.1 `native.gpu_film_scan` SEGFAULT — **원인 확정·닫음**

- 앞 기록: `ctest -R native.gpu_` **27회 중 3회** `***Exception: SegFault`.
- **원인은 GPU 가 아니었습니다.** 그 시험은 `negaflow_native` 를 링크하지 않아
  상주 스코프를 쓰지도 않습니다. `core/row_block_pool.cpp` 의 완료 통지가 잠금
  **밖**에 있어 호출부 스택의 `PendingCounter` 가 사라진 뒤 워커가 그것을 만졌습니다.
- 고친 뒤 **292회 연속 통과**(`--repeat until-fail:120` + 동시 프로세스 172회) +
  `native.gpu_` 묶음 12바퀴 전부 통과.
- 시험 타깃에도 크래시 기록기를 넣어 두었습니다 — 다시 나면 스택이 남습니다.

## 5. 2026-08-20 오후 — 맥 내보내기 대조 (문서 19 가 본문)

사용자가 맥에서 frame_4·frame_5 를 **MAIN · 자동 보정 없음 · 현상만** 으로 16bit 내보내
주었습니다. 문서 19 가 "못 했다" 고 적은 두 플랫폼 화소 대조를 처음으로 했습니다.

### 결론 (상세는 [`19`](../audit/19-image-pipeline-frame4-frame5.md) 6.4~6.7)

| 사용자 보고 | 판정 |
|---|---|
| "노이즈가 맥보다 많다" | **아닙니다.** 색공간을 맞추면 σ 비 0.96~1.00. 맥 = Display P3, 우리 = sRGB 였습니다 |
| "채도가 다르다" | 절반은 색공간, 절반은 베이스 색(dmin 채널비) |
| "톤이 다르다" | **맞습니다.** 원인은 **dmin 하나**. 맥 dmin 을 넣으면 평균차가 10배 줄어듭니다 |

### 맥의 dmin 은 이제 실측값입니다

토우 화소(맥 출력이 `base_toe` 근처인 자리)의 원본 투과율:

- frame_4 `0.20331 / 0.11626 / 0.05926` (우리 `0.22287 / 0.13022 / 0.06738`, +9.6~13.7%)
- frame_5 `0.22266 / 0.13347 / 0.07079` (우리 `0.22737 / 0.13439 / 0.07106`, +0.4~2.1%)

최소제곱 역산과 0.1~1% 안에서 일치합니다. **frame_5 는 이미 맞고 frame_4 만 어긋납니다.**

### 어디가 갈리는지 성분 단위로 특정했습니다

frame_4 에서 맥은 성분 **#2**(2030칸, 상위절반 중앙값 `0.20283/0.11348/0.05726`)를,
우리는 **#0**(201칸, `0.23024/0.13619/0.07088`)을 고릅니다. 규칙은 같으므로
**맥 그리드에는 #0·#1 이 아예 없습니다.**

원인: 불변량 A(반경 2 안 1.15배 밝은 이웃 → 경계 혼합 셀 제외)는 **국소 대비**에 걸리는데,
우리 표본 그리드는 밉맵 박스 평균이라 너무 매끄러워 그 판정이 약해집니다.

### 1:1 로 확인해 이상 없는 것

인화 응답 상수(비트 패턴 해독) · dmax 측정 수식 · 후보 판정 · 성분 규칙 · 강등 · 형제 병합 ·
percentile/median/upper_median · 그리드 크기(256×171) · 프록시 해상도 · ICC/mscms 경로.

### 다음 사람이 할 일

1. **맥 그리드의 성분 목록**을 받으면 닫힙니다(19 6.7 ⑥). dmin 은 이미 실측했으니
   남은 질문은 "왜 맥 그리드에는 #0·#1 이 없는가" 하나입니다.
2. **한 장에 맞추지 마십시오.** 점 표본으로 바꾸면 frame_4 의 R 은 맞지만 G·B 가 −11~21%
   빗나가고 **frame_5 가 +7% 깨집니다**(19 6.7 ④ 표).
3. 고친 뒤 `compare16` 으로 두 프레임 모두 재십시오.
